# 同期の版 6：変更ログをやめ、生存を Worker の観測に移す

2026-10-16 に決めた。D1 の読み取りがアカウントの無料枠（1 日 500 万行）を超えた件の直しである。

## なぜ

- 読み取りの 97% は `compact()`（packages/cloud/src/changes.ts）だった。`seq <= ? and received_at < ?` を主キーの範囲で引き、`changes`（直近 14 日の記録、約 5 万行）を毎回全部読む。消すものが 0 件の回も同じで、量の 2 乗で増える。`received_at` の索引を張っても計画は主キーを選ぶ（miniflare で実測）。
- 端末が送る変更の 9 割は時刻の刻みだった。`runs.heartbeat_at` の 30 秒ごとの書き換えが 65%、`sessions.last_activity_at` が 27%。
- Worker は push、pull、files のたびに `devices.last_seen_at` を書く（1 日約 3 万行）。

## 形

1. **`rows` を `files` と同じ作りにする。**
   - `seq integer primary key autoincrement, k text not null unique, …`。
   - push の 1 行は 2 文で書く。`delete from rows where k = ? and updated_at < ?` のあとに `insert … on conflict(k) do nothing`。連番は SQLite が書き込みのロックの中で振るので、commit の順と連番の順がそろう。JS で連番を計算しない。
   - `accepted` は文の `meta.changes` で数え、push の前の `select k, updated_at from rows where k in (…)` は消す。
   - `GET /changes?since=` は `select … from rows where seq > ? and device_id != ? order by seq limit ?` で引く。応答の形 `{changes, nextSeq, more}` は保つ。
   - `GET /rows` は残す。新しい端末の初回の取り込みで、自分の行も含める。
   - `changes` 表、`compact()`、410、`changes_floor`、`last_compact_seq`、`seq_high`、`last_pulled_seq` の読み書きは消す。列や meta の行は残っていても読まない。
2. **D1 の移行**（`ensureSchema`）。
   - `rows` に `seq` が無いときだけ、1 つの batch で行う。
   - 先頭で `meta` に印の行を `insert` する。`on conflict` は付けない。2 本目の isolate はこの一意制約で batch ごと落ちるので、落ちたら握って、もう一度確かめる。
   - `create table rows_v6 …`、`insert into rows_v6 (seq, …) select H + row_number() over (order by updated_at, k), … from rows`、`drop table rows`、`alter table rows_v6 rename to rows`、`drop table changes` の順。
   - H は旧い高水位で、`meta.seq_high` と `changes` の `max(seq)` の大きい方を採る。全端末の `since` が H 以下になり、移行の後に 1 回だけ全件を取り直す。
   - `rename` のときに `sqlite_sequence` も追従することは、miniflare で確かめた（2026-10-16）。
3. **生存は Worker が見たものにする。**
   - pull の応答に `peers: [{ id, lastSeenAt }]`（解除していない PC）と、Worker の `now` を添える。
   - 端末は「Worker の now − lastSeenAt」を年齢として、手元（共有しない場所）に持つ。
   - `runs.heartbeat_at` は共有の行に書かない。手元の間引き（manager.ts の tick）には残す。
   - ロックの stale（db/queries.ts の lockMap）は、その run の PC の年齢が `PEER_STALE_MS`（約 3 分）を超えたら立てる。
   - `aliveRunForSession` による 409 も同じ判定でそろえる。年齢の古い PC の run では、ふさがっているとみなさない。
   - 同期を一時停止していても、1 分に 1 回は Worker へ生存だけを知らせる。
4. **Worker の `touchDevice` を間引く。** 認証で読んだ行の `last_seen_at` が 1 分以内なら書かない。
5. **共有の `last_activity_at` を間引く**（indexer/indexFile.ts）。前の値から 5 分未満の進みなら書かない。ほかの事実が変わったときと、ターンの終わりには書く。
6. **互換の版 6。** `COMPAT_VERSION`、`MIN_DEVICE_COMPAT`、`MIN_WORKER_COMPAT` をすべて 6 に上げ、一斉に切り替える。
   - 混在を許さない。古い PC は heartbeat で判定するので、新しい PC が heartbeat をやめると、2 分で「応答がありません」になり、二重に起動しうる。
   - Worker だけの巻き戻しはしない（直す方向だけ）。
   - docs/design.md の「互換の版番号」に、両方を同時に上げる例外として書く。
7. **読み取りの予算の試験。** 古い行の多い表を用意して、push、pull、rows、devices を叩く。掃除や認証の文の `meta.rows_read` が、返した行数＋定数に収まることを試験で縛る。

## 範囲の外（別の PR）

- 使用量の見張りに D1 の読み取りを足す。画面に出るので試作から始める。
- 土台の要約の「N ターン・所要時間」を本文から列へ出す。
- 共有の `devices.last_seen_at`（10 分おき）をやめ、設定の「最終確認」を peers から引く。

## 試験の順

- Worker（packages/cloud/test）：移行（旧い表から、2 本目の競合、H より上から振ること）、push の LWW と同着、pull のページ送り中の更新、自分の行の除外、peers と now、touchDevice の間引き、読み取りの予算。
- 端末（packages/server）：peers の年齢から lock の stale を立てること、409 の判定、heartbeat を共有に積まないこと、一時停止中の生存の知らせ、last_activity_at の間引き、`MIN_WORKER_COMPAT` 6。fake-cloud も追随させる。
