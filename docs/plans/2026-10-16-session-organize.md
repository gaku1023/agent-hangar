# セッションの整理（移動・削除・右クリック・状態の欄・並べ替えの動き・クイックセッション）

2026-10-16 に利用者と決めた計画。
試作は `~/workspace/hangar-explainers/session-menu-2026-10-16/index.html`（この PC だけにある）。
利用者は 6 節とも「A（推す案）」を選び、文言は Gemini と見直した版で確定した。

## 決めたこと

### 同期の置き場

- 本文から読み取れる事実（件名、cwd、時刻、トークン）は `sessions` に置き、本文を持つ PC が書き直してよい。
- 利用者が決めること（所属、状態、削除）は `session_states` に置く。利用者の操作でしか書かれないので、索引の書き直しや後勝ちで戻らない。
- `session_states` に列を 2 つ足す（列を足すだけなので Worker と互換の版は変えない）。
  - `project_id text`：利用者が移した先。null なら cwd からの自動の振り分けに従う。
  - `trashed_at integer`：削除の印。null なら生きている。行の論理削除の `deleted_at` とは別物である。

### 移動

- 動かすのは hangar 上の所属だけ。本文（jsonl）と `sessions.cwd` は元のまま。
- 移したら `session_states.project_id` を書き、`sessions.project_id` も同じ値に合わせる。
- 索引（`applySessionFacts`）、自動の振り分け（`assignSessions` / `assignSession`）、同期の取り込み（`applyRemoteChange` の sessions の upsert）のあとで、`session_states.project_id` があれば `sessions.project_id` をそれに合わせ直す。古い所属を持った upsert が後から届いても、移した先のままになることを試験で確かめる。
- プロジェクトをまとめる（merge）ときは、`session_states.project_id` もまとめ先へ付け替える。unlink のときは null に戻す。
- 再開（resume）の所属は移した先。注入する指示も移した先のプロジェクトのものを使う。
- 再開の cwd は元のまま。cwd がこの PC に無いときの読み替え（`resumeCwd`）は、移した先ではなく、cwd を含む場所を持つプロジェクトの場所で行う。

### 削除

- どちらの PC からでも消せる。
- 実行中の会話は消せない。メニューで押せないことに加え、サーバでも `sessionRunsAnywhere` が真なら 409 で断る。
- 消した PC は、まず自分の本文（主線の jsonl と、隣の `<uuid>/` のサブエージェントの本文）を OS のゴミ箱へ移す。ゴミ箱へ移せなかったら何も変えずにエラーを返す。`rm` に倒さない。
- 移せたら `trashed_at` を書き、`sessions` の行を論理削除する。
- 印を受け取ったほかの PC は、次のことをする。
  - その PC が本文の持ち主なら、本文をその PC のゴミ箱へ移す。その PC で実行中なら、止まるまで待ってから移す。
  - hangar が降ろした写し（`~/.agent-hangar/remote/...`）は、hangar の持ち物なので普通に消す。
- 起きていなかった PC は、次に起きたときに同じことをする。
- 生き返らないこと：`trashed_at` のある会話は、索引でも同期の upsert でも掘り起こさない（`apply.ts` が upsert で `deleted_at=null` にする所を含む）。
- 戻せること：ゴミ箱へ移した本文の元のパスを、端末ローカルの表に控える。本文の持ち主の PC で、同じパスにファイルが戻ってきたら、`trashed_at` を外し、行の論理削除も外して索引し直す。この復元は同期でほかの PC にも届く。
- クラウドの写し（R2 の `transcripts/<端末>/<uuid>.jsonl.gz` と D1 の索引）は、`trashed_at` から 30 日たったら Worker の掃除（sweep）で消す。端末の API を変えずに済むなら互換の版は上げない。Worker の配備は、利用者に聞いてから行う。
- ゴミ箱へ移す方法（サーバ、Node から呼ぶ）：
  - macOS：`osascript -l JavaScript` で `NSFileManager.defaultManager.trashItemAtURL...` を呼ぶ。Finder を操作しないので、自動操作の許可を求められない。
  - Windows：PowerShell で `Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile`（ディレクトリは `DeleteDirectory`）に `SendToRecycleBin` を渡す。
  - Linux：`gio trash`。
  - CI の windows のジョブで、一時ファイルを本当にゴミ箱へ移す試験を走らせ、実機の代わりにする。

### 状態

- 既存の `session.state.set` を使う。Paused を選んだときは、いまと同じ戻る日のダイアログ（`session.pause.open`）を開く。

### 画面（試作の A で確定）

1. **セッションの右クリックのメニュー（1A）**
   - ホームの一覧、プロジェクト画面の一覧、ホームの帯（`BandRowView`）、サイドバーで同じメニューを出す。行の「⋯」と `.` も同じメニューを開く。
   - 並び：
     - 条件付きの「この PC で再開」
     - Active・Paused・Done・Archived の 4 つ。いまの状態に ✓ を付け、状態の色の点を添える。打鍵の印は u・p・d・a。
     - 区切り
     - 「プロジェクトを変更…」（打鍵の印 m）
     - 区切り
     - 「停止」（実行中だけ。外のターミナルのものはいまの理由で押せない）
     - 「削除…」（実行中は押せず、理由「実行中のセッションは削除できません。先に停止してください」）
   - 危険色は停止と削除だけ。
   - 停止の補足の 1 行は出さない。
2. **移し先の選び方（2A）**：ダイアログ。
   - 見出し「プロジェクトの変更」。
   - 本文「「{name}」の移動先を選んでください。」
   - 検索欄の薄い文字「プロジェクトを検索」。区切りは「最近」と「すべて」。
   - いまの所属の行は押せず、「現在のプロジェクト」を添える。
   - 注意書き「変わるのは hangar での分類だけです。トランスクリプトと、再開するフォルダ（{cwd}）はそのままです。」
   - ボタンは「キャンセル」と「{project} へ移動」。
3. **削除の確認（3A）**
   - 見出し「「{name}」を削除しますか？」。
   - 下の 1 行「{project}・{n} ターン」。
   - 本文「トランスクリプトをゴミ箱へ移動し、hangar から削除します。同期しているほかの PC からも削除されます。ゴミ箱から戻すと、hangar にも戻ります。」
   - ボタンは「キャンセル」と、危険色の「ゴミ箱へ移動」。初めの焦点はキャンセル。
4. **セッション画面の状態の欄（4A）**
   - 見出しの右の操作の並びの先頭（主ボタンの左）に、`StatusSelect` と同じ札を置く。
   - いまの状態のバッジがあれば置き換える。
   - 一言は、プロジェクト画面と同じく「進行中のもの」「一時的に止めているもの」「完了したもの」「一覧に表示しないもの」。
   - プロジェクト一覧の行は、右クリックで行の「⋯」と同じメニュー（`menuItems`）を出す。
5. **サイドバーの並べ替え（5A）**
   - 掴んだ行は、白い面と影、102% の拡大で浮く。
   - 浮いた行はポインタに付いて縦だけ動き、端では行 1 つ分の手前（約 8px 先）で止める。
   - ほかの行は `--dur-fast` と `--ease-out` で滑ってよける。
   - 離すと空いた場所へ `--dur-fast` で収まり、影が消え、収まってから並びを確定する。
   - Esc で元の場所へ戻る。
   - いまの入る線（`data-over` の線）はやめる。
   - ポインタのイベントの作り（HTML の DnD を使わない）は変えない。
   - `prefers-reduced-motion` では拡大と滑りを止める（長さはトークンで 0 になる）。
6. **ほかの PC のクイックセッションの再開（6A）**
   - 再開の確認の「この PC」の欄に、作って再開するフォルダのパスを出す。
   - その下に「クイックセッションの置き場に同名の空フォルダを作成して再開します」を添える。
   - 「場所を指定してください」は出さない。

### クイックセッション（画面では「クイックセッション」、コードでは scratch）

- いまは PC ごとに別のスクラッチのプロジェクトがある。これを全 PC で 1 つのプロジェクトにまとめる。
  - 既存のものは、作った日時の古いもの（同じなら id の小さいもの）にまとめる。どちらの PC でも同じ先を選ぶようにする。
  - 所属の会話、TODO、状態は引き継ぐ。
- 新しいクイックセッションは `~/.agent-hangar/quick-sessions/<yyyymmdd-HHmmss>` に作る。この PC の場所（`project_roots`）は `quick-sessions` にする。
- 既存の利用者に齟齬を出さない。
  - 既存の `~/.agent-hangar/scratch/*` は動かさず、消さない。その下の会話は cwd もそのままで、いままでどおり再開できる。
  - クイックセッションかどうかの判定（`isUnderScratch` など）は、`~/.agent-hangar/scratch` と `~/.agent-hangar/quick-sessions` の 2 つの完全なパスで行う。
  - 利用者が自分で作った `scratch` という名前のフォルダ（`~/workspace/scratch` など）は、クイックセッションと取り違えない。試験で確かめる。
- ほかの PC のクイックセッションを再開するとき、cwd がこの PC に無ければ、この PC の `quick-sessions/<元のフォルダ名>` を作ってそこで再開する。元のフォルダ名は Windows と POSIX のどちらの区切りでも取り出す。
- フォルダの信頼（Claude Code の「このフォルダを信頼しますか」）について、親のフォルダの信頼が子に及ぶかを実物の claude で確かめてから、次のように作る。
  - クイックセッションの置き場は、hangar が自分で信頼済みにする。使っているアカウントの設定ディレクトリの `.claude.json` に、既存の安全な書き込み（`claudeFileWrite.ts`）で書く。
  - 作業フォルダは、セットアップのすゝめの中で利用者の同意を取ってから、`hangar workspace set <dir> --trust` で信頼済みにする。
