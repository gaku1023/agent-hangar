# 画面分割（別のセッションを並べる）の計画

決まったこと、動き、文言、今のコードの前提は `docs/plans/session-split-handoff.md` にある。
手本の試作は `docs/plans/session-split-proto.html`（ブラウザで開く）。
この計画はインタフェース、受け入れの試験、タスクの分け方だけを書く。

枝は `worktree-session-split`。
今あるセッション内のタブ分割（`split.toggle`、`split.resize`、`SessionViewState.split`、`views/SplitPane.tsx`）は触らない。
新しい分割は名前を `pane` でそろえ、取り違えないようにする。

## 用語

- ペイン：本体を分けた 1 区画。1 つのセッションか、空（セッション未選択）を入れる。
- 分割の木：ペインを葉、分け目を節にした二分木。節は向き（横に並ぶ `row`、縦に並ぶ `col`）と比率を持つ。
- 操作中のペイン：キーと見出しの操作が向かうペイン。青い枠で示す。

## 状態（mediator）

`State` に `panes` を足す。

- `panes.root`：分割の木。葉は `{ kind: 'pane', id, sessionId: string | null, toc: boolean }`、節は `{ kind: 'split', id, dir: 'row' | 'col', ratio, a, b }`。ペインが 1 つも無いときは null。
- `panes.focus`：操作中のペインの id。
- `panes.zoom`：最大化しているペインの id か null。保存しない。

画面との関係（ここが要）：

- `state.screen` が `session` のとき、`screen.id` は常に操作中のペインの `sessionId` と同じにする。キー、ヘッダ、履歴は今までどおり `screen.id` を見ればよい。
- セッションへ移る入力（サイドバーのクリック、一覧から開く、⌘I、ディープリンク、戻る・進む）は次のように木を変える。
  - そのセッションが木にあれば、そのペインを操作中にする。
  - 無ければ、操作中のペインの中身をそのセッションに替える。
  - 木が null なら、ペイン 1 つの木を作る。
- ペインを押して操作中を移したときは、`screen` を合わせる。履歴は積まない（置き換え）。
- ホーム、プロジェクト、設定へ移っても木は残す。セッションへ戻ると分割が戻る。
- 消されたセッション（Store から消えた行）のペインは外す。終わっただけのセッションは、終わった画面のまま残す。
- ペインが 1 つのときは、今までの 1 画面と同じ見た目にする（大きな見出し、右パネルは今の開閉のまま）。

保存：

- `localStorage` の `panes.layout` に `{ root, focus }` を残す。木の形か操作中が変わるたびに `storage.save` の Effect を出す。
- 起動時に `runtime.ts` で読み、壊れた形を捨てる関数（`cleanPaneLayout`）を通す（`sidebarOrder` と同じ形）。

## 入力（UiAction）

| 入力 | 中身 | 振る舞い |
|---|---|---|
| `pane.open` | `sessionId, target: paneId \| null, side: 'left' \| 'right' \| 'up' \| 'down' \| 'center'` | target は null なら操作中のペイン。辺なら分けて新しいペインを置き、中央なら置き換える。すでに木にあるセッションなら、新しく開かず、そのペインを操作中にして光らせる（`pane.flash` の一時状態）。 |
| `pane.openEmpty` | `side: 'right' \| 'down'` | 操作中のペインの隣に空のペインを開く（⌘D、⌘⇧D）。 |
| `pane.fill` | `pane, sessionId` | 空のペインにセッションを入れる。 |
| `pane.remove` | `pane` | 分割から外す。セッションは止めない。最後の 1 つなら知らせを出して何もしない。 |
| `pane.removeOthers` | `pane` | ほかのペインを全部外す。 |
| `pane.move` | `pane, target, side` | 見出しのドラッグ。中央なら 2 つの中身を入れ替える。辺なら抜いて差し込む。自分の上は無効。 |
| `pane.resize` | `node, ratio` | 境目のドラッグとキー。比率は 0.1〜0.9 に収める（最小の幅は描画の側で 280px を守る）。 |
| `pane.equalize` | なし | 全部の節の比率を 0.5 に戻す。 |
| `pane.focus` | `pane` | 操作中を移す。 |
| `pane.zoom` | `pane` | 最大化と解除を切り替える。外したペインが最大化中なら解除する。 |
| `pane.toc` | `pane` | そのペインの右パネルを開閉する。ペインが 2 つ以上のときに効く。 |

隣のペインへの移動（⌘⌥矢印）は位置で決めるので、描画の側で隣を求めて `pane.focus` を出す。

## 描画（views）

- `Root.tsx` の `session` の場合：ペインが 2 つ以上なら `PaneWorkspace`、1 つなら今までどおり `SessionScreen`。
- `PaneWorkspace`：木を入れ子の flex で描く。節の子の大きさは `flex-grow` に比率を入れる。境目は今の `SplitPane` の Divider と同じ触り心地（ドラッグ、ダブルクリックで均等、矢印キー、ドラッグ中は `beginLayoutMotion`）。
- 各ペインは `SessionScreen` を `variant="pane"` で描く。`presentSession` にはペインの `sessionId` を渡す。
  - 大きな見出し（PageHeading）の代わりに `PaneHeader`（案 A）を出す。点、名前、プロジェクト名、一言、ステータスの札、主の操作、⋯、ⓘ、☰、✕。
  - 幅で畳む：620px 未満で一言とプロジェクト名と主の操作の文字を消す。420px 未満でステータスの札の文字を消し、主の操作と ⓘ を ⋯ の中へ移す。判定はペインごとの ResizeObserver。
  - 右パネルはペインの `toc` に従う（既定は閉じる）。
- 空のペインは `PanePicker`。動いているセッションの一覧を出し、押すと `pane.fill`。
- 操作中のペインは青い 2px の枠。最大化中は、そのペインだけを本体いっぱいに出し、見出しに解除のボタンを出す。
- サイドバーの行の右端に、木にあるセッションならペインの番号の札（ペインが 2 つ以上のときだけ）。

## ドラッグ（views）

- HTML5 DnD は使わない。サイドバーの RowList の pointerdown と DRAG_SLOP の流れに、本体の上に出たときの分岐を足す。
- ドロップ先は純関数 `dropZone(rect, point)` で決める。辺までの距離の最小が 0.28 未満ならその辺、ほかは中央。
- 予告の枠は本体の上に 1 つだけ置き、位置と大きさを滑らせる。ラベルは handoff の文言。
- ペインの見出しのドラッグは `pane.move`。自分の上は「同じ位置には配置できません」と出して落とせない。
- Esc でやめる。サイドバーの上に戻したときは、今までどおりの並べ替えになる。

## 右クリックとキー

- `presenters/sessionMenu.ts` の `sessionMenuEntries` に「右に分割して開く」「下に分割して開く」を足す。そのセッションが木にあれば先頭を「表示中のペインへ移動」にする。サイドバーと一覧の両方に効く。
- ペインの見出しの右クリック：ステータス（サブメニュー）、ID をコピー、ペインを最大化／解除、右に空のペインを開く、下に空のペインを開く、ペインのサイズを均等にする、分割から外す、ほかのペインを外す。
- ⌥クリック（ほかの OS は Alt）で右に分割して開く。
- `keys.ts` に足す：`pane.splitRight` ⌘D、`pane.splitDown` ⌘⇧D、`pane.remove` ⌘⇧W、`pane.focusDir` ⌘⌥矢印、`pane.zoom` ⌘⇧↩。ほかの OS とターミナルの中の割り当ては、既存の表とぶつからない組を選び、表のコメントに理由を書く。

## 文言

handoff の表のとおり。`packages/shared/src/i18n/{ja,en,keys}/` に足す。用語集（`docs/superpowers/specs/2026-10-09-glossary.md`）に「ペイン」「画面の分割」「分割から外す」「最大化」の行を足す。

## 受け入れの試験

T1（mediator、純関数）：

- 1 つのペインに右・左・上・下で開くと、向きと並びの合った節ができ、新しいペインが操作中になる。
- 中央で開くと中身だけ替わり、ペインの数は変わらない。
- 木にあるセッションを開くと、数は変わらず、そのペインが操作中になり、光らせる一時状態が立つ。
- 外すと親の節がたたまれ、兄弟が親の位置に入る。操作中だったら兄弟の最初のペインへ移る。最後の 1 つは外れず、知らせが出る。
- 入れ替えと差し込みの後も、ペインの id とセッションの組が保たれる。
- 比率は 0.1〜0.9 に収まる。均等にすると全部 0.5。
- 最大化中のペインを外すと最大化が解ける。
- セッションへ移る入力で、木にあれば操作中が移り、無ければ操作中のペインが替わる。`screen.id` は常に操作中のペインのセッション。
- 木の形と操作中が変わると `storage.save` が 1 回出る。最大化と光らせるのは出さない。
- `cleanPaneLayout` が、壊れた形、同じセッションの重複、空の木を捨てる。
- 消されたセッションのペインが外れる。

T2〜T4（views、jsdom）：

- ペインが 2 つ以上のとき、大きな見出しが無く、ペインの数だけ見出しがある。1 つのときは今までどおり。
- ペインの見出しに、ステータスの札、主の操作、⋯、ⓘ、☰、✕ がある。幅で `tight`、`tiny` が付く。
- `dropZone` が辺の近くで辺、真ん中で中央を返す（角も含めて表で試す）。
- サイドバーの行を本体へ引いて離すと `pane.open` が出る。Esc では出ない。自分の見出しの上では `pane.move` が出ない。
- 右クリックの項目に 2 つの分割があり、木にあるセッションでは「表示中のペインへ移動」が出る。
- 新しいキーが既存のキーとぶつからない（keys の既存の試験に乗る）。i18n の ja・en・keys がそろう（既存の試験に乗る）。

T5（動き）：

- 動きを減らす設定では、どの動きも呼ばれても何もしない。
- 画面の確かめ：4177 の実データに worktree の `packages/ui/dist` を重ねて WebKit で撮る（memory の reference-overlay-ui-check）。1 つ → 2 つ → 3 つ → 1 つの途中と終わりを撮って見る。

## タスク

順に進める。T3 と T4 は T2 の後に並べてよい。

1. **T1 状態**：`panes` の型、入力、純関数、保存と読み込み、画面との関係、消されたセッションの刈り込み。試験は上の T1。
2. **T2 描画**：`PaneWorkspace`、`PaneHeader`（案 A と畳み方）、`PanePicker`、境目、ペインごとの右パネル、最大化、サイドバーの番号の札。`SessionScreen` の `variant="pane"`。
3. **T3 ドラッグ**：サイドバーの行と見出しのドラッグ、`dropZone`、予告の枠、Esc。
4. **T4 右クリックとキー**：sessionMenuEntries、ペインの右クリック、⌥クリック、keys と一覧、隣への移動。
5. **T5 動き**：handoff の「動き」の節を motionKit のトークンで。名前の札の移動、見出しの開閉、予告の出方、札の吸い込み、入れ替えと最大化の FLIP、右パネルの畳み、番号の札、空のペインの一覧。
6. **T6 文書と文言**：`docs/design.md` に「画面の分割」の節（セッション内タブの節の近く）、i18n、用語集。

各タスクは implementer（sonnet）に 1 本ずつ渡す。そのあとは CLAUDE.local.md の流れ（typecheck と全部の試験、画面の確かめ、build 3 本、PR、CI、マージ、アプリの入れ替え、後片付け）。
