# 本番のクラウドを作って使い始めた記録（2026-09-20）

フェーズ 4 の確認は試し用の資源（`hangar-dev`）で行い、終わったら消した。
この文書は、利用者が**本番として使い始めた**ときの記録である。
作ったのは Worker `hangar`、D1 `hangar`、R2 `hangar-files` で、消していない。

## 決めたこと

- **メタデータ（セッションの一覧、要約、プロジェクト、TODO、メモ）は全部同期する。**
  2 台目で過去のセッションが一覧と検索に出て、選んだものだけ本文が降りてくる。
- **本文（会話の中身）は、クラウドを使い始めた後に動いたものだけ上げる。**
  手元には 1,060 件、生の合計 1.6 GB があり、全部上げる意味は薄いと判断した。
  新しく始めたセッションと、再開したセッションが対象になる。
  過去の分を上げたくなったら `hangar cloud backfill` で床を外す。
- 参加トークンは 1Password の Employee vault に「agent-hangar join token」として置いた。
  2 台目はそれを読んで `hangar join <トークン>` に渡す。

## 起きたこと

### 参加トークンを画面に出してしまった

伏せ字の処理が 16 進を想定しており、base64 のトークンを素通りさせた。
R2 が空で 2 台目も未参加だったので、**秘密を作り直す代償はゼロ**だった。
`setup cloud --rotate-secret` で作り直し、新しいトークンは画面に出さずに 1Password へ直接入れた。
値をコマンドの引数に置かず、標準入力で渡した。

### 「これから触るものだけ」が効かず、過去の本文が 105 件（148 MB）上がった

`/Applications/Hangar.app` が、この決まりが入る前のサーバを同梱していた。
古いサーバが先に起動して同期を始め、`lastSeq` を書いた。
そのあとに起動した新しいサーバが「すでに同期したことがある端末」と判断し、床を 0（全部上げる）にした。

床を刻む場所を、サーバの推測から **CLI が `cloud.json` を書く場所**へ移した。
保険として残したサーバ側の判定も、`lastSeq` ではなく `cloud.json` の `joinedAt` を見る形にした。
実物で起きた筋（古いサーバが先に走る）をそのまま試験にしてある。
上がってしまった 105 件は直近の作業なので、利用者の判断で残した。

### 枠の数え方を実物で突き合わせた

これがこの回の主目的だった。

`wrangler d1 insights` は Cloudflare の計上として 14,860 行を返し、Worker の台帳は 12,829 行だった。
14% の食い違いに見えたが、**当てにならなかったのは insights の方だった。**

- `changes` の連番は 1 から 2,411 まで隙間なく詰まっており、挿入はちょうど 2,411 回である。insights は 3,196 回と申告した。
- 同じ batch に必ず 2 文ずつ積む二つの文の回数が一致しない（3,196 対 2,433）。
- スキーマの 8 文は 1 つの batch で同時に走るのに、回数が 83 から 4 まで 20 倍ばらついた。
- 公式にも `d1QueriesAdaptiveGroups` は適応標本抽出の推定だと書かれている。

手元の miniflare で同じ流れを流すと、模型 13,262 行に対して台帳も 13,262 行で、一行も狂わなかった。
**台帳は正しい。突き合わせの物差しには `max(seq)` を使う。**

一方で、**端末側の見積もりは本当に少なく数えていた。**
`changes` への挿入は `seq integer primary key autoincrement` が `sqlite_sequence` も書き換えるので 1 回 3 行で、定数の 2 は誤りだった。
台帳自身の 1 文も見積もりに入っていなかった。
どちらも直し、スキーマから `autoincrement` が消えたら試験が落ちるようにした。
報告が届かないときの見張りは、これでおよそ 25% 早く止まる。

### `.app` がときどき自分から終了する

2 回起きた。1 回目は起動 44 秒後、2 回目は 103 秒後である。
一方で、同じ日に 4.8 時間動き続けた回もある。

分かっていること。

- クラッシュの記録は残らない。`~/Library/Logs/DiagnosticReports` に何も無い。
- ログの最後は `server stopped` で、正規の終了の手順を踏んでいる。アプリが「終了」を受け取っている形である。
- メモリ不足ではない（48 GB、jetsam の記録なし）。
- **何もせずに放置すると 3 分以上動き続ける。**
- `hangar cloud status` を 12 秒ごとに 8 分叩いても落ちない。

**再現の条件を特定できていない。** 2 回とも、入れ替えた直後で、同期が大量に動いている最中だった。
次に起きたときのために、起動の時刻と、そのとき走らせていたものを控える。
