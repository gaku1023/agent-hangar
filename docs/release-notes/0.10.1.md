# Hangar 0.10.1

Hangar を終了しても opencode の会話が続くようになり、ローカルモデルの準備も Hangar が自動で行うようになりました。

## 更新の前に

0.10.1 を起動すると、この PC のデータベースが新しい形式に更新され、0.10.0 以前には戻せなくなります。同期しているほかの PC は、0.10.0 のままでも同期できます。

## 足したこと

### Hangar を終了しても、opencode の会話が続きます

- Claude の会話と同じく、返答の途中で Hangar を終了しても opencode は動き続けます。Hangar を再び開くと、進行中の会話に再接続します。
- opencode を終了すると、バックグラウンドで動いていたサーバーも 1 秒ほどで停止します。

### LM Studio のモデルを、会話の開始前に準備します

- 会話を始める前に、使うモデルを必要なコンテキスト長でロードし直します。長さは設定 › 連携 › opencode の「ローカルモデルのコンテキスト長」で変更できます（デフォルトは 64K）。
- メモリが足りない場合は、1 つのモデルにまとめるか、ほかのモデルをアンロードするかを、会話の開始前に確認します。アンロードするのは Hangar がロードしたモデルだけです。

### OpenAI 互換サーバーに「準備」を設定できます

- 接続先ごとに、会話を始める前に実行するコマンドと、最後の会話が終わったあとに実行するコマンドを設定できます。GPU サーバーを起動してから使う、といった使い方ができます。

### opencode のシェルコマンドは、実行前に確認します

- git status や ls などの読み取り専用のコマンドはそのまま実行し、ほかのシェルコマンドは実行前に確認を求めます。
- 設定 › 連携 › opencode の「コマンド実行前に確認」でオフにできます。opencode.json に permission の設定がある場合は、そちらが優先されます。

### サイドバーの幅を変えられます

- サイドバーの右端をドラッグすると、幅を変更できます。ダブルクリックで元の幅に戻ります。

### そのほか

- 新しい会話のダイアログで、エージェントを選ぶ所にアイコンが表示されるようになりました。
- opencode で /models からモデルを切り替えると、右パネルのモデルの表示も切り替わります。
- 新しく同期に参加した PC は、新しい会話から順に取得します。ディスクの空きが足りなくなりそうなときは、取得を中断してお知らせします。

## 直したこと

- 終わった会話の見出しの経過時間が、最後のメッセージより後の動きを基準にしていました。今は「最終メッセージ N 分前」として、最後の入力か返答の時刻から数えます。
- Windows で、ターミナルを開いてすぐに閉じると、バックグラウンドにプロセスが残ることがありました。今は残りません。
- Windows で、ターミナルを開いて閉じるたびに、Hangar のサーバーが使うシステムのリソース（ハンドル）が増えていました。今は増えません。
- お知らせの一覧で、説明が 2 行で途切れて最後まで読めませんでした。今は全文を表示します。
