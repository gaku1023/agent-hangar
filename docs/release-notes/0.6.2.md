# Hangar 0.6.2

## フォルダの登録

### ほかの PC で登録したプロジェクトに、この PC のフォルダを結び付けます

2 台の PC で同じリポジトリを使うとき、0.6.1 までは、それぞれの PC で登録するたびに別のプロジェクトができていました。
同期すると、同じ名前のプロジェクトが 2 つ並びました。

0.6.2 からは、ほかの PC から届いていて、この PC に場所の無いプロジェクトのうち、次のものを「同じプロジェクト」と見なします。

- git の remote が同じもの（`git@github.com:owner/repo.git` と `https://github.com/owner/repo` は同じと読みます）。
- 名前が同じで、remote が食い違わないもの。

新しいフォルダの作成場所の直下で Claude Code と会話したフォルダを自動で登録するときは、同じプロジェクトがあれば、新しく作らずにこの PC の場所として結び付けます。
結び付けは「場所を再指定」と同じで、そのフォルダで動いた会話もそのプロジェクトに入ります。
名前が同じでも remote が違うときは、別のリポジトリなので結び付けず、今までどおり新しく作ります。

見分けるために、プロジェクトに git の remote を覚えるようにしました。
覚えるのは `github.com/owner/repo` の形だけで、URL に含まれるユーザー名やトークンは覚えません。
同期している PC は、0.6.2 に上がると、自分の PC に場所のあるプロジェクトの remote を起動のときに埋めます。
0.6.1 以前の PC が残っていても同期は壊れませんが、その PC は remote を埋めないので、その PC だけで登録したプロジェクトは名前でしか見分けられません。

### 登録済みのプロジェクトの中のフォルダを、黙って別のプロジェクトにしません

0.6.1 までは、登録済みのプロジェクトの中のフォルダ（たとえば `agent-hangar/packages/ui`）を登録すると、確認なしで別のプロジェクトに分かれていました。
0.6.2 からは、そのフォルダが「<名前> の中にあります」と知らせ、分けると決めたときだけ別のプロジェクトにします。
分けても、それまでの会話は元のプロジェクトに残ります。
分かれるのは、これからの会話です。

登録済みのプロジェクトの中のフォルダからセッションを始めたときは、セッションは元のプロジェクトに入り、Claude Code はそのフォルダで起動します。
