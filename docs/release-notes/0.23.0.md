# Hangar 0.23.0

別の PC の会話を手元の会話と同じ画面で扱えるようにし、未読の同期、英語の返答の翻訳表示、Linux でのサーバーの常駐を追加しました。

## 更新の前に

未読・ミュート・使用率・開いている会話の同期は、同期する PC がすべて 0.23.0 のときだけ動作します。同期する PC は同じ版に統一してください。

- 0.23.0 を 1 回でも起動するとデータベースの形式が変わり、前の版には戻せなくなります。
- この版では Worker の更新は不要です。

## 足したこと

### 別の PC の会話を手元の会話と同じ画面で閲覧・回答できます

- 別の PC の会話でも、右の欄に現在の作業とターンの目次が表示されます。目次から過去のターンへ移動でき、上へスクロールすると過去の分を追加で読み込みます。
- 別の PC の Codex と opencode の会話も、Claude Code の会話と同じく閲覧、送信、中断、許可や質問への回答ができます。質問には選択肢の説明が付き、思考の要約も表示されます。
- 別の PC の会話でも、入力欄で `/` を入力すると、会話が動いている PC のスキルとコマンドが候補に表示されます。アカウントの切り替えもその PC で行い、ヘッダーのアカウントの表示もその PC のものになります。

### 別の PC の会話の作業ディレクトリで SSH のシェルを開けます

- 別の PC の会話の画面に、「Claude」「シェル」「+」のタブを追加しました。「+」を押すと、その会話の作業ディレクトリで SSH のシェルが開きます。鍵と接続の設定は、OS の `ssh` の設定をそのまま使います。

### 未読を 2 台で同期し、会話をミュートできます

- どちらの PC で既読にしても、両方で既読になります。どの会話を開いているかも同期するので、片方で開いている会話の通知はもう片方にも出ません。
- ミュートした会話は未読の数に含めず、通知もしません。ミュートと解除は会話のメニューで切り替えます。
- 返答が終わるたびに Hangar が未読を 1 つ付けます。エージェントに毎回の通知を求めなくなったので、その分のトークンの消費が減ります。

### 英語の返答を日本語に訳して表示できます

- PFN の plamo-translate を使い、会話の記録の画面と実行中のターミナルで、英語の返答に訳を表示します。思考は、開いたときか訳すアイコンを押したときに訳します。翻訳はこの PC の中で行い、エージェントに渡る内容は変わりません。
- 既定では無効です。ホームのセットアップの確認に出る「翻訳」の行で有効にします。Windows では使えません。

### 会話の context の使用量をサイドバーで確認できます

- 各会話の状態の点を囲む輪が、context の使用量に応じて伸びます。量が増えると黄、赤の順に色が変わり、ポインタを合わせると `448K/1000K` の形式で表示されます。同じ数字は会話の右の欄にも表示されます。

### Linux でサーバーだけを常駐させられます

- tar をダウンロードして `install.sh` を実行し、`hangar service install` で systemd のサービスとして常駐させます。更新は `hangar update` で行います。手順は [Linux で使う](https://github.com/gaku1023/agent-hangar/blob/main/docs/linux.md) にあります。

### そのほか

- ホームの Paused の行の「今すぐ試す」は、その会話が最後に動いた PC で起動します。
- 使用率をアカウント名ごとに 2 台で同期します。別の PC で使った分も、ヘッダーの使用率の表示に反映されます。
- サイドバーの開閉ボタンの隣に、戻る・進むのボタンを追加しました。Hangar の会話へのリンクはブラウザではなくアプリの中で開きます。
- スマートフォンの会話の画面が Codex と opencode の会話に対応しました。札には理由と選択肢の説明が表示されます。
- 新しいディレクトリで Claude Code が求める信頼の確認に、札で答えられます。別の PC からも答えられます。

## 変わったこと

- 手元の Claude Code の会話では、本文の上に札の帯を出さなくなりました。Claude Code の札は従来どおりターミナルで答えます。Codex と opencode の会話の帯と、ホームの行の札は変わりません。
- 会話の記録の返答と思考の表示の幅を、約 38 字から約 60 字に広げました。
- Hangar の MCP を使うエージェントは、会話ごとの URL からでもほかのプロジェクトを読み書きできるようになりました。ほかの会話を Done や Paused にすることもできます。
- ホームの未読に統括の会話も表示するようになりました。統括を無効にしている別の PC のサイドバーには、統括の会話を出さなくなりました。

## 直したこと

- 別の PC の会話の質問に答えると、誰も答えていないのに「すでに答えています」と拒否されることがありました。同じ質問の札が 2 枚並ぶこともありました。
- 別の PC の会話で札に答えたあとも、入力待ちの表示がしばらく残っていました。いまは即座に消えます。
- 別の PC の会話でアカウントを切り替えると、「ディレクトリが見つかりません」で失敗していました。
- 貼り付けた文章が、会話の吹き出しに `<pasted_content id="…">` のタグのまま表示されていました。いまは貼り付けた部分を、吹き出しの中に左に線の付いた引用として表示します。
- 別の PC でバックグラウンドの処理だけが動いている会話が、作業中の濃い点で表示されていました。いまは薄い点で表示します。
- 返答 1 回に未読が 2 つ付くことがありました。
- 最初の指示が長いと、起動が「command too long」で失敗していました。
- バックグラウンドの処理だけが残っている終了済みの会話が、サイドバーの実行中から外れていませんでした。
- 実行中の会話が止まると、プロジェクトのグループの並び順が入れ替わっていました。
- 会話から起動した `claude` の使用率が、別のアカウントの使用率として計上されていました。
- 予定で起動した会話は、利用者が途中から加わっても、終了時に「このセッションをどうしますか」と尋ねていませんでした。
- Windows で SSH のシェルが「SSH サーバーがありません」で失敗していました。接続のたびに警告も表示されていました。
- 別の PC の会話を開くと、ターンが少ない間は右の欄が折りたたまれていました。
- Windows と Mac で statusLine の内容が異なるだけで、設定の同期の競合として扱われていました。
- opencode で、使用しないモデルの読み込みが終わるまで待たされていました。
- Worker が古いときのエラーの文が、相手の PC が古いという内容になっていました。いまは「Worker を更新してください」と表示します。
