# Hangar 0.6.1

## 直したこと

### Node 24 など、新しい Node でも起動します

0.6.0 までは Node 22 だけを使っていたので、Node 24 だけがある PC では起動の画面に「Node が見つかりません」と出て、Hangar を使えませんでした。
Hangar のデータベースと端末の部品は Node-API 10 を使うので、要るのは Node 22.14 以上です。
0.6.1 からは、Node 22.14 以上（Node-API 10 以上）で、アーキテクチャが合う Node を使います。
新しい版に上限はありません。
今 Node 22 を使っている人や、設定の「Node のパス」で Node を指している人は、これまでと同じ Node を使います。
`hangar` コマンドも同じ条件で Node を選びます。

### 起動できないとき、Node の何が合わないかを言い分けます

- 合う Node が無いときの起動の画面の見出しを、場合で分けました。
  Node が見つからないときは「Node.js が見つかりません」、古い Node だけがあるときは「Node.js 20.18.0 は見つかりましたが、Hangar は Node.js 22.14 以上が要ります」、作りが違うときは「x64 用の Node.js は見つかりましたが、Hangar は arm64 用が要ります」です。
  記録（`desktop.log`）の種類も、`node-missing`、`node-version-mismatch`、`node-arch-mismatch` に分けました。
- 古い Node があるときは、今の Node を置き換えない入れ方を先に案内します。
  macOS は `brew install node@22`、Windows は nodejs.org の zip を別のフォルダに展開する手順です。
  winget の Node は `C:\Program Files\nodejs` の今の Node を置き換えるので、Node が何も無いときだけ案内します。
- 起動の画面に「node を選ぶ…」（Windows は「node.exe を選ぶ…」）を足しました。
  選んだ Node を設定の「Node のパス」と同じ条件で確かめ、合えば保存して起動し直します。
  合わなければ、その理由を出します。
- 設定の「Node のパス」も、版が古いのか作りが違うのかを分けて言います。

### 同じフォルダを指すプロジェクトを 1 つにまとめられます

2 台の PC で同じリポジトリを別々に登録すると、同期で同じ名前のプロジェクトが 2 つ並びます。
0.6.0 までは、届いた方の「場所を再指定」で、この PC で登録済みのフォルダを選ぶと、同じフォルダを指すプロジェクトが 2 つになっていました。
そうなると、新しいセッションがどちらに入るかが決まりませんでした。

0.6.1 からは、登録済みのフォルダを選ぶと「<名前> と 1 つにまとめますか」と確認します。
確認には、まとめた後のプロジェクトが PC ごとに持つ場所と、セッションの数を並べます。
「1 つにまとめる」を押すと、届いた方のセッション、TODO、メモ、成果物が元からある方へ移り、他の PC の場所も引き継ぎます。
届いた方は一覧から消えます。
同期している他の PC でも 1 つになります。元には戻せません。
ディレクトリとトランスクリプトは変わりません。

0.6.0 までに既に 2 つになってしまったものは、ホームの帯の「同じフォルダのプロジェクト」と、プロジェクトの画面のパスの横の札から、同じ確認でまとめられます。
同期している PC は、どれも 0.6.1 に上げてください。
0.6.0 のままの PC では、「場所を再指定」が今までどおり確認なしで同じフォルダを結び付けます。

### サイドバーの並べ替えがアプリの中で効かなかったのを直しました

- サイドバーの「実行中」の行を掴んで上下に動かす並べ替えが、デスクトップのアプリの中では効いていませんでした（ブラウザで開いたときは効いていました）。
  アプリの中でも、行を掴んで動かすと入る場所に線が出て、離すとその場所へ入ります。
- 押してすぐ離したときは、これまでどおりそのセッションへ移ります。
  少し動かしてから離したときは並べ替えだけを行い、セッションへは移りません。
- 動かしている途中で Esc を押すと、並べ替えをやめます。

### Windows のアプリで、トラックパッドの横スワイプで戻る進むができるようになりました

- 0.6.0 までは、Windows のアプリの中ではトラックパッドを 2 本指で横に払っても、前の画面へ戻りませんでした。
  0.6.1 からは、macOS と同じく、払うと画面の端に矢印が出て、引き切って指を離すと戻ります（逆へ払うと進みます）。
- Windows は指を離した瞬間をアプリに知らせないので、払う手が止まったところで離したとみなします。
  引き切ったまま指を止めても動きます。止めたくないときは、引き切る前に戻してください。
- 縦に流しているとき、横へ流せる一覧の中で、まだ端に着いていないときは動きません。
- ブラウザで開いたときは、これまでどおりブラウザの戻る進むに任せます。

### マウスの戻るボタンと進むボタンが効くようになりました

- デスクトップのアプリ（macOS と Windows）で、マウスの横にある戻るボタンと進むボタンで、前の画面と次の画面へ移れます。
- ⌘[ と ⌘]（Windows では Ctrl+[ と Ctrl+]）と同じく、入力欄やターミナルにフォーカスがあっても効きます。
  入力のあるダイアログを開いている間と、アプリの最初の画面からは戻りません。

## ほかの PC で進めた会話

### macOS と Windows の間で「この PC で再開」できるようになりました

0.6.0 までは、ほかの PC で進めた会話を「この PC で再開」すると、前の PC の作業フォルダのパス（たとえば `D:\src\notes-app`）をそのまま使って起動しようとしていました。
macOS と Windows の間のように、パスの形が違う PC の間では、トランスクリプトを写した後に「ディレクトリが見つかりません」で止まっていました。
0.6.1 からは、前の PC のプロジェクトの場所からの相対パスを、この PC のプロジェクトの場所に読み替えて起動します。
worktree や下位のフォルダで進めていた会話も、この PC に同じフォルダがあればそこで、無ければいちばん近い親のフォルダで起動します。
フォークも同じです。

この PC にプロジェクトの場所が無いときは、トランスクリプトを写す前に止めます。
先にプロジェクトの場所を指定してください。

### 確認の 1 枚で、前の PC とこの PC を見せます

「この PC で再開」を押すと、前の PC（名前、OS、作業フォルダ、最後に使った日時）とこの PC（名前、OS、作業フォルダ）を並べた確認を出します。
プロジェクトのファイル、未コミットの変更、開発環境（道具、環境変数、秘密の値）は同期されません。
同期されるのは会話のトランスクリプトと hangar の記録だけです。

この PC にプロジェクトのフォルダが無いときは、「この PC で再開」を押せなくし、理由と「場所を指定」を見出しの下に出します。
一覧の行のメニューでも、項目の下に理由を出します。

### ほかの PC で進めた会話を続けるとき、Claude に引き継ぎを伝えます

Hangar から再開した会話の直前の実行がほかの PC だったときは、Claude に次のことを伝えます。

- 前の PC とこの PC の名前と OS、前の作業フォルダとこの PC の作業フォルダ、最後に使った日時、会話の終わりのブランチ。
- 同期されたのはトランスクリプトと hangar の記録だけで、ファイル、git の作業ツリー、未コミットの変更、環境は同期されていないこと。
- この会話で編集したファイルのうち、この PC に無いもの（10 件まで）。
- 次の指示を受けたら、作業に入る前に 1 度だけ git の状態を確かめ、合わなければ推し量って進めずに聞くこと。ssh、scp、rsync は Claude が自分で打たないこと。

この PC で 1 度動かした後は伝えません。
2 台以上の PC で使っているプロジェクトでは、過去の会話のパスやファイルの状態がこの PC と違うことがある、とだけ 1 文で伝えます。
どちらも、同期を使っていなければ出ません。
設定の「足す指示の全文を見る」で、全文を確かめられます。

### MCP の検索と一覧に、会話を動かした PC を添えます

`search_sessions`、`list_sessions`、`get_project` の直近のセッションに、会話を最後に動かした PC（名前、OS、この PC かどうか）を添えます。
