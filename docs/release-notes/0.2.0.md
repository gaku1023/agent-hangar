# Hangar 0.2.0

## v0.1.0 から入れ替える人へ（先にお読みください）

v0.1.0 には自動更新が無いので、手で入れ直します。
この dmg を開き、`Hangar.app` を `Applications` へドラッグして、古い `Hangar.app` を置き換えてください（先に Hangar を終了します）。
`~/.agent-hangar` の中身は、そのまま引き継がれます。

0.2.0 から、署名が変わります。
v0.1.0 は署名なしで、0.2.0 は自作の証明書で署名します。
入れ直したあとの初回だけ、次の 2 つが起きます。

- 「"Hangar" は開いていません」という警告が、もう一度出ます。
  「完了」で閉じ、システム設定の「プライバシーとセキュリティ」で、「…"Hangar"がブロックされました。」の行の「このまま開く」を押します。
  README の「インストール（配布版）」の 3 段目に、手順を書いています。
- ローカルネットワークなどの許可を、一度だけ取り直します。

この入れ直しのあとは、更新のたびに警告も許可の取り直しも出ません。

## お知らせ（設定を直す必要がある人へ）

設定の「Node のパス」（`nodePath`）に、次のどれかを入れている人は、0.2.0 からその指定が使われません。

- 名前だけの指定（`node` など）や、相対パス。フルパスで指定してください。
- `~/` で始まる値。`~` は展開されないので、フルパスに書き直してください。
- Hangar が同梱する版と違う Node（版かアーキテクチャが違うもの）。

設定の欄の下の確かめが ✗ になり、保存もできません。
Node 22 のフルパスに直してください（例：`which node` で出る場所）。
使われなくなったときは、Hangar が Node を自分で探します。

## 新しくなったこと

### 自動更新

- 設定の「更新」の節と右下の札が、新しい版を知らせます。
  起動したときと、その後 6 時間おきに確かめます。
  「ダウンロードしてインストール」を押すと、取得して入れ替え、再起動したあとにセッションの続きを表示します。
  tmux の中のセッションは止まりません。
- 更新は、署名を確かめてから入れます。
- 起動に失敗したときの札にも「更新を確認」があります。
  起動に失敗する版からでも、次の版へ入れ替えられます。
- 取得している最中に「更新を確認」を押しても、取得中の版のまま進みます。

### 許可が保たれる署名

- Hangar を入れ替えても、ローカルネットワークなどの許可が外れなくなりました。
  これまでの未署名の build は、入れ替えるたびに別のアプリとして扱われていました。

### 配布

- macOS は、dmg で配ります。zip は予備です。どちらにも checksum を添えています。
- 試しの版（Pre-release の印の付いたもの）は、確かめが済むまでの間だけ置きます。ふだんは Latest の版を使ってください。

### Windows 11（x64）

- Windows のインストーラ（`Hangar-v0.2.0-windows-x64-setup.exe`）を添えました。
  管理者権限は要らず、`%LOCALAPPDATA%\Hangar` に入ります。
  署名していないので、SmartScreen が出たら「詳細情報」から「実行」を選びます。
- tmux の代わりに psmux を使います。先に `winget install -e --id marlocarlo.psmux` で入れてください。Node 22 も要ります。
- 入力待ちの通知、外のターミナル（Windows Terminal）、`hangar open`、`hangar` コマンドの PATH への追加が使えます。
- Hangar の窓や、フォルダを選ぶダイアログが前にあるときは、入力待ちの通知を出しません。
- Windows Terminal が無くて既定のターミナルで開いたときの知らせは、8 秒出ます。
- Hangar を開いたままアンインストールして、確認で取り消しても、`hangar` コマンドの PATH はそのまま残ります。
- ターミナルで打った `claude` の包み（`hangar shell install`）は、Windows では作りません。セッションは Hangar の画面から始めます。

### 通知

- 入力待ちの通知と、戻る時刻の通知は、別々に残ります。
  戻る時刻の通知が来ても、入力待ちの通知の問いの文は消えません。
- 答えた、止めた、Done や Archived にしたセッションの古い通知は、通知センターから消えます。
  Hangar を終了している間に古くなった通知も、次の起動で消えます。
  Windows では、アンインストールしたときに、Hangar の通知もすべて消えます。

### コマンドとプロジェクト

- `hangar open` は、鍵の付いた URL を端末に出さなくなりました。
  開けたときは「ブラウザで開きました」の 1 行だけを出します。
  開けなかったときは、鍵の無い URL と `hangar url` の案内を出します。
- 外したプロジェクトに付けていたアーティファクトの URL を、別のプロジェクトに足すと、付け替わります。
  今も使っている別のプロジェクトに付いているときは、そのプロジェクトの名前を出して断ります。
- ホームのセットアップの帯などで、英字の名前の後ろに助詞を詰めていた日本語の文に、空白を入れました。

### 起動まわり

- Node が見つからないときや、4177 のサーバの版が合わないときは、読み込み画面が理由と直し方を出します。
- アプリは、Homebrew、nvm、fnm、Volta、mise、asdf、nodenv の Node 22 を見つけます。
  Windows では、nvm-windows、fnm、Volta、scoop の Node 22 を見つけます。
  見つからないときは設定の「Node のパス」に、フルパスで指定します。
- アプリ、`hangar` コマンド、設定の確かめが、同じ条件で Node を選びます。
  同梱の版と合うもの（Node 22、同じアーキテクチャ）だけが使われます。
  アプリは、選んだ Node の置き場を、起こすセッションの PATH にも足します。
- 初めて起動する人は、OS の表示言語（日本語か英語）で始まります。
  すでに設定がある人の表示言語は変わりません。
  起動画面と、通知の代わりの文も、同じ言語で出ます。
- 2 つ目を起こしたときは、窓を増やさず、動いている窓を前へ出します（Windows）。

## 前提

- macOS 13 以降の Apple silicon、または Windows 11 の x64。
- Node 22、tmux（Windows は psmux）、Claude Code（`claude`）。アプリは Node を同梱していません。
