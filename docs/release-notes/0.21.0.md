# Hangar 0.21.0

GitHub の PR・CI・レビューや、ほかのサービスからの webhook をきっかけに、会話を起こしたり、会話に指示を送ったりできるようになりました。

## 更新の前に

イベントで会話を動かすには、Worker を更新してください。更新しなくても、同期・スマホ・別の PC への起動・別の PC の会話はこれまでどおり動きます。

1. 使う PC を 0.21.0 に上げます。
2. クラウドを作成した PC で、リポジトリを clone したディレクトリから `npm run hangar -- setup cloud` を実行します。データやリカバリーキーはそのままで、同じクラウドの Worker だけが更新されます。

- 0.21.0 を一度起動すると、データベースの形が変わり、前の版には戻せません。

## 足したこと

### PR の CI が終わったら、Paused の会話を起こせるようになりました

- 会話を Paused にするとき、「PR #12 の CI が失敗したら」のような条件を付けられます。エージェントが条件を提案していれば、その案が最初から出ます。
- 条件が一度満たされると会話が起き、条件は消えます。

### 予定の画面に「イベント」の節を足しました

- GitHub の CI の完了・失敗、レビュー、コメント、マージ、issue の作成で、会話に指示を送る・PR を出した会話に送る・新しい会話を作る、のどれかを選べます。
- webhook を受ける URL を作れば、ほかのサービスからの通知でも同じように動かせます。URL は再生成すると前のものが使えなくなります。
- GitHub の repo の webhook は、hangar が GitHub CLI（gh）で自動で登録します。repo の管理者の権限が要ります。

### エージェントが出したイベントの設定は、承認するまで動きません

- エージェントが作った設定の下書きと、エージェントが担当すると申し出た PR は、予定の画面の「承認待ち」に並びます。

### hangar を閉じている間に届いたイベントを、起動したときに動かすか選べます

- 「閉じている間に N 件のイベントが届きました」の札から、すべて実行するか、設定ごとに最新のみ・すべて・実行しないを選べます。
- 1 つの設定が 1 時間に 12 回を超えて動いたときは止めます。予定の画面の「再開」で戻せます。

## 安全のために

- 届いたイベントは Worker の中では暗号化したまま預かり、設定を作った PC だけが開けます。
- GitHub の webhook は署名を確かめ、合わないものは捨てます。
- 自分以外の人が書いたコメントや PR の本文は、許可した人のものだけエージェントに渡します。
