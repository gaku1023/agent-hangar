# Hangar 0.6.3

## 足したこと

### Claude Code に環境を整えてもらう「セットアップのすゝめ」

hangar を入れたあと、Claude Code に手引きを 1 枚渡すと、あなたの環境を診断して、hangar を使いやすい形に整える提案をします。
あちこちのフォルダで claude を起動していて会話が散らばっている人や、作業をデスクトップに置いている人に向けたものです。

- 設定 › 連携の末尾に「Claude Code に環境を見てもらう」の札を足しました。
  貼る一言をそのまま見せ、「コピー」で写せます。「手引きの中身を見る」で手引きをエディタで開けます。
- ホームの「セットアップの確認」の最後にも「仕上げ」の行を足しました（欄が出ている間だけ）。
- コピーした一言を Claude Code に貼ると、Claude は次の順で進めます。
  1. 読むだけで環境を診断する（消えそうな会話、会話した場所、連携の状態、クラウド同期のフォルダ）。
  2. いくつか質問する。
  3. 会話したフォルダを「登録する／聞きたい／しない」に分けた表を見せる。
  4. 承諾した分だけ、プロジェクトとして登録し、連携を入れる。
- フォルダの移動や削除はしません。CLAUDE.md にも触れません。
  フォルダを動かすと、Claude Code の会話を再開できなくなるからです。
- 手引きはアプリに同梱し、起動のたびに `~/.agent-hangar/setup-guide.md`（Windows は `%USERPROFILE%\.agent-hangar\setup-guide.md`）に写します。
  先頭に版と内容のハッシュを入れ、貼る一言にも同じものを入れます。
- 慣れてきたら読む「最初の 1 週間で試すこと」（`setup-guide-habits.md`）も一緒に置きます。

### ターミナルからプロジェクトを登録できます

セットアップのすゝめで Claude が使う道具として、次のコマンドを足しました。自分で打っても使えます。

```sh
hangar project candidates [--json]          # 会話したフォルダの候補（読むだけ）
hangar project add <パス…> [--dry-run]      # プロジェクトとして登録し、その下の会話を紐づける
hangar project remove <パス> [--dry-run]    # 登録を外す（会話は未分類に戻るだけで、本文は消えない）
hangar workspace set <フォルダ> [--dry-run]  # 新しいフォルダの作成場所を決める
hangar workspace unset [--dry-run]          # 作成場所を決めていない状態に戻す
```

- `--dry-run` は書かずに結果を見せます。
  登録と同じ処理を走らせてから巻き戻すので、見積もりと本番が食い違いません。
- 候補には、最近の会話の題、git のリポジトリかどうか、ほかの候補の下にあるか、iCloud や OneDrive で同期しているフォルダか、注記（デスクトップの直下、ダウンロードの直下、30 日より前、会話 1 件など）が付きます。
- 作成場所にホームフォルダとその上、ドライブの根を選ぶと断ります。
  直下が全部プロジェクトとして登録されてしまうためです。
- サーバが動いていないときは何もせず、`hangar start` を促します。

## 直したこと

### 長く動きの無い会話も自動で Done にします

- これまで自動の Done は、短い会話か、要約が完了・中止のものだけを拾っていました。
  hangar を入れる前に外のターミナルで動いた長い会話などは、ずっと Active のまま残っていました。
- 0.6.3 からは、止まってから決めた日数のあいだ動きの無い会話も Done にします。
- 日数は、設定 › 一般 › 「hangar が自分で行うこと」の「長く動きの無い会話も Done にする」で選べます（3・7・14・30 日・しない、既定は 7 日）。

### 初日のプロジェクトの候補に、作成場所そのものを出さなくしました

- 新しいフォルダの作成場所そのものが、初日の候補に出ていました。
  作成場所はプロジェクトにできないので、選んでも登録できませんでした。
