# クラウド同期の割り切りと実測

README の「[クラウド同期](../README.md#クラウド同期上級者向けのベータ)」の節に書ききれない、細かい割り切りと実測の記録です。
同期の仕組みは `docs/design.md` の「クラウド同期」にあります。

## 割り切りと限界

どれも実際に確かめたか、意図して残したものです。

1. **参加トークンは全セッションの読み書き権を持つ秘密です。** 1Password 経由で自分の 2 台目へ渡す前提で作ってあります。標準出力に出す以上、端末のスクロールバックとシェルの記録には残ります。自分の端末以外には渡さないでください。
2. **無料枠の上限に達すると、次の UTC の 0 時まで同期が止まります。**
   hangar は量を数えません。
   上限に達すると Cloudflare が断るので、その失敗を見分けて止め、日が変わると自動で再開します。
   無料プランは上限を超えても課金されず、要求が断られるだけです。
   止まっている間に「今すぐ同期」を押すと、1 回だけ試し直します。
   まだ断られれば、また次の UTC の 0 時まで退いて、トーストで知らせます。
   なお R2 自身の枠は月ごとの別勘定で、この使い方（1 セッションを 1 日走らせて上げ下ろしが 2,880 回ほど）では月の上限に対して桁が 2 つ小さく、先に当たるのは必ず D1 の書き込みの側です。
3. **他端末の run は止まりません。** ロックは見せるだけです。「この PC で再開」は本文を降ろして手元で新しい run を立てるので、同じセッションの本文が 2 か所で伸びること（枝分かれ）があります。索引は 1 つのファイルだけを採るので画面は二重になりませんが、本文そのものは分かれます。
4. **`~/.agent-hangar/backups/` は直近 20 回ぶんだけ残します。**
   控えを取るのは、設定の取り込み（`claude-config/`）、「この PC で再開」での本文の上書き（`transcripts/`）、セッションの名前の競合（`memos/`）の 3 つで、どれも新しい方から 20 世代を残して古いものを消します。
   `claude-config/` は取り込みのたびに刈り、`transcripts/` と `memos/` は控えを取った後と、サーバを起こしたときに刈ります。
   この置き場の外に残る控え（プロジェクトのメモの隣の `memo.md.bak-<日時>` と、設定の同期が残す `*.conflict-*`）は消しません。
5. **孤児は掃除しますが、解除した PC の本文は消しません。**
   本文の PUT は R2、D1 の順なので、途中で倒れて残るのは索引に無い R2 の本体だけです。
   Worker は `GET /files` を契機に、6 時間に 1 回だけ R2 を 50 件と索引を 50 行まで見て、索引に無い本体と、本体の無い索引の行を消します。
   置いてから 1 時間たっていないものには触らないので、書いている最中の 1 本は消えません。
   誰も本文を降ろさない日は `GET /files` が来ないので走りませんが、孤児が増えるのも上げ下ろしをした日だけです。
   掃除自身が D1 に書くのは、孤児が数件のときの実測で 1 回 7 行、1 日 4 回で 28 行です（枠の 0.03%）。
   PC を解除しても、その PC の `transcripts/<端末 ID>/` と `config/<端末 ID>/` は R2 と D1 に残します。
   ほかの PC が一覧と検索とこの PC で再開で使っており、解除は参加し直せば戻る操作だからです。
   明示的に消す操作は、まだありません。
6. **`CLAUDE_CONFIG_DIR` と `HANGAR_CLAUDE_DIR` は別物です。** 前者は起こされた `claude` が見る設定の置き場、後者は hangar が読む置き場です。普段はどちらも `~/.claude` ですが、試しの環境を分けるときは両方を向けてください（実物確認で見つかりました）。
7. **アカウントを足すと、2 つ目以降の置き場（`~/.claude-2` など）の中身は `~/.claude` へのリンクになります。** 設定・スキル・履歴は共有で、別になるのは認証（Keychain の項目と `.claude.json`）だけです。hangar はトークンを読みません。渡すのは `CLAUDE_CONFIG_DIR` だけで、ログインは `claude auth login` に任せます。リンクの場所に実ファイルがあると起動を断ります。中身を確かめて、要らなければ消してください。
8. **取り込んだ設定ファイルの更新時刻は、相手の端末で編集した時刻になります。** 手元で書いた時刻ではありません。どちらが新しいかの判定をホームをまたいで揃えるためです。
9. **確認は 1 台の Mac で 2 端末を模して行いました。**
   `HANGAR_HOME` と `HANGAR_CLAUDE_DIR` を分け、2 つのポートで起こしています。
   実際に別のマシンから接続することは、まだ確かめていません。
   孤児の掃除はこの確認より後に入れたもので、偽のクラウドとローカルの workerd（miniflare）の試験だけで確かめています。
   上限で退く処理も後に入れたもので、偽のクラウドと、手元の Worker の前に置いた中継でだけ確かめています。
   実物の Cloudflare では動かしていません。
10. **降ろすのを諦めた本文は画面に出ます。**
   ヘッダーに件数が出て、Settings のクラウド同期の節に鍵と理由と試した回数が並びます。
   同じ 2 か所に、まだ上げていない本文の件数も出ます。
   30 分ごとと、サーバを起こし直したときに自動で試し直すので、放っておけば回復します。
11. **`hangar cloud teardown` に合言葉を一度に流し込むと、2 つ目が読めません。** 安全側に倒れて中止します。手で打つか、1 つずつ送ってください。
12. **参加より前の本文はクラウドに上がりません。**
    上げ始める時刻は、`hangar setup cloud` と `hangar join` が `cloud.json` を書くのと同じ時点で `~/.agent-hangar/hangar.db` の `sync_state` に 1 度だけ刻みます。
    いま刻まれている時刻は `hangar cloud status` の「本文:」の行で確かめられます。
    上げたければ、そのセッションを再開するか `hangar cloud backfill` を実行してください。
13. **マイグレーションの版 8 が走ります。** `transcript_files` に `device_id` の列が増え、R2 との同期の台帳である `file_sync` が出来ます。索引の作り直しは起きません。
14. **1 台目の初回の設定は、途中で止まることがあります。**
    止まったら、原因を直してから `npm run hangar -- setup cloud` をもう一度打ってかまいません。
    作成済みの D1 と R2 は、そのまま使います。
    よく止まるのは次の 2 つです。
    - R2 が有効になっていない。
      Cloudflare のダッシュボードで R2 を有効にします（支払い方法の登録が要ります）。
    - `workers.dev` のサブドメインが未登録。
      ダッシュボードの Workers & Pages でサブドメインを決めます。
      Worker の URL に出るので、メールアドレスや本名とつながらない名前にしてください。
      あとで変えると、Worker の URL と参加トークンが変わります。
15. **Cloudflare のアカウントが複数あるときは、作る先を自分で選びます。**
    `--account-id <ID>` か環境変数 `CLOUDFLARE_ACCOUNT_ID` で指定します。
    他の人も入っているアカウントに作ると、平文で置くメタデータがその人たちにも読めます。
16. **clone の版は、アプリと同じ版のタグにしてください。**
    clone の CLI は `~/.agent-hangar/hangar.db` をマイグレーションしながら開きます。
    互換の版はクラウドと話せるかどうかだけを決めるもので、手元の DB は守りません。
    アプリより新しい版で打つと、アプリより先に DB が進んでしまうおそれがあります。
17. **`npm ci` のとき、npm 11 が install scripts の警告を出すことがあります。**
    `better-sqlite3`、`esbuild`、`node-pty`、`workerd` などについての警告で、無視してかまいません。
18. **設定が済んだら、アプリを終了して開き直してください。**
    サーバは `cloud.json` を起動時に 1 度だけ読むので、開き直すまで同期は始まりません。
    1 台目も同じです。
19. **スマホは参加の秘密を持たず、スマホ用の鍵と使い捨ての券で参加します。**
    スマホに渡るのは、参加の秘密から導いたスマホ用の鍵（受信箱と起動の依頼の暗号にだけ使い、R2 の本文の鍵とは別です）と、5 分で失効して 1 回しか使えない券だけです。
    スマホや QR が漏れても、PC として参加することも、R2 の本文を読むこともできません。
    ただし QR にはスマホ用の鍵が入っているので、画面に出している間は人に見せないでください。
20. **スマホからは、承諾なしで、選んだ権限モードの会話を、どの PC にも起こせます。**
    PC 側に上限や確認はありません。
    スマホを手にした人は、受信箱（待っている内容、会話の題、意図の文）を読め、全部の PC に権限モード込みで会話を起こせます。
    なくしたらすぐ、設定 › クラウド同期 の「参加している端末」から解除してください。
    解除すると、そのスマホのトークンは通らなくなります。
    解除しても、スマホ用の鍵はスマホに残ります。
    鍵を無効にするには、参加の秘密を作り直します（21）。
21. **参加の秘密を作り直すと、スマホは接続し直しです。**
    スマホ用の鍵は参加の秘密から導くので、`setup cloud --rotate-secret` で秘密を作り直すと、スマホの鍵では受信箱が開けなくなります。
    スマホは「接続し直してください」と出すので、新しい QR を読み直します。
22. **Worker が配るスマホの画面は、Cloudflare のアカウントを取られると差し替えられます。**
    受信箱の暗号は、鍵を持つスマホの画面の中で解きます。
    その画面は Worker が配るので、Cloudflare のアカウントを取った人は、配る画面を書き換えて、鍵と受信箱を盗めます。
    CSP（`default-src 'self'` ほか）は、画面が外へ送ることと、外のスクリプトを読むことを防ぎますが、配る側を取られた場合は守れません。
    アカウントを取られた時点で、D1 の平文のメタデータも読まれます。
    Cloudflare のアカウントには二段階認証を付けてください。
23. **スマホからの起動は、PC が pull したときに受け取ります。**
    PC の pull は 30 秒ごとなので、会話が始まるまで最大で 75 秒ほどかかり、それを過ぎた依頼は起こされません。
    受け取った後に PC の応答が失われたときは、起こさずに時間切れとして終わります（二度起こさないための側に倒しています）。
24. **スマホの画面に会話の中身は出ません。**
    会話を開いて続けるのは、Claude の Remote Control です。
    API キーのアカウントでは `--remote-control` を付けずに起こすので、起こせても Remote Control では開けません。
25. **スマホで確かめたのは、手元の偽のクラウドと miniflare までです。**
    実際の Cloudflare、実際の iPhone や Android、実際の Remote Control の通しでは、まだ動かしていません。

## 実測の記録

### 1 台目の作成と起動

実測では `setup cloud` は 16 秒で終わりました。
同期を入れた後も `hangar start` は 1.0 秒から 1.1 秒で、起動が遅くなることはありません（APAC のリージョンで測りました）。

### 設定の同期

実測では、片方の書き換えが相手に降りるまで 10 秒から 30 秒でした。

### やめるとき（`teardown`）

実測では 14 秒から 18 秒で終わりました。

### スマホの受信箱と起動

D1 の書き込みと読み取りの見積もりは `docs/design.md` の「スマホ（試験的）」の末尾にあります。
実測は、1 日使ってから、その表の「実測」の欄に埋めます。
いまは未実測です。
