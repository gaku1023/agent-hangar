# クラウド同期の作り直し（参加コードと E2E）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 参加用のシークレットと参加トークンを廃止し、参加は「参加コード＋発行した PC での承認」、暗号は「人に見せない世代鍵を PC の公開鍵に封じて配る」形に作り直す。D1 と R2 に行の中身、ファイルのパス、PC の名前、セッションの題を平文で置かない。

**Architecture:** 暗号の部品は `packages/shared/src/e2e/` に WebCrypto だけで書き、PC（Node）とスマホ（ブラウザ）で同じものを使う。PC のサーバでは、今の `CloudClient` の内側に封と開封の層（`SealedCloudClient`）を挟み、同期エンジンは今の `ChangeIn`／`ChangeOut` のまま動かす。Worker は封じた BLOB と、認証と順序に要る平文の列だけを持つ。名簿の変化は `rows` に印の行（`~roster`）を 1 つ置いて pull に相乗りさせ、pull の読み取りの行数を増やさない。

**Tech Stack:** WebCrypto（X25519、HKDF-SHA256、HMAC-SHA256、AES-256-GCM）、`CompressionStream('gzip')`、Hono（Worker）、D1、R2、miniflare（試験）、better-sqlite3、React 19、Tauri（殻）、vitest。

**Spec:** `docs/superpowers/specs/2026-10-17-cloud-e2e-design.md`（実装者は計画と一緒に必ず読む）

**進み：** Task 1〜2（PR 1、#292）、Task 3〜7（PR 2、#298）、Task 8〜12（PR 3）は済み。互換の版は 8 ではなく 9 にした（スマホ版 0.8.0-rc.2 が 8 を使ったため）。以下の本文の「版 8」は「版 9」と読み替える。

## 作り手に任された点の決定（この計画で決める）

設計書の「作り手に任せること」への答えと、実装の前提になる細部。

| 項目 | 決定 | 理由 |
|---|---|---|
| 参加コードの文字種 | `ABCDEFGHJKMNPQRSTVWXYZ23456789`（30 字。`0 O 1 I L U` を除く） | 読み違い、打ち違いを減らす。入力は大小を区別せず、`-` と空白を捨てる |
| 参加コードの長さ | 8 文字、表示は `XXXX-XXXX`（約 39 bit） | 5 分、1 回限り、確認コードの照合と承認が要るので、総当たりで価値があるのはこの 5 分だけ |
| 総当たりへの守り | 参加コードの口（認証なし）で、一致しないコードへの要求は Worker 全体で 10 分に 30 回まで（`meta` に窓と回数）。超えたら 429 | 30 回では 30^8 の空間に届かない。参加の妨害には使えるが、10 分で戻る |
| 参加コードの保存 | D1 には `SHA-256(正規化したコード)` だけ。承認か拒否か期限切れで `request` 列を null にし、1 日を過ぎた行は発行のついでに消す | `request` は参加コードから導いた鍵で封じるが、39 bit は D1 の写しから総当たりできるので、名前と OS を残さない |
| 参加リクエストの封 | `AES-256-GCM(HKDF(コード, salt="hangar-join-v1", info="hangar-join-req-v1"))`、AAD は `join:<code_hash>` | 発行した PC だけが開ける |
| 確認コード | `HKDF(コード, salt=新しい PC の公開鍵, info="hangar-join-sas-v1", 4 バイト)` を uint32 として 10^6 で割った余り、0 埋め 6 桁、表示は `123 456` | 設計書の式どおり |
| PC の鍵ペアの置き場 | 最初の版は `~/.agent-hangar/cloud.json`（0600）。Windows では `icacls` で他のユーザーに読めるかを見て、読めれば CLI と設定に警告を出す。OS のキーチェーンは使わない | 設計書の「最初の版は後者」 |
| `cloud.json` の形 | `{ v: 2, url, cloudId, deviceToken, keyPair: { pub, priv }, epochs: { "<n>": "<鍵>" }, currentEpoch, phoneKey: { epoch, key } \| null, rosterVersion, workerName, accountId, dbName, bucketName, joinedAt }`（鍵は base64url）。`joinSecret` は無い | 世代鍵を手元に持てば、pull ごとに keybox を読まない |
| 古い `cloud.json` | `joinSecret` を持つ形は `state: 'legacy'` と読み、同期は始めず、設定に「作り直しが必要」を出す。`hangar cloud teardown` だけは古い形でも動く（Task 26） | 作り直しの手順で、0.9.0 に上げた後でも旧い Worker を片付けられる |
| 問い合わせの間隔 | 新しい PC は 2 秒（1 回の参加で最大 150 回）。発行した PC はコードが生きている間だけ 3 秒（最大 100 回） | どちらも 1 回で 1〜2 行の読み取り。読み取りの予算の試験に入れる（Task 7） |
| 名簿の変化の伝え方 | 名簿と keybox を書き換えた PC が、`rows` に `k = "~roster"` の印の行を upsert する（`sealed` は空、`epoch` は今の世代）。pull でこれを見た PC だけが `GET /roster` と `GET /keyboxes` を読む | `GET /changes` の読み取りの行数を増やさない（設計書「Worker の表」の最後の行） |
| スマホ用の鍵を PC が持つ所 | 名簿の文書の中（`phoneKey: { epoch, key }`）。名簿は `/roster` の鍵で封じるので、スマホは読めない | 表を増やさない。PC は名簿を読めばスマホ用の鍵がわかる |
| 封の形（行） | `sealed = 0x02 \|\| iv(12) \|\| AES-256-GCM(/row の鍵, 平文)`。平文は `flag(1) \|\| 本文`、`flag` は 0x00 で生、0x01 で gzip（本文が 256 バイト以上のとき）。本文は `JSON {tableName, rowId, payload}`。AAD は `JSON.stringify(["row", k, deviceId, updatedAt, op, epoch])` の UTF-8 | 設計書の AAD の列を、区切りの曖昧さなく並べる |
| 封の形（ファイルのメタ） | `sealed_meta` は `/row` と同じ形で、本文は `{path, sha256, mtime, origin}`、AAD は `["file", key, deviceId, kind, epoch]` | |
| R2 の本文の鍵 | `HKDF(K[n], info="hangar-e2e-v2/file")`。本文の暗号は今の `encryptStream`／`decryptStream`（`packages/server/src/sync/crypto.ts`）を鍵だけ差し替えて使う | ストリームの暗号を作り直さない |
| R2 の鍵名 | 本文は `b/<device_id>/<base64url(HMAC(/index, "t:" origin ":" uuid [":" agent]))>`。**設定のファイルも** `b/<device_id>/<base64url(HMAC(/index, "c:" origin ":" rel))>` にする | 設計書は本文だけを書くが、今の `config/<id>/<rel>` は相対パスが平文で残る（失敗とみなすもの） |
| 鍵の表現 | X25519 の秘密鍵と公開鍵は raw の 32 バイト（秘密鍵は WebCrypto の `pkcs8` から取り出す／戻す関数を shared に置く）、世代鍵は 32 バイト、どれも base64url | Node とブラウザで同じ値を持つ |
| リカバリーキーの形 | 本文は `hangar リカバリーキー` の見出し、`作成日`、`URL`、`暗号鍵` の 4 行。暗号鍵は秘密鍵 32 バイトの base32（RFC 4648、詰め物なし、52 字）を 4 字ごとに `-` で区切った 64 字 | 末尾 4 文字の照合がしやすい |
| setup のリカバリーキー | `hangar setup cloud`（CLI）が端末に表示し、`--save <パス>` か対話の問いでファイルにも書け、末尾 4 文字を入力するまで終わらない。D2 の画面（コピー、ファイルへの保存、120 秒の進捗バー）は設定の「リカバリーキーを再発行」で使う | 今の setup は CLI だけで、設定の画面はコマンドを見せるだけ（`settings.cloud.off.runStart`）。setup を画面に移すのは範囲の外 |
| 再発行の順 | 新しい鍵ペアを作って表示し、末尾 4 文字の照合が済んでから名簿の公開鍵と keybox を差し替える | 保存し損ねた人が古いものまで失わない |
| 最初の端末トークン | setup が Worker の secret `BOOTSTRAP_TOKEN_HASH` に入れ、`POST /bootstrap` で 1 回だけ `devices` に登録できる。使ったハッシュを `meta.bootstrap_used` に残し、同じハッシュは 2 度通さない | `hangar recover` は `wrangler secret put` で別のハッシュを入れ直せば、もう 1 度通る |
| 承認待ちの欄の文 | 「参加コードを発行した PC で承認してください。」（設計書「試作との差」） | |
| 新しい PC の参加を動かす所 | 殻（Tauri）から CLI を短く呼ぶ。`hangar cloud join-check <url>`（接続先の確認）、`join-request`（鍵ペアを作り、リクエストを置き、確認コードを返す。下書きを `~/.agent-hangar/cloud-pending.json` に 0600 で置く）、`join-poll`（1 回だけ問い合わせ、承認なら `cloud.json` を書く）。画面が 2 秒ごとに `join-poll` を呼ぶ | 今の参加と同じく、殻は CLI を呼ぶだけ（`cloudmember.rs`）。1 回の呼び出しを短くして、殻の締め切りに掛からない |
| CLI だけで PC を追加する口 | 作らない。発行と承認は動いているアプリの設定から | YAGNI |
| スマホの解除の「元に戻す」 | 画面が 5 秒の通知を出し、その間は Worker に何も送らない。5 秒たったら解除する | 取り消しのための口を Worker に作らない |
| スマホから起こした印 | PC の手元の `mobile_launches` に `session_id`、`permission_mode` の列を足し（新しいマイグレーション）、セッションの DTO に `fromPhone: { bypass: boolean } \| null` を載せる。起こした PC でだけラベルが付く | `sessions` は共有の表なので、列を足すと同期の形が変わる |
| 互換の版 | Worker `COMPAT_VERSION = 8`、`MIN_DEVICE_COMPAT = 8`。PC の `MIN_WORKER_COMPAT = 8`。版 7 以下の Worker には PC は何も書かない | 設計書。作り直しなので混在はさせない |
| 作り直しの判定 | Worker が D1 を作ったときに `meta.cloud_id`（乱数）を置き、`GET /health` で返す。PC は `sync_state` の `cloudId` と比べ、違えば作り直しの 3 つの道を走らせる | URL の文字列だけでは、同じ名前で作り直した Worker を見分けられない |

## Global Constraints

- 失敗とみなすもの（設計書）：D1 と R2 に行の中身、ファイルのパス、PC の名前、セッションの題が平文で残る／参加コードが漏れたときに承認なしで参加できる、期限切れや使用済みのコードで参加できる／解除した PC が解除の後の行やファイルを復号できる／リカバリーキーを保存しないまま setup を終えられる／スマホの解除でほかのスマホの接続が切れる。
- 暗号は shared の `e2e/` に WebCrypto（`globalThis.crypto.subtle`）だけで書く。shared から `node:crypto` を import しない（スマホからも読む）。サーバのファイルのストリーム暗号だけは今の `node:crypto` の実装を使う。
- HKDF の info は `hangar-e2e-v2/row`、`/index`、`/fp`、`/file`、`/roster`、keybox は `hangar-keybox-v1`、確認コードは `hangar-join-sas-v1`。値を変えない。
- 参加コードは 5 分（`JOIN_CODE_TTL_MS = 5 * 60_000`）、1 回限り。発行は 1 台の PC につき 10 分に 5 回まで（`JOIN_CODE_RATE = { max: 5, windowMs: 10 * 60_000 }`）。
- スマホのトークンは 30 日使わないと失効（`PHONE_IDLE_MS = 30 * 86_400_000`）、接続から 90 日で再接続（`PHONE_MAX_AGE_MS = 90 * 86_400_000`）。判定は Worker の時計だけで行う。
- IP と所在地は保存も表示もしない（`devices` の `last_ip`、`last_city`、`last_region`、`last_country` を作らない）。
- D1 の文は 1 文 1 行で書く（`ensureSchema` の exec が改行で区切る）。
- 動きはアプリの決まった動きだけ（`packages/ui/src/views/primitives/motionKit.ts` の `growIn`、`collapseOut`、`resizeFrom`、`fadeIn` と `usePresence`、長さと曲線はトークン）。新しい動きを作らない。
- 配色は明るい配色だけ。暗い配色を持たない。
- 画面の語は用語集（`docs/superpowers/specs/2026-10-09-glossary.md`）に従う。新しい語は「参加コード、確認コード、参加リクエスト、リカバリーキー、通知、ラベル」。文言は `packages/shared/src/i18n/ja/*.ts` と `en/*.ts` の両方に置く。
- 公開リポジトリ。試験、文書、コミットに実際の会話の題、使用量の実数、私的なパス、メールアドレスを書かない。試験の PC の名前は `pc-a`、`pc-b` のような作り物にする。
- 開発の流れ（リポジトリの CLAUDE.local.md があればそれに従う）：
  - PR ごとに worktree を切り、`npm ci`。
  - 試験を先に書き、落ちるのを見てから実装する。
  - `npm run typecheck` と `npm test`（全部）を通す。
  - 画面が変わったら、動いているアプリの実データに worktree の `packages/ui/dist` を重ねて撮り、自分の目で見る。確認を利用者に返さない。
  - 返す前に build を 3 本（`npm run build`、`npm run bundle-server -w apps/desktop`、tauri build）通す。
  - PR は統合の枝 `e2e-rebuild` に向けて出し（`gh pr create --base e2e-rebuild`）、CI（check、desktop、node24、windows、windows-test）が緑ならマージする。アプリの入れ替えは、統合の枝を main に入れた後に 1 回だけ行う。
  - 仕組みが変わったら `docs/design.md` の該当の節も同じ PR で直す（全体の書き直しは Task 27）。
- **実物のクラウドに触る段（Worker の配備、作り直しの本番、実物での確かめ）は、その都度、使う無料枠の見積もりを添えて利用者に聞く。** 聞かずに実物を叩かない。やらなかったものは報告に「実物では未確認」と書く。
- 待ちの長い作業（CI、ビルド）はメイン側で待つ。サブエージェントは起動したものと確認の場所を報告して終わる。

## Review Focus

1. **2 台が同時に名簿を書き換える。** 承認と解除、または 2 つの承認が同時に起きても、どちらの変更も失わない（版の番号つきの条件付き更新が 409 を返し、読み直してから当て直す）。→ Task 5（Worker の 409）と Task 11（読み直して当て直す、3 回まで）に試験を置く。
2. **世代鍵の欠けた行。** 世代を回している途中に参加した PC や、keybox の取得に失敗した PC が、知らない `epoch` の行を受け取る。画面全体や同期を止めず、その行を飛ばして keybox を読み直し、読めたら当て直す。→ Task 9 に試験を置く。
3. **回しかけの世代。** PC の解除で、端末トークンの無効化までは済み、新しい世代の keybox を配り切る前にアプリが落ちる。次の起動で続きから終わらせ、新しい世代で封じた行を誰も読めない状態を残さない。→ Task 19 に試験を置く（`sync_state` の `rotation` の記録から再開）。
4. **承認の前に発行した PC が落ちる。** 参加コードの平文はメモリにしか無いので、再起動の後は承認できない。新しい PC は「応答なし」と次の手順を出し、5 分で終わる（固まらない）。→ Task 14 と Task 16 に試験を置く。
5. **コードの打ち間違いと形の揺れ。** 小文字、`-` 無し、前後の空白、全角の英数字は通し、字種の外の文字（`0 O 1 I L U`）は Worker に送る前に「参加コードの形が違います」と出す（総当たりの回数を消費しない）。→ Task 1 と Task 16 に試験を置く。

## 画面のメモ

試作はリポジトリの外にある。利用者が 2026-10-17 に選んだ案と、その説明。試作どおりに作り、外れるときは作る前に利用者に聞く。動きはすべて `motionKit` の決まった動き（新しい動きは作らない）。

画面の文は、その時点の用語集と `glossary.test.ts` の `FORBIDDEN_JA` に従う。試作の「〜から参加リクエストが届きました」は「参加リクエストを受信しました」の形にする（「届く」は 0.8.0 の文言の見直しで禁止語になった）。クラウドの URL は「接続先」と呼ぶ（文言の見直しのセッションで決まっていれば、それに合わせる）。

- **A1（参加済みの PC：PC を追加）**：設定 › クラウド同期 の PC の一覧の近くに「PC を追加」。押すとセクションの中に欄が開き（`growIn`）、参加コード（`XXXX-XXXX`、大きく等幅、コピーのボタン）、Worker の URL、残り時間（5 分）を出す。参加リクエストが届くと、同じ欄が承認の欄に切り替わる（`resizeFrom`＋`fadeIn`）：新しい PC の名前と OS、確認コード（6 桁）、「新しい PC に表示されている確認コードと同じなら承認してください」、「承認」「拒否」。承認で欄が閉じ（`collapseOut`）、PC の一覧に新しい行が増える（`growIn`）。
- **B2（新しい PC）**：設定 › クラウド同期 の未参加の段で、URL の欄と「次へ」。押すと接続先の確認（ホスト名と参加済みの PC の台数）を出し、参加コードの欄が開く（`growIn`）。「参加をリクエスト」で待ちの段に（`resizeFrom`）：確認コードと「参加コードを発行した PC で承認してください。」。承認で完了の段（`resizeFrom`）。期限切れ、拒否、応答なし（参加済みの PC がスリープ中など）は、その旨と次の手順（新しい参加コードを発行してもらう）。
- **C1（承認の通知）**：発行した PC の右下の通知と OS の通知。「〈名前〉から参加リクエスト」と確認コード、「確認して承認」で設定の A1 へ。出入りは今の通知と同じ。
- **D2（リカバリーキー）**：見出し「hangar リカバリーキー」、作成日、URL、暗号鍵（区切りつきの base32）。「コピー」「ファイルに保存」、120 秒で暗号鍵を伏せる進捗バー。「保存しました」で入力のステップ（`growIn`）に進み、暗号鍵を伏せ字にして、末尾 4 文字の入力。合うまで「完了」は押せない。
- **E2（PC の一覧）**：小見出し「PC」と「スマホ」で分ける。PC の行は名前、OS、参加日、最後の同期、「解除」（確認つき）。スマホの行は名前、残りの日数と再接続の日付、「解除」（1 クリック、右下に「元に戻す」）。IP と所在地の行は無い。解除した行は `collapseOut`。
- **F1（スマホから起動したセッション）**：右下の通知「iPhone から起動：〈プロジェクト〉（〈権限モード〉）」、Bypass permissions は赤い通知と「停止」。セッション一覧の行とセッションの見出しに文字のラベル「スマホから」、Bypass permissions は「スマホから · Bypass permissions」を赤い枠。一覧の新しい行は `growIn`。

試作との差（設計書の「試作との差」。この 3 つは試作ではなく設計書に従う）：

1. B の承認待ちの文は、試作の「参加済みの PC（〈名前〉、〈名前〉）に通知を送信しました。いずれかの PC で承認してください。」ではなく、**「参加コードを発行した PC で承認してください。」**。承認できるのは発行した PC だけで、承認の前は名前を復号できないため。
2. B2 の接続先の確認は、参加済みの PC の名前ではなく、**ホスト名と参加済みの PC の台数**を出す。名前は封じた名簿にあり、承認の前は復号できないため。
3. D の「リカバリーキーを表示」は**「リカバリーキーを再発行」**にする。PC はリカバリーキーの秘密鍵を持たないため。
