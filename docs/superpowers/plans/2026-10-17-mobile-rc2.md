# スマホ版 0.8.0-rc.2 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** rc.1 のスマホ版に、入口の案内（A1）、プロジェクトの選び方（B1）、詳しい設定と effort（C3）、始めた後のシート（D2）、アカウントの札（E1）、指示の欄の `/` `@` 画像、と、それを支える Worker の呼び鈴（Durable Object）と画像の置き場を足す。

**Architecture:** Worker に Durable Object `HangarBell`（1 実体）を足し、PC が WebSocket（Hibernation）でつなぎっぱなしにする。スマホの `@` と `/` の問い合わせは `POST /m/ask` から Durable Object を通して PC へ中継し、D1 に書かない。起動の依頼を入れたら宛先の PC を鳴らし、PC は `pullNow()` で今の道から受け取る。画像はスマホが封をして R2 の `mobile/<スマホ>/<依頼>/<番号>` に置き、PC が取って drops に置き、パスを最初の指示に足す。

**Tech Stack:** Hono、D1、R2、Durable Objects（SQLite 型、Hibernation WebSocket）、miniflare（試験）、Web Crypto、`ws`（PC）、React 19＋Vite（スマホ）、vitest 5。

**Spec:** `docs/superpowers/specs/2026-10-17-mobile-rc2-design.md`（必ず先に読む）。rc.1 の設計は `docs/superpowers/specs/2026-10-17-mobile-pwa-design.md`、rc.1 の仕組みは `docs/design.md` の「### スマホ（試験的）」。

## 作り手に任された点の決定

| 項目 | 決定 | 理由 |
|---|---|---|
| 呼び鈴の実体 | `env.BELL.idFromName('bell')` の 1 つ | PC は数台。1 つなら宛先探しがメモリで済む |
| PC の認証 | Worker の `/m/bell` で `authMiddleware()` と `requireKind('pc')` を通し、`x-hangar-device: <端末 ID>` を付けて Durable Object へ `fetch` を渡す。Durable Object はこの見出しを Worker からしか受けない（外から Durable Object へ直に届く道は無い） | 認証を 1 か所に |
| 同じ PC の重複 | 新しい WebSocket を受けたら、同じ端末 ID の古いものを `close(4000, 'replaced')` | 寝起きのつなぎ直しで二重に答えない |
| 待ちの持ち方 | `Map<askId, {resolve, timer}>`。答えが来ない 5 秒で 504 | 問い合わせの間は fetch が開いているので Durable Object は眠らない |
| PC の WebSocket | `ws` で `headers: { authorization, ...compatHeaders() }`。ping 30 秒、pong 75 秒来なければ張り直し、張り直しは 1→2→4…60 秒 | |
| 呼び鈴の版 | `COMPAT_VERSION = 8`、`MOBILE_BELL_MIN_WORKER_COMPAT = 8`。`MIN_DEVICE_COMPAT` は 6 のまま | 古い PC を締め出さない |
| 問い合わせの上限 | 本文 4 KiB、答え 64 KiB、スマホ 1 台 10 秒に 20 回（Durable Object のメモリ） | |
| 画像の上限 | 1 枚 5 MiB（封の 28 バイトを足して受ける）、1 依頼 4 枚、1 台のスマホの置いたまま 40 枚 | 試作の文言 |
| 画像の掃除 | PC の答え（started/failed）で Worker がその依頼の画像を消す。スマホが画像を置くときと依頼を出すときに、そのスマホの `mobile/<id>/` の下の 24 時間より古いものを消す | cron を足さない |
| 起動の状態の読み直し | 3 秒 → 2 秒 | 鳴らすので数秒で答えが来る |
| `/` の候補 | 受信箱の素に載せず、`@` と同じ問い合わせ（`kind: 'commands'`） | プロジェクトのスキルまで載せると素が膨らむ |

## Global Constraints

- 設計書の「失敗とみなすもの」を全部守る。特に、問い合わせ、候補、画像は平文で Worker、Durable Object、D1、R2 を通さない（全部スマホの鍵で封をする）。
- 配色は明るい配色だけ。動きは `packages/mobile/src/presence.ts` と `styles.css` の決まった動きとトークン（reduced-motion で 0）。
- `innerHTML`、`dangerouslySetInnerHTML` を使わない（`noInnerHtml.test.ts`）。
- 文言は用語集どおり（「接続」「解除」）。地の文の日本語は一文ごとに改行し、ダッシュと中黒を使わない。
- 公開リポジトリ。試験や文書に実際のプロジェクト名、ファイル名、会話の題、使用量を書かない。
- D1 の文は 1 文 1 行。
- 試験を先に書き、落ちるのを見てから実装する。
- **同じ worktree で 3 本の担当が並列に動く。** コミットは自分のパッケージのパスだけを `git add <パス>` してから行う（`git add -A` と `git commit -a` を使わない）。`index.lock` で断られたら数秒おいてやり直す。ほかの担当の途中の変更で typecheck が落ちたら、自分のパッケージの試験と typecheck（`npx tsc -p packages/<名前>`）で確かめ、報告に書く。

## Review Focus

1. 呼び鈴に、スマホのトークン、解除した PC、宛先でない PC がつなげない、答えられないこと（Task 2）。
2. 呼び鈴が無い Worker、つながっていない PC で、起動が今までどおり 30 秒の pull で動くこと（Task 2、Task 5）。
3. 画像を宛先でない PC が読めないこと、スマホが `mobile/<自分>/` の外に書けないこと、残り続けないこと（Task 3）。
4. 問い合わせの答えがプロジェクトの外のパスを含まないこと、上限で切ること（Task 5）。
5. effort と images の検証が値表と上限で行われること、画像のパスの足し方が PC の指示欄と同じこと（Task 6）。
