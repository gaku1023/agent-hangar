# 作り替えの全体計画

2026-10-07 に利用者と決めた、hangar 全体の作り替えの計画である。
段ごとに別の spec と計画を書く。
この文書が持つのは、段の分け方、順番、段をまたぐ決定、段階的に入れるときの約束だけである。
段の中の決定は各段の spec に書き、この文書には戻さない。

決めるまでに、Fable の 5 体にサーバ、UI、同期と殻と CLI、用語、画面の構成を調べさせ、計画の案にもう 1 体で反論させた。
この文書の数字（行数、か所の数）は、その調査で 2026-10-07 の main（`2da9655`）を数えたものである。

## 作り替える理由

3 週間で約 970 コミットを重ね、機能を足すたびに次の 6 つが重くなった。

- **機能を足す重さ**：状態を 1 つ足して保存するだけの機能で、ソース 6〜7、試験 4、設計書 1 のファイルに触る（右ペインの分割比の記憶、サイドバーの並べ替えの実コミットで確かめた）。
- **同期と配布の複雑さ**：端末側の無料枠の見張り、Claude Code の設定の同期、Node の探索と ABI の照合、wrangler に頼る setup。
- **動作の不具合と重さ**：同じ事実を 2 か所に持つ状態、登録が変わるたびに全プロジェクトを読み直して配る処理など。
- **Windows 移植の下地**：Node の探索、sh の包み、macOS に固有の処理が、殻とサーバと CLI に散っている。
- **用語**：Claude Code の公式の用語集（<https://code.claude.com/docs/ja/glossary>）と食い違う語や、公式の別の意味と衝突する語がある。
- **画面の構成**：配置の根拠が書かれていない所、同じ事実の重複表示、画面どうしの役割の重なりがある。

### 段 0 Claude Code との互換の約束

hangar は、Claude Code が公開を約束していない形式に頼っている。
`~/.claude/sessions/<pid>.json` のレジストリ、jsonl の行の形、statusline に渡る JSON、アカウントの切り替えのための `~/.claude` の中の配置、シェルの包みが知っている claude の引数がそれにあたる。
公開すると利用者ごとに claude の版が違うので、版が変わって形式が変わったときに、hangar 全体ではなくその機能だけが止まるようにする。

- 版ごとの jsonl とレジストリの見本を試験に置く。
- 対応する claude の版の幅を決めて README に書く。
- 読めない形式に出会ったら、その機能を止めて理由を出す。
- design.md の陳腐化した記述（マイグレーションの版の数など）をここで直す。

終わりの条件：見本の試験が CI で回り、読めない形式で落ちずに機能を止めることを試験で確かめている。

### 段 1 引き算

決めごとに依らずに消せるものを消す。

- 引き継ぎ（takeover）一式：表を共有テーブルの一覧から外し、型、Intent、ServerEvent を消す。
- 端末側の無料枠の見張りと Worker の台帳（D4）：見積もりの計算、台数割り、`d1RowsToday` の往復。代わりに、上限による失敗で退く処理を入れる。
- 形だけの Provider 抽象（D7）：インターフェースだけを消す。`sessions.provider` の列と一意の制約、API の `provider` の絞り込みは D8 により残す。
- 使われていない Intent、ServerEvent、ApiClient のメソッド、CSS のクラス。
- 互換の版番号（D10）を入れ、古い版のための分岐を消す。
- cli.mjs がサーバ全体を二重に同梱しているのをやめる。`cloud/` の同梱は、源の写しをやめ、Worker を 1 本にビルドしたものに替える（段 5 で REST から上げるため）。

Claude Code の設定の同期は、この段では消さずに今の形のまま残す（D6）。
引き算で消す部品（Worker の DELETE、無料枠の見張りなど）と同じ所を通る箇所では、設定の同期の経路を壊さない。

終わりの条件：上の項目が消え、`npm test` と 3 つのビルドが通り、入れ替えたアプリで同期が 1 日動いている。

### 段 2 サーバの骨格

- 「DB に書く、読み直す、配る」の写し（セッションで 16 か所、プロジェクトで 13 か所）を、変わったものを受け取って配る 1 つの層にする。`deviceId` の渡し忘れでロックが消える罠も、この層で無くす。
- `createApp` の約 80 のルートをリソースごとのファイルに分ける。依存の任意項目は、試験の組み立ての道具を先に作ってから無くす。
- RunManager から、アカウントの解決とペインの操作を外す。run の寿命（起動、見張り、終了、復帰、停止）は割らない。
- shared を契約（DTO、API、イベント）だけにし、UI だけが使うモジュールを UI へ移す。
- マイグレーション 15 本を、v15 と同じスキーマの 1 本の起点に畳む。新しい DB と、v1 から v15 を順に当てた DB の `sqlite_master` を試験で突き合わせる。
- 全体を起動する試験を数本の端到端に絞り、配線を関数に出して単体で押さえる。

段 2 の spec で利用者に決めてもらう点：名前とメモの置き場。
索引は本文が伸びるたびに `sessions` の行全体を書き直すので、同期で別の PC の名前やメモを上書きしうる。
状態は同じ理由ですでに別の表（`session_states`）に分けてあり、残るのは名前とメモだけである。

終わりの条件：配る処理が 1 つの層だけにあり、`server.ts` と `http/app.ts` が配線と経路の登録だけになっている。

### 段 3 UI の骨格

- Mediator が Store を読めるようにし（`transition(state, store, input)`）、Store から分かる事実をイベントにして往復させる経路（6 種）を 1 つずつ無くす。同じ事実を State と Store の 2 か所に持つのもやめる。
- 状態を変えずに API を 1 回呼ぶだけの Intent について、Effect を挟む形を見直す。
- 保存しない一時の状態（スクロールの追従、本文の検索、ターンの開閉）を View に下ろすかを決める。
- 文言の辞書の仕組みを入れ、日英を切り替えられるようにする。中身を埋めるのは段 4 である。
- CSS の試験は禁則（太さ、ガラスの置き場、トークンの直書き）の 3 つだけを残す。
- design.md から Intent と State の一覧を落とし、型を正にする。設計書は意図と決定の記録に絞る。

終わりの条件：往復のイベントが無くなり、新しい文言を辞書の鍵で書ける。

### 段 4 画面と言葉

画面を 1 枚ずつ、試作を並べて利用者が選び、選んだら次の PR で実装する。
その画面に出る言葉（日英）も試作で一緒に決める。
複数の画面にまたがる語は、最初の画面より前に用語集として 1 度だけ決める。
色、書体、質感の磨きは 2026-10-02 のデザイン調査で済んでいるので、対象は情報の構成と配置と言葉である。

画面の構成で利用者に決めてもらう点は次のとおりである。

- Sessions は検索の画面か、全件を読む画面か。開くと Active の行が畳まれずに全部並ぶ。
- 「実行中」をサイドバー、Home の札、パレット、各一覧、セッション画面などの 7 か所で見せ、言い方が 4 通りある。どこに残すか。サイドバーと Home の札では並びが違う。
- Projects の画面を残すか。Active のプロジェクトは Home の錠剤と重なり、残る役目は Done と Archived の整理と新規作成である。
- 終わったセッションにもターンの目次を出すか。いまは実行中にしか出ない。
- セッション画面の情報の行（11 項目）を、いまの値（状態、コンテキスト、コスト）と属性（モデル、開始、作業ディレクトリ、PR）に分けるか。
- ヘッダーの同期の操作（今すぐ同期、一時停止）を常に出すか、設定だけに置くか。
- 設定のうち読み物（使用量の表、索引、この PC）を設定から出すか。
- 画面の分け方そのものを変えるか。調査は 3 つの対極の案を出した（Sessions を Home に吸収する、Projects を絞り込みにする、セッション画面を主役にした作業台にする）。

用語集で利用者に決めてもらう点は次のとおりである。
出発点は 2026-10-01 の用語表の案（`docs/superpowers/specs/2026-10-01-ux-refresh/terminology.md`）で、その「やわらかい和語寄り」という語調の決まりは D5 に合わせて見直す。

- 画面の「本文」を公式の「トランスクリプト」にするか。
- 「指揮役」「主線」を公式の「メイン会話」（main conversation）にするか。
- 権限モードの和語のラベル（都度たずねる、計画だけなど）を、公式の語（Manual、Plan など）にするか。公式の日本語訳は同じ頁の中でも揺れている。
- 「メモ」を、公式の memory と紛れない語にするか。
- 「実行中」「動いている」「作業中」の使い分け。公式の agent view の状態（Working、Needs input、Idle）に合わせるか。
- 公式の語と衝突する語の扱い。5 時間の枠は公式では session limit と呼ぶので「セッション」と書かない。workspace と scratchpad も公式では別の意味である。
- UI の内部の型 `Intent` と、ターンの「意図」（`set_turn_intent`）が同じ語で衝突している。前者はコードの中だけの名前なので、D8 の範囲で改名できる。

試作は、これまでと同じく `docs/superpowers/specs/<日付>-<画面>/` に HTML で置く。
決まった用語集は design.md の「画面の用語」の節を置き換え、辞書の鍵の元にする。

この段では、Claude Code の設定の同期も狭く作り直す（D6）。
サーバの側は、段 2 の骨格（変わったものを受け取って配る 1 つの層と、畳んだマイグレーション）の上に作る。
画面の側（入れるときに見せる一覧と、ぶつかったときの写しの見せ方）は、設定の画面の試作と一緒に決める。
細部は別の spec で詰め、ここには骨子だけを置く。
今の設定の同期の形式（R2 の `config/` の置き方、同期の記録、設定の `syncClaudeConfig`）とデータとの互換は持たない。
いまの利用者は本人だけなので、作り直すときに壊して入れ替えてよい。

- **運ぶもの**：`CLAUDE.md`、skills と commands と agents、`keybindings.json`、`settings.json` のうち持ち運べる鍵（許可リスト、モデル、言語など）、プロジェクトごとのメモ（`project_roots` で相手の PC の slug に写す）。認証（`.credentials.json`、`~/.claude.json`）、`settings.json` の `env` と `apiKeyHelper` と `hooks` と `statusLine`、plugins の cache、sessions、history は運ばない。
- **書き方**：`settings.json` は鍵ごとに併合し、ファイルごとには上書きしない。消したものは、相手の PC では消さずに控えへ移す。ぶつかったら新しい方を採り、古い方を写しとして残して画面に出す。
- **始め方**：既定は切。入れるときは、1 台目では上げるものの一覧を、2 台目では書き換えるものの一覧を見せ、控えを取ってから書く。運ぶ対象と `settings.json` の鍵の許可リストは、段 0 の互換の見張りに載せる。

作り直した形は、D9 が殻の命令とネイティブの確認に寄せるファイル（`~/.claude.json` と statusline）も、実行につながる鍵も運ばない。
入れる操作（一覧を見せて承諾を取る）を HTTP API に載せるか、殻の確認ダイアログで行うかは、作り直しの spec で D9 に照らして決める。
作り直すまでは今の設定の同期が残り、`settings.json` の全体と statusline のスクリプトも運んで書く。

終わりの条件：全画面が新しい構成で、画面とサーバの文と注入の文が日英の辞書から出ている。
設定の同期が、上の骨子の形に作り直されている。

### 段 5 配布

- Node を同梱し、探索、`manifest.json` の照合、設定の `nodePath` を無くす。.app は約 8MB から約 100MB に増える。
- 配布する .app は、Apple の開発者の証明書で署名せず、公証も通さない（2026-10-09 の利用者の決定。Apple Developer Program に登録しない）。dmg（または Homebrew cask）で配る。他の人の Mac では開くときに警告で止められるので、README に開き方を書く。Apple Silicon で動かすのに要るその場の署名（ad-hoc）だけは、同梱する Node、`.node`、`spawn-helper` を含めて付ける。自動更新（次の項目）が開発者の署名なしでどこまで動くかは、段 5 の spec で確かめる。
- 自動更新を入れる（Tauri の updater、更新の署名鍵、更新の目録の置き場）。
- セットアップ（参加、MCP、statusline、シェルの包み）をアプリから行う（D9）。初回の体験の受け入れ基準を決める（`hangar setup` を打たずに .app だけで始められるか）。
- claude、tmux、エディタの実行パスを API から変えられる件を見直す。Node を同梱して `nodePath` を消しても、これらは任意の実行ファイルを指せる。
- クラウドの準備を、wrangler ではなく、利用者が貼った API トークンと Cloudflare の REST API で行う。要るトークンの権限（Workers のスクリプト、D1、R2 の編集）を画面に出す。
- 殻とサーバの合図を、HTTP のポーリングから子プロセスの標準出力に変える。4177 にすでにいるサーバを採るための HTTP の確認は残る。
- `hangar` コマンドは、url、open、status だけの薄いものにする。
- 公開物をそろえる：英語の README、SECURITY.md、プライバシーの説明（要約のために本文を `claude -p` へ渡すこと、テレメトリを送らないこと）、CHANGELOG、版番号の統一（いまはアプリとサーバで別の版）。

終わりの条件：他の Mac で、dmg から入れて .app を開くだけで、クラウドなしで使い始められる。

### 段 6 Windows

## 段階的に入れるときの約束

- 各 PR は、それ単独でアプリが動く状態で入れる。
- サーバは、マイグレーションを当てる前に DB を `~/.agent-hangar/backups/db/` へ自動で控える（`VACUUM INTO`）。いまは DB の自動の控えが無い。
- スキーマか同期に触る PR は、DB の写しを置いた別の `HANGAR_HOME` で 1 日使ってから入れる。手元の開発用サーバとアプリは同じ DB を使うので、古い版が先に起きて同期の区切りを壊した前例がある。
- 戻すときは、前の .app に戻し、必要なら控えた DB を戻す。そのために、入れ替えの手順で前の .app を退避する。
- 互換の版番号（D10）を段 1 で入れるので、それ以降は 2 台の端末の版がずれても、断られた側が理由を出して止まる。
