# 設定の同期を「基本は同期される」ものに直す（2026-11-13 の決定）

きっかけ：Mac で作った skill が、別の PC で使えなかった。
束は届いていたが、適用は画面からの指示（`PUT /config-sync/apply-order`）でしか起きず、`configApproval='auto'` でも承諾の札が外れるだけだった。
その PC は 2 週間、一度も適用されていなかった。

grilling で決めたことを下に並べる。文言は試作のあと、いつもの流れで校閲する。

| # | 問い | 決めた答え |
|---|---|---|
| 1 | 「自動」の意味 | 束が届いたら、サーバが確認なしで書く。書く前に backups へ控えを取る。アプリが閉じている間に届いた束は、次の起動で書く |
| 2 | 種類の粒度 | 今の 20 種類（`ConfigItemKind`）をそのまま並べ、会話の本文を足す |
| 3 | 行の状態 | 切・確認・自動の 3 つ。全体の `configApproval` はやめる。会話の本文は切と自動の 2 つ |
| 4 | 既定 | 自動で走るコード（hooks、statusline、plugins、Claude・Codex・opencode の MCP）は確認。ほかは自動。会話の本文は自動 |
| 5 | 効く範囲 | 選んだ内容は全部の PC で共通。どの PC で変えても全部に効く。緩める変更にも守りを置かない |
| 6 | 自動にするときの注意 | 実行される種類を自動にするときだけ、その場で 1 文示す（2026-10-09 の決めたこと 2 を引き継ぐ） |
| 7 | 競合 | 手元を残し、その項目だけ確認に回す |
| 8 | 削除 | 控えを取って自動で消す |
| 9 | 初回 | 片方にしか無いものは自動で書き足す・送る。中身の違うものは一覧にし、まとめても 1 件ずつでも選べる |
| 10 | シンボリックリンク | 送らない。種類の行に、外した件数を出す |
| 11 | 移行 | `configBundleSync` を切っていた人は切のまま。入れていた人は、今の `configApproval` を行の状態へ読み替える |
| 12 | 知らせ | 確認・競合・失敗は ask の場面（未読、OS、スマホは利用者の決まりどおり）。自動で入ったものは札と履歴に静かに残す |
| 13 | 戻し | 履歴から、1 回の適用ごとにも、1 項目ごとにも戻せる |

## 2026-10-09 の設計から変わる点

- 決めたこと 2（実行される種類は既定で項目ごとに承諾）は、実行される種類を「自動で走るコード」に絞った。skills、commands、agents は既定で自動になる。
- 決めたこと 3（適用の経路は殻の命令とネイティブの確認、および CLI。HTTP API には載せない）は、自動の適用だけサーバの中から起こす。HTTP の口は増やさない。

## 試作

`options.html`。一覧の並べ方 3 案（A エージェントごと、B 状態の列、C 性質ごと）と、件数の札の置き場 2 案（P1 ヘッダ、P2 サイドバー）を切り替えて見る。

## 試作で選んだもの（2026-11-13）

- 一覧は **C 性質ごと**。指示・スキルとコマンド・記憶・設定・自動で走るコードで束ね、束の見出しにも切り替えを置く。
- 件数の札は **P1 ヘッダ**。同期の表示の横に、確認の件数と自動で入った件数を出す。
