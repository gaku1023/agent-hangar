上限で止まったときと「数は不明」 試作

段 1 の PR 5（docs/superpowers/plans/2026-10-08-stage1-pr5-quota-backoff.md の Task 1）の試作です。hangar は無料枠を数えるのをやめ、Cloudflare の上限で断られたら次の UTC の 0 時（この PC の 9:00）まで同期を止め、日が変われば自分で再開します。
目に見えて変わるのは、ヘッダーの同期の一行のボタン、設定の「状態」の語、設定の「使用量と費用」です。ヘッダーの文「無料枠で停止 · 9:00 に戻る」は spec のとおり変えません。数はすべて作り物です。

推す組み合わせ：Q1 から Q5 まで、すべて案 A

Q2帯とトーストで、上限に届いたことと、9:00 に自分で再開することを言う推す 案 A
Q3止まりそうなときは「Cloudflare が書き込みを断ります」と言う推す 案 A

Q5設定の「状態」もヘッダーと同じ「無料枠で停止 · 9:00 に戻る」推す 案 A

いまの「今すぐ同期」には、一時停止中だけ「一時停止のまま、1 回だけ同期する」の説明が付きます。案では利用者の一時停止ではないので付きません。

ヘッダーは「無料枠で停止 · 9:00 に戻る」と言うので、設定の「状態」もそろえるかの問いです。

案 A「無料枠で停止 · 9:00 に戻る」推すヘッダーと同じ語。
