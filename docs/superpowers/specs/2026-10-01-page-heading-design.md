# 位置の表示を本文の見出しへ移す（設計）

## この文書の位置づけ

この文書は、2026-10-01 の brainstorming で、試作を見比べながら決めた内容をまとめたものである。
試作は `docs/superpowers/specs/2026-10-01-page-heading/` に置いた。ブラウザで直接開けば動く。

- `header-location.html`：今の形と新案の比較。赤い線が検索欄の左端である。
- `collapsed-logo.html`：サイドバーを畳んだときのロゴ。採ったのは「2 図と名前」である。
- `heading-line.html`：見出しの見せ方。採ったのは「A 3 のまま」である。

実装が入るときに、`docs/design.md` の「骨格」の記述を同じ内容へ書き換える。

## 目的

ヘッダーの左上には、今いる場所のパンくず（「ホーム」「agent-hangar / セッション名」）がある。
文字の幅がページごとに違うので、右に続く検索欄が、ページを移るたびに左右へ動く。
利用者の言葉では「ページ移動した時に、検索窓がズレるのが気に食わない」であり、これを直す。

成功の基準は次のとおりとする。

- どのページへ移っても、検索欄の位置が変わらない。
- どのページへ移っても、見出しとその下の線の位置が変わらない。
- 今いる場所と、親へ戻る道（セッション → プロジェクト、プロジェクト → 一覧）が、今と同じく 1 回の操作で辿れる。

## 決定の要約

| 箇所 | 決定 |
|---|---|
| パンくず | ヘッダーから外す。今いる場所は、各ページの本文の一番上の見出しで示す。見出しの無かったホームにも「ホーム」を置く |
| 見出し | 18px、太さ 700。下に 1px の線（`--line-strong`）を引いて本文と分ける |
| 親へのリンク | 見出しの上に「agent-hangar ›」と小さく（12px）出す。親の無いページでも、この行の高さを空けて取る |
| セッションの画面 | 線の上は、親、状態の点、名前、要約の 1 文、操作のボタンだけにする。チップの列と細かな事実は線の下に置く |
| 検索欄 | 左端を本文（見出し）の左端にそろえる |
| ロゴ | サイドバーからヘッダーの左（信号の 3 点の右）へ移す。図と「Hangar_」の両方を、開いても畳んでも同じ形・同じ位置に置く。押すとホームへ行く |
| 開閉のボタン | 開いた帯では「ホーム」の行の右端に置く。畳んだ帯では一番上に置く |
| ハンガーの揺れ | 開閉のたびに、ヘッダーのロゴを今と同じ振り子で揺らす |
| ヘッダーの右側 | 同期、使用率、新規セッションは、今と同じく窓の右端に置く |

## 骨格

### ヘッダーの列

ヘッダーは今と同じく、窓の上辺と左右の端に付いた帯である。
中身の置き方だけを、殻（`.shell`）の 2 列に合わせる。

- ヘッダーは `grid-template-columns: subgrid` で、殻の列（サイドバーの列と本文の列）をそのまま使う。サイドバーを開閉すると列の幅が動き、ヘッダーの中身も一緒に動く。
- 左の列には、信号の 3 点とロゴを置く。ロゴは信号の右（`--lights-end`）から始まる。
- 右の列には、検索欄と右の塊（同期、使用率、新規セッション）を 1 行に置く。

`container: header / inline-size` はレイアウトの封じ込めを伴い、封じ込めのある要素では subgrid が `none` として扱われる（CSS Grid 2 の定め）。
そこで、コンテナ（検索欄の左端の式が使う `100cqw` の入れ物）は、ヘッダーそのものではなく右の列の行に付ける。

（2026-10-01 追記）狭いときに部品を畳む仕組みは、コンテナクエリの決め打ちの幅をやめ、右の列の幅と中身の幅を測る仕組み（`views/headerFold.ts` と `views/useHeaderFold.ts`）に替えた。
決め打ちの幅は同期の文や件数の長さの変化に追いつかず、同期の一行がゲージに重なって描かれたからである。
畳む順と、重ならないことの保証は `docs/design.md` のヘッダーの節に書く。
コンテナを右の列の行に付ける約束はそのまま守る。

### 本文と検索欄の左端

本文は今と同じく、`--main-w`（1200px）を上限に本文の列の中央へ寄る。
検索欄の左端は、本文の左端と同じ式で決める。

- 本文は `--main-w` を上限に本文の列の中央へ寄る。その左の余りを `--box-l`（`max(0, (100vw − --col1 − --main-w) / 2)`）とする。
- 本文の左の余白を `--gutter-l` とする。既定は今と同じ 16px である。
- ヘッダーの左の列にあるもの（信号とロゴ）の右端を `--head-end` とする。中央へ寄った本文が `--head-end` より左に来てしまう間だけ、`--gutter-l` を `--head-end − --col1 − --box-l` まで広げる。サイドバーを畳むと列は 60px になり、ロゴは約 197px まで伸びているので、窓が狭い間は本文も検索欄もロゴの右から始まる。窓が広く、本文が十分に中央へ寄っているときは広げない（畳んだときに本文が右へ逃げない）。
- 検索欄の左の余白は `max(--gutter-l, (本文の列の幅 − --main-w) / 2 + --gutter-l)` とする。本文の列の幅は、右の列の行のコンテナの幅（`100cqw`）で取る。

ロゴの箱の幅は、字形の幅に頼らず tokens の `--brand-w`（104px）に決め打ちし、はみ出した分は切る。字形の読み込みの前後で本文の位置が動かないためである。
左の列の幅は、登録したカスタムプロパティ `--col1` に持つ。開閉の動きは列の幅と `--col1` を同じ長さで動かし、本文と検索欄の余白も途中の幅に付いて動く。

### サイドバー

ロゴと、その横にあった開閉のボタンの段（`.sidebar-top`）を外す。

- 開いた帯では、「ホーム」の行の右端に開閉のボタンを置く。ホームの錠剤は、ボタンの分だけ他の項目より短くなる。
- 畳んだ帯では、ボタンを一番上に置き、その下にアイコンを並べる。ボタンの吹き出し（「開く ⌘B」）は今のまま残す。
- 信号の 3 点の分の上の余白は、今までどおりヘッダーの高さが受け持つ。

### 開閉の動き

`views/primitives/sidebarMotion.ts` は、帯の幅、項目の箱、アイコン、項目名、図、名前（Hangar_）を同じ長さと曲線で動かしている。
図と名前はヘッダーへ移り、開閉では動かなくなるので、その 2 つを測る部分を外す。
振り子の揺れは、ヘッダーの図に付け替える。引かれる向き（閉じると右、開くと左）と長さは今のまま使う。
開閉ボタンは、開いた帯では「ホーム」の行、畳んだ帯では一番上と、2 か所を移る。この移動も、項目の箱と同じく前の形との差を埋めて動かす。
開閉の動きは、開閉の印だけを一瞬戻して前の形を測るので、2 つの形は CSS だけで作り、DOM の組み立ては変えない（畳んだ帯では、ホームの行を縦に並べ替えてボタンを上に出す）。

## 見出しの部品

見出しの段を 1 つの部品（`PageHeading`）にし、6 つの画面すべてで使う。

- 1 段目は親へのリンクの行で、高さは 18px に決め打ちする。親が無ければ空の行を置く。
- 2 段目は見出しの行で、高さの下限を `--row-h`（28px）にする。ボタンの並ぶセッションの画面と、ボタンの無いホームで、線の高さがそろう。
- 見出しの行には、見出しの前に置くもの（セッションの状態の点）と、後ろに置くもの（件数、絞り込み、操作のボタン）を渡せる。
- 段の下に 12px の余白と 1px の線を置き、線の下に 16px 空けてから本文を始める。

画面ごとの中身は次のとおりである。

| 画面 | 親 | 見出し | 見出しの行の残り |
|---|---|---|---|
| ホーム | なし | ホーム | なし |
| Projects | なし | プロジェクト | 名前で絞る欄、アーカイブの切り替え |
| プロジェクト詳細 | プロジェクト（一覧へ） | プロジェクト名 | ステータス、新規セッション、VS Code で開く、ターミナルで開く、右レールの開閉 |
| Sessions | なし | セッション | 件数 |
| セッション | プロジェクト名（そのプロジェクトへ）。プロジェクトに属さなければなし | セッション名 | 状態の点（前）、要約の 1 文、操作のボタン |
| Settings | なし | 設定 | なし |

Sessions の画面だけが持っていた外側の余白（`.sessions-screen` の padding）は外し、他の画面と見出しの位置をそろえる。
見出しの `h1` は今のまま 1 画面に 1 つとし、読み上げの見出しの構造は変えない。
親へのリンクは `a` で、押すと今のパンくずと同じく `nav.go` を出す。

## データの流れ

`presenters/shell.ts` の `crumbs` を外し、`ShellProps` と `Header` の props からも外す。
親へのリンクは、プロジェクト詳細とセッションの presenter が返す（`parent: { label, route } | null`）。
ラベルの決め方は今の `crumbs` と同じである（セッションは属するプロジェクトの名前、プロジェクト詳細は「プロジェクト」）。

## テスト

- presenter：プロジェクト詳細とセッションが `parent` を返すこと。プロジェクトに属さないセッションでは `null` になること。`ShellProps` に `crumbs` が無いこと。
- 見出しの部品：親の有無で 1 段目の行が常にあること、親のリンクが `nav.go` を出すこと。
- ヘッダー：パンくずを描かないこと、ロゴが Home へのリンクであること。
- サイドバー：開いた帯で開閉のボタンがホームの行にあること、畳んだ帯で一番上にあること。
- 開閉の動き：図と名前を測らなくなっても、揺れがヘッダーの図に掛かること。
- CSS：ヘッダーに `container` が無く、右の列の行に付いていること（subgrid を殺さないため）。ロゴの箱の幅が tokens の `--brand-w` であること。余白の式。
- 目視：開いた帯と畳んだ帯、窓の幅 860px と 1280px と 1680px で、6 画面を順に移り、検索欄と見出しと線が動かないこと。

## 範囲の外

- ヘッダーの右側の並びと中身は変えない。
- 見出しの行に置くボタンの中身と順は変えない。
- 起動画面の揺れは変えない。
