# LM Studio のサーバー自動起動

会話開始時、ローカル LM Studio の API が停止していれば CLI で起動し、接続できてからモデルのロードへ進む。利用者は試作 A（一行＋完了履歴）を選択した。既存の growIn / fadeIn を再利用する。

## 比較した案
- A: 進行中の一行と完了履歴。既存 UI の中で収まり、利用者が選択。
- B: 全手順の一覧。先の手順が見えるが表示面積が増える。

## 動作
- 「LM Studio のサーバーを起動中…」。成功後は「LM Studio のサーバーを起動しました」を完了履歴に残す。起動済みなら表示しない。
- ユーザー設定の準備コマンドを優先。新規開始・再開時、選択モデル・small_model・agent が参照する LM Studio を対象にする。
- 自動操作は provider ID が lmstudio、HTTP の localhost / 127.0.0.1 / ::1、標準 /v1 パスの接続先だけ。別サービスや LAN 接続先を推測して起動しない。
- lms daemon up → lms server start --port <設定ポート> --bind <ループバック>。シェルを介さず、秘密を含まない環境を渡す。
- API が応答済みなら CLI を呼ばない。停止中の起動は同じ接続先で共有し、全待機者が中止したら起動コマンドを中止する。起動済みサービスの停止はしない。
- 起動と API 確認を合計 30 秒で制限。CLI 不在・起動失敗はサーバーの失敗として表示。言語は既存の ja/en 辞書に従う。
- 実機検証: アプリ終了後も daemon up が既存 LM Studio を --run-as-service で起動し、server start 後に API 200 と同じモデル一覧を確認済み。

## 対象外
モデルのダウンロード、CLI の自動インストール、終了時のサーバー停止、リモートサーバーの起動。
