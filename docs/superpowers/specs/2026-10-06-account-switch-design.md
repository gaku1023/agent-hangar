# アカウントの切り替え

2026-10-06。試作は `2026-10-06-account-switch/` の `model.html`（全体の案）、`model2.html`・`model3.html`（ダイアログの札）、`model4.html`（ヘッダの使用量）、`model5.html`（切り替えの流れ）。試作の名前、メールアドレス、使用率はすべて仮の値である。

## 利用者の要望

- Claude Code のアカウントを 2 つ持っている（仕事用と大学用）。切り替えのたびに `/login` してブラウザで承認するのをやめたい。
- 新規セッションで、セッションごとにどのアカウントで動かすかを選びたい。
- 切り替えは Google のアカウントの切り替えのようにしたい。ヘッダを押すと一覧が開き、選ぶと切り替わり、新しいセッションもそのアカウントで始まる。

## 調べたこと

### 公式の方法と規約

- Claude Code の公式ドキュメント（Authentication の「Log in with multiple accounts」）は、アカウントごとに `CLAUDE_CONFIG_DIR` を分ける方法を案内している。macOS では Keychain の項目も置き場ごとに分かれる。ログインは置き場ごとに 1 回で済む。
- Consumer Terms にアカウントの数を制限する条項は見当たらなかった。禁じられているのは、ログイン情報の共有、BAN の回避、第三者の開発者が Claude.ai の資格情報やトークンを収集・保存・仲介することである。
- Pro・Max の上限は「通常の個人利用」を前提にしている。

ここから引いた線は 2 つである。

- hangar はトークンを読まず、保存もしない。渡すのは `CLAUDE_CONFIG_DIR` だけで、ログインは `claude` 自身のブラウザの流れに任せる。
- 上限に当たったときに自動で次のアカウントへ回す仕組みは作らない。切り替えは必ず利用者の手で行う。

### 実物で試したこと（2026-10-06、Claude Code 2.1.289）

2 つ目の置き場の中身を `~/.claude` へのシンボリックリンクにして、別に持つのは認証（Keychain の項目と `.claude.json`）だけにした。

| 試したこと | 結果 |
|---|---|
| 2 つ目のアカウントで新しい会話を始める | 動いた。本文は `~/.claude/projects` に書かれた |
| 2 つ目で始めた会話を 1 つ目のアカウントで再開する | 動いた |
| 1 つ目で始めた会話を 2 つ目のアカウントで再開する | 動いた |
| リンク越しに `settings.json` へ書き込む | リンクは残り、実体が書き換わった |
| 試しのあとのリンクと認証 | リンクは全部残り、どちらのログインも変わらなかった |

リンクにしたのは次の 17 個である。`CLAUDE.md`、`settings.json`、`statusline-command.sh`、`history.jsonl`、`commands`、`skills`、`plugins`、`memory`、`projects`、`file-history`、`paste-cache`、`plans`、`tasks`、`session-env`、`shell-snapshots`、`sessions`、`jobs`。リンクにしなかったのは `.claude.json`、`backups`、`cache`、`daemon`、`ide`、`telemetry`、組織から配られる設定（`remote-settings.json`、`policy-limits.json`）である。

試していないのは、対話の画面（`-p` でしか動かしていない）と、長い会話や思考つきの会話をまたいだ再開である。実装の最初に実物で確かめる。

## 決定

### 共有の範囲

アカウントを切り替えて変わるのは認証だけである。設定・スキル・プラグイン・履歴は `~/.claude` を共有する。履歴の実体が 1 か所のままなので、hangar の索引・保持期間・クラウド同期は変えない。

仕事の会話を別の組織のアカウントで再開すると、その中身がそちらへ送られる。どちらで動かすかは利用者が決め、hangar はどのアカウントで動いているかを見えるようにする。

### アカウント

- アカウントは、名前・置き場・色の組である。この PC の hangar の設定に持つ。ほかの PC へは同期しない。
- 最初のアカウントは `~/.claude` で、消せない。
- メールアドレスとプランは、置き場ごとに `claude auth status` を呼んで読む。起動時とログインの後に読み直す。
- 頭文字の四角い印は付けない。目印は名前の文字と小さな色の点である。色は追加のときに自動で割り当て、設定で変えられる。

### いまのアカウント

- hangar 全体で「いまのアカウント」を 1 つ持つ。新しいセッションの既定になる。
- ターミナルでただ `claude` と打ったとき（シェル連携の経由）も、いまのアカウントで起動する。利用者が自分で `CLAUDE_CONFIG_DIR` を付けたときは、そちらを優先する。
- hangar が起動していないときのターミナルの `claude` は、今までどおり `~/.claude` で動く。

### ヘッダ

- 使用量の計器（5 時間・週）の前に、色の点とアカウントの名前を出す。
- ホームや一覧では、いまのアカウントの使用量を出す。
- セッション画面では、そのセッションを動かしているアカウントの使用量を出す。途中で切り替えたセッションは、最後に動かしたアカウントである。
- 押すと一覧が開く。アカウントごとに、名前、プラン、メールアドレス、5 時間と週の使用量、戻る時刻を並べる。値がいつのものかもアカウントごとに書く。下に「アカウントを追加」と「アカウントの設定」を置く。
- 一覧から選んだとき、ホームや一覧では、いまのアカウントが変わる。動いているセッションには触らない。
- 一覧から選んだとき、セッション画面では、確認のうえそのセッションを選んだアカウントで再開し直し、いまのアカウントも変える。作業中なら、確認に「途中の作業が中断されます」と書く。

### 新規セッションのダイアログ

- プロジェクトの欄の下に「アカウント」の段を置く。色の点つきの横並びの札で、名前、プラン、メールアドレス、5 時間と週の使用量を入れる（試作の N4）。
- はじめは、いまのアカウントが選ばれている。そのセッションだけ別のアカウントにできる。ダイアログで選んでも、いまのアカウントは変えない。
- 5 時間の使用量が 80% 以上の札には「まもなく上限。HH:MM に戻ります」と書く。値が 1 時間より古い札には「N 時間前の値」と書く（試作の N3）。選択は動かさない。
- アカウントが 1 つだけのときは、この段を出さない。

### 再開と一覧

- 再開は、そのセッションを最後に動かしたアカウントで起こす。変えるのはセッション画面のヘッダの一覧からである。
- セッション画面の情報の行に、色の点と名前の札を出す。
- セッションの一覧には、アカウントの印を出さない。

### アカウントの追加

1. 名前を付ける。
2. hangar が置き場（`~/.claude-<連番>`）を作り、上の 17 個のリンクを張る。
3. hangar がターミナルのタブを開き、`CLAUDE_CONFIG_DIR=<置き場> claude auth login` を走らせる。承認は利用者がブラウザで行う。
4. 終わったら `claude auth status` を読み、メールアドレスとプランを確かめて出す。

途中でやめたら、名前の付いた「未ログイン」のアカウントが残る。設定から続きができる。

## 仕組み

### 起動

- `LaunchParams` に `account`（アカウントの id）を足す。無ければ、いまのアカウントを使う。
- `RunManager.launch` は、アカウントの置き場を `CLAUDE_CONFIG_DIR` として tmux の環境に足す。最初のアカウント（`~/.claude`）のときは足さない。今までと同じ動きを保つためである。
- どのアカウントで動かしたかは、run の `launch_params` に残す。`launch_params` は JSON の文字列なので、列は足さない。
- セッションのアカウントは、そのセッションの最後の run のものである。run が無いセッション（hangar の外で始めたもの）は、最初のアカウントとして扱う。
- シェル連携は環境変数をそのまま渡している（`runs/terminal.ts`）。利用者の環境に `CLAUDE_CONFIG_DIR` があればそれを使い、登録済みの置き場と一致すればそのアカウントとして記録する。無ければ、いまのアカウントの置き場を足す。

### リンクの見張り

起動の前に、置き場のリンクが残っているかを確かめる。欠けていたら張り直す。リンクが実ファイルに置き換わっていたら起動を止め、どのファイルかを伝える。黙って直すと、置き換わった側に書かれた設定を失うためである。

### セッションの切り替え

Claude を止め（Paused にしたときと同じ止め方）、同じ会話を選んだアカウントの置き場で `-r` で起こす。本文は共有なので写さない。

### 使用量

- `UsageTracker` はアカウントごとに値を持つ。
- statusline から届いた値は、payload の `session_id` からセッションを引き、そのアカウントへ振り分ける。本文の置き場は共有なので、`transcript_path` では見分けられない。
- `usage_snapshots` にアカウントの列を足す（v15）。この表は同期しない。500 件の上限はアカウントごとに数える。
- 使用量は、そのアカウントのセッションが動いたときにしか届かない。値の時刻をアカウントごとに持ち、画面に出す。
- `UsageDto`、`usage.update`、`GET /api/usage`、MCP の `get_usage` は、アカウントごとの値の一覧を返す形に変える。
- 事後の要約が使うのは最初のアカウントで、止める判定もその使用量で行う。

### hangar が置き場に入れるもの

statusline の設定は `settings.json` が共有なので、どのアカウントにも効く。MCP は起動ごとの `--mcp-config` で渡しているので、置き場ごとの登録は要らない。準備の確かめ（readiness）は今のまま最初のアカウントだけを見る。

## 入れないもの

- 上限に当たったときの自動の切り替え。
- セッションの一覧のアカウントの印と、絞り込み `account:名前`。
- 事後の要約に使うアカウントの選択。
- ほかの PC とのアカウントの同期。
- 設定や履歴をアカウントごとに分ける使い方。

## 試作で退けたもの

- ダイアログの置き場所 A1〜A4・A6（1 段の択一、見出しの札、詳細の中、起動ボタン、プロジェクトの欄の隣）。使用量を見て選べる A5 を採った。
- 札の変種 V1〜V7、N1〜N3、N5。頭文字の印は、名前の横に同じ意味がもう 1 つ並ぶだけなのでやめた。
- 一覧の印 B1〜B4（名前の後ろの札、既定でないものだけの札、要約の行の頭、左の縁の線）。
- ヘッダの使用量 H1〜H4、H6〜H8（きつい方を 1 組、2 本の細い棒、数字だけの塊、二重の輪、余裕があるときは畳む、サイドバーの足元、ヘッダに出さない）。
- プロジェクトごとに前回のアカウントを覚える案。いまのアカウントを 1 つ持つ形に寄せた。
- セッション画面でもヘッダにいまのアカウントを出す案（S1）。
- 追加の流れ G2（先にログインし、名前は候補から選ぶ）。

## 残り

- 対話の画面と、長い会話・思考つきの会話をまたいだ再開を、実装の最初に実物で確かめる。動かないものがあれば、この設計に戻って直す。
- Claude Code が `~/.claude` の直下に新しい項目を足したとき、リンクの一覧に無いものはアカウントごとに別になる。一覧は版を上げるたびに見直す。
- 置き場ごとの `.claude.json` は別なので、2 つ目のアカウントでは初回の案内と、フォルダの信頼の確認がもう一度出る。
