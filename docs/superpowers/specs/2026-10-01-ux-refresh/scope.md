境目の外の決定は、それぞれの設計書を正本とする。

## live-explainer との境目

実行中のセッション画面の、ターミナルの右側（右ペイン）は live-explainer が持つ。
右ペインの中身（状態の灯、意図、指揮役の手、サブエージェント、触っている層、作業の居場所、目次と色帯）、並び、高さの配り方、幅、開閉は、live-explainer の設計に従う。
UX 刷新はそこに手を入れない。

UX 刷新が持つのは次のものである。

- 右ペインより左（ターミナル、タブの列、ターミナルの上に出す切断と transcript 表示中の知らせ）。
- 見出しの段（page-heading の部品の中身の並べ方と、主の操作の選び方）。
- セッション画面の縦の配り方（ターミナルと右ペインが窓の残りの高さを全部使うこと）。右ペインの中の配り方は live-explainer が決める。
- 終わったセッションの画面（live-explainer は範囲の外としている）。本文の表示（`transcript-render.html`）と、終了後の右欄（`session-layout.html` の E 軸）はこちらで決める。

試作との対応は次のとおりである。

- `session-layout.html` の D 軸（目次の幅と開閉）は選ばない。live-explainer が決める。
- `session-layout.html` の B2（畳んだ情報を右欄の先頭に置く）は、実行中の画面では使わない。右ペインは live-explainer のものだからである。終わった画面の右欄（E 軸）の中でなら使える。
- ①で入れたターンの目次のキー操作（↑↓ と j/k、Enter で開く）は、live-explainer が目次の行に色帯を足すときに残すよう申し送る。

## page-heading との境目

見出しの段の骨組み（親へのリンク、状態の点、名前、要約の 1 文、操作のボタンを線の上に置き、チップと細かな事実を線の下に置く）は page-heading が決めた。
`session-layout.html` の A 軸（上段の操作）、B 軸（畳んだ情報）、C 軸（名前の重複）は、この骨組みの上での並べ方として選ぶ。
C 軸のうち、パンくずをヘッダーから外すことは page-heading で済んでいる。
残るのは、要約の帯の題が見出しの名前と重なる件である。

page-heading は、どのページでも検索欄の位置を変えないために、検索欄の左端を本文の左端（`--main-w` の 1200px を上限に中央へ寄せた箱）にそろえている。
UX 刷新の「セッション画面だけ幅の上限を外す」は、この約束とぶつかる（セッション画面でだけ検索欄が左へ動く）。
利用者は 2026-10-01 に、上限を外し、セッション画面でだけ検索欄が左へ動くのを受け入れると決めた（案 b）。

## 入れる順番（利用者の決定）

UX の直し 1 を先に main へ入れ、次に live-explainer、最後にセッション画面の組み直しを入れる。
セッション画面の骨組みに触れない UX 刷新 2 の部分は、この順を待たずに進める。
