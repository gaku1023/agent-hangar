# 段 0 Claude Code との互換の約束

作り替えの全体計画（`2026-10-07-refactor-roadmap-design.md`）の段 0 である。
hangar を公開すると（D3）、利用者ごとに claude の版が違う。
Claude Code の形式が変わったときに、hangar がそれに気づき、その機能だけを止めて理由を出せるようにする。

## いまの姿

hangar は、Claude Code が公開を約束していない形式に 33 か所で頼っている。
主なものは、トランスクリプトの行の形、`~/.claude/sessions/<pid>.json` のレジストリ、statusline に渡る JSON、`~/.claude` の中の配置、CLI の引数と出力、ターンへ跳ぶときに読む画面の文字である。

形式が違ったときの振る舞いは、ほとんどが黙って捨てるか既定値に落とすかで、利用者にも開発者にも知らせない。
たとえば次のことが黙って起きる。

- `system.subtype` の `turn_duration` の名前が変わると、「バックグラウンドで作業中」の印が付かなくなる。
- statusline の `resets_at` が秒からミリ秒に変わると、使用率が戻る時刻が 1000 倍ずれる。
- Claude Code が `~/.claude` に新しい項目を足しても、アカウントの切り替えで共有されない。
- シェルの包みが知らないサブコマンドは、初期の指示として claude に渡る。

最後のものはすでに起きている。
包みが知っているサブコマンドの一覧には、2.1.292 の `claude --help` にある `purge` が無く、`--help` に無い `daemon` と `project` が残っている。

claude の版で振る舞いを分けている所は無い。
版は、レジストリ、トランスクリプトの各行、statusline の JSON のどれにも載っているが、どこも読んでいない。
試験の見本は匿名化した手書きで、実物の観察は spikes の文章にしか残っていない。

## 決めたこと

- 知っている値の集合で見張り（実行中）、版ごとの見本で確かめる（試験）。対応する版の範囲は決めない。Claude Code はほぼ毎日新しい版が出るので、範囲はすぐ古くなり、範囲の中で形式が変わっても捕まえられないためである。
- ずれは設定の確認リストの 1 行で知らせる。
- 見本は、使い捨ての場所で本物の claude を動かして採る。
- マイグレーションの前の DB の自動控えを、この段で入れる。段 1 以降でスキーマを変える前に入っている必要があるためである。

## 契約

hangar が頼る形式を、次の 6 つの契約に分ける。
置き場は Claude に固有のコードの塊（いまの `packages/server/src/provider/claude-code/`）の中の `compat/` である。

| 契約 | 見張るもの | ずれたときの振る舞い |
| --- | --- | --- |
| トランスクリプト | 行の `type`、`system.subtype`、本文の塊の種類、`attachment.type`、メタ行の種類が、正規化の知っている集合にあるか | いまの扱い（知らない行は meta として残す、知らない塊は捨てる）のまま、記録する |
| レジストリ | `status` が知っている集合（busy、idle、waiting、shell）にあるか。`sessionId` と `pid` があるか | 知らない `status` は、いまと同じく作業中として扱い、記録する。休んでいるセッションを止める機能があるので、誤って止めるより待たせるほうが害が小さい |
| statusline | 読む項目（`rate_limits` の `used_percentage` と `resets_at`、`context_window`、`cost`、`model`）があるか。`resets_at` の単位 | `resets_at` がミリ秒と見られる値（10^11 より大きい）なら、秒に直さずにそのまま使い、記録する。欠けた項目は、いまと同じく直前の値を保ち、記録する |
| `~/.claude` の項目 | 直下の項目が、アカウントの切り替えで共有するもの（いまの 17 項目）か、アカウントごとに持つものとして知っているものか | 知らない項目は、いまと同じくアカウントごとのままにし、記録する |
| CLI | サブコマンドの一覧、`agents --json`、`auth status --json`、`-p --output-format json` の形 | サブコマンドの一覧は、サーバの起動のたびに `claude --help` から作り直し、シェルの包みに書き込む。読めないときは組み込みの一覧を使う。組み込みの一覧との差を記録する。ほかの出力は、いまと同じく形が違えば読まずに既定へ落とし、記録する |
| 画面の文字 | ターンへ跳ぶときに読む目印（トランスクリプト表示の最下行の文言、指示の行の頭の記号） | いまと同じく、見つからなければ跳ぶのをやめ、記録する |

利用者の発言でない行を見分ける目印（本文の頭のタグなど）は自由な文字列で、知っている集合で見張れない。
これは見本の試験で確かめる。

### ずれの記録

ずれは、契約、値（たとえば `system.subtype=foo`）、claude の版、回数、最初と最後に見た時刻を持つ。
版は、その値を読んだ元（レジストリ、トランスクリプトの行、statusline の JSON）に載っている `version` を使い、無ければ手元の `claude --version` を使う。

記録は `~/.agent-hangar/compat.json` に置く。
端末ごとのもので、同期しない。
DB のマイグレーションを要らない形にするためにファイルにした。
同じ契約と値の組は 1 件にまとめて回数を数え、件数には上限を置く。

読む口は `GET /api/compat` で、確かめた版、手元の版、ずれの一覧を返す。
`GET /api/readiness` の応答にも、確かめた版、手元の版、ずれの件数を足す。

### 確かめた版

確かめた版は、見本のうち最も新しい版である。
手元の claude がそれより新しいときは「未確認の版」として知らせるが、止めはしない。
README に確かめた版を書き、見本を足すときに更新する。

## 見本

### 採る道具

開発用の道具 `scripts/capture-claude-fixtures` を作る。
CI では動かさない（認証が要るため）。
動かすと Claude の使用量を少し使う。

1. 一時ディレクトリを作り、そこで本物の claude を起動する。tmux は専用のソケットを `-S` で名指しし、`kill-server` は呼ばない。止めるのは名指しのソケットの名指しのセッションだけである。
2. モデルは haiku、effort は low にする。権限の確認で止まらない起動の仕方は、計画で確かめて決める。
3. `--settings` で、statusline に渡る JSON をファイルへ写すスクリプトを差し込む。利用者の `settings.json` には触れない。
4. 決めた筋書きを流す：ファイルを書く、Bash を動かす、サブエージェントを使う、作業中に次の指示を積む、TodoWrite を使う、終える。
5. 動いているあいだ、その会話のレジストリを状態が変わるたびに写す。
6. 終えたら、トランスクリプト（サブエージェントのものを含む）、`claude agents --json --all` のその会話の分、`claude auth status --json`、`claude --help` を採る。
7. 一時ディレクトリのパス、ホームのパス、メールアドレス、組織名、アカウントの識別子を、決まった置き換えの値に伏せる。
8. `claude purge <一時ディレクトリ> -y` で、その会話の記録を `~/.claude` から消し、一時ディレクトリも消す。

採った見本は `packages/server/test/fixtures/claude/<版>/` に置く。
コミットする前に、伏せ残しが無いかを目で確かめる。
採っているあいだ、動いている hangar はこの会話を一覧に出し、後始末の後は消えた会話として扱う。

### 見本の試験

すべての版の見本について、正規化、索引、レジストリ、statusline、`--help` の読み取りを通し、次を確かめる。

- ずれが 0 件である。
- 主な読み取り（ターンの数、サブエージェント、題名、使用量、積んだ指示）が筋書きどおりに取れる。
- `--help` から作ったサブコマンドの一覧が、シェルの包みに書き込まれる。

いまの手書きの見本は、見本に現れない端のケースのために残す。

### 週に 1 度の照合

GitHub Actions に、週に 1 度と手動で走るジョブを足す。
最新の claude を入れ、`claude --version` と `claude --help` を、最も新しい見本と突き合わせる。
サブコマンドか引数が変わっていればジョブを落とし、見本を採り直す合図にする。
認証は要らない。
claude の入れ方は計画で確かめる。

## 画面

設定の確認リストに、6 行目「Claude Code との互換」を足す。
状態は次の 3 つである。

- 問題なし：確かめた版を添える。
- 未確認の版：手元の版と確かめた版を並べる。止めてはいないので、弱い色で出す。
- ずれ N 件：開くと、契約、値、版、最初に見た時刻、その契約で止めた機能が見える。

文言と配置は、実装の前に試作を作って利用者が選ぶ。

## DB の自動控え

`openDb` は、当てていないマイグレーションがあり、かつ DB がすでに 1 本以上のマイグレーションを当てているとき、当てる前に `VACUUM INTO` で `~/.agent-hangar/backups/db/hangar-v<当てた最後の版>-<時刻>.db` へ控えを取る。
新しい DB と `:memory:` では取らない。
控えは新しいものから 5 つまで残す。
控えが取れなければマイグレーションを当てず、理由を出して起動を止める。
設計書の「控えが取れなければ書かない」の原則に合わせた。

## 設計書

design.md に「Claude Code との互換」の節を足し、契約、ずれの記録、見本、確かめた版を書く。
「外のターミナルのセッション」の節の、包みがそのまま渡すサブコマンドの記述を、`--help` から作る形に直す。
マイグレーションの版の数など、陳腐化した記述もこの段で直す。

## 範囲外

- 対応する版の範囲を決めて、範囲外の claude を断ること。
- 形式のずれを自動で直すこと（statusline の単位とサブコマンドの一覧を除く）。
- ずれを、確認リストの外（ヘッダー、知らせの札）に出すこと。

## 終わりの条件

- 見本の試験が CI で回り、採った最新の版でずれが 0 件である。
- 知らない値を混ぜた試験で、ずれが記録され、その機能だけが止まり、確認リストに出ることを確かめている。
- シェルの包みが `--help` から作ったサブコマンドの一覧を使い、`claude purge` がそのまま渡る。
- マイグレーションの前に DB の控えが取られることを、試験で確かめている。
