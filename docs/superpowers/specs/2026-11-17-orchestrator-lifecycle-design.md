# 統括の会話の作り直しと、過去を引く仕組み 設計

2026-11-17。統括（常駐の Claude Code の会話）を「延命する 1 本」から「いつでも作り直せて、過去を引ける 1 本」に移す。

## なぜ

- 統括は 1 本の会話を延命し続ける作りで（`orchestrator/keeper.ts`）、利用者が始め直す手段が無い。設定を入れ直して同じ会話を再開するのは、知らないと使えない手順。
- 役の文（システムプロンプトへの追記）は起動と再開のときにしか入らない。アプリを入れ替えても tmux の統括は動き続けるので、古い役の文のまま話す（2026-11-17 に起きた）。
- 見張りの状態（止まった、10 分に 3 回失敗した）と文脈の量が画面に出ない。
- 統括は過去の話も、ほかの会話も検索できない（下の「確かめたこと」）。会話を新しくすると、前の話が切れる。

## 確かめたこと（2026-11-17）

### search_sessions が統括の会話を拾わない理由

- 全文索引（`event_fts`）には統括の本文が入っている（統括の会話 1 本で 240 行、「赤で答えました」も 2 件当たる）。
- 落ちるのは枠のため。MCP の検索と一覧は、セッション別 URL ではそのセッションのプロジェクトに絞られる（`mcp/tools.ts` の `projectScope`）。統括は `project_id` が null なので、プロジェクトのセッションから検索すると外れる。
- 統括自身の URL では、枠が null（プロジェクトに属さない）になり、`search_sessions` は NO_PROJECT で断られ、`list_sessions` は自分しか返さない。統括の会話（11-13〜11-17）では `search_sessions` を一度も呼んでいない。`get_transcript` だけは別のセッションを指せる。

### /compact は実物で動いたか

- 動いていない。統括の会話（11-13〜11-17、応答 203 回）の文脈は最大 13.4 万で、閾値の 15 万に届いていない。compact の境目の記録も無い。
- 増え方は 11-17 の 1 日で 8 万から 13 万。よく使う日なら 1〜2 日で 15 万を超える。

## 利用者が決めたこと

| 問い | 決定 |
|---|---|
| 統括の道具で、どこまで見せるか | 全プロジェクトを読める。読む道具だけで、書く道具の枠は今のまま。統括の過去の会話も検索に入る。 |
| 新しい会話に切り替えるきっかけ | 柱のボタン（いつでも）と、太ったときの自動。自動は、過去を引く仕組みが入ってから有効にする。 |
| 切り替えのとき渡すもの | hangar が記録から作る引き継ぎを必ず渡し、古い統括に書かせたメモを、書けたら添える。メモが失敗しても切り替えは進む。 |
| 柱の操作の見た目 | 試作の案 A（開いた柱の右上の丸を押すとメニュー）。 |

## 目標

- 利用者が柱から、統括を新しい会話で始め直す、止める、起こす、ができる。状態（動いている、止まった理由）と文脈の量が見える。
- 会話を新しくしても、「〇〇ってどうなってる？」「前に頼んだあれ」に、検索して答えられる。
- アプリの更新で役の文が変わったら、統括は新しい役の文で話す。
- 文脈が太っても、答えの質を保つ（要約を重ねない）。

## 目標でないもの

- 統括の記憶を別の DB に作ること。既存の会話の本文と全文索引を使う。
- 複数の統括。PC ごとに 1 本のまま。
- 定時の切り替え。

## 中身

### 1. 統括の読む道具の枠を外す

- 統括の URL（`isOrchestratorCtx` が真）では、読む道具 `search_sessions`、`list_sessions`、`get_transcript`、`list_projects`、`get_project` を、共通 URL と同じく全プロジェクトに効かせる。
- 書く道具（`update_project`、予定、`open_in_hangar` など）の枠は今のまま。統括は今と同じく、プロジェクトに書けない。
- 統括の過去の会話（下の系譜にある id）は、検索の結果に印 `orchestrator: true` を付ける。統括は、自分の過去の話とほかの会話を見分けられる。
- プロジェクトのセッションから検索したとき、統括の会話は今と同じく出ない（枠の外）。

### 2. 系譜

- 設定 `orchestrator` に `history: { sessionId, startedAt, endedAt, reason }[]` を足す。`reason` は `fresh`（利用者が押した）、`auto`（太った）、`gone`（会話が消えて起こし直した）。上限 20 件、古いものから落とす（会話そのものは消さない）。
- 切り替えると、今の `sessionId` を history に移し、新しい会話の id を `sessionId` に書く。
- 統括が関わった会話（`involved.ts`）は、系譜の id まで含めて引く。前の統括が起こした会話の終わりも、新しい統括に届く。
- 前の統括の会話はサイドバーに出さない（柱の固定の行は今の 1 本だけ）。検索とその会話を開く操作では見える。

### 3. 切り替えの手順

1. 古い統括が idle で、入力欄が空で、預かり（feed の出来事、許可の預かり）が空になるのを待つ。手動のときは待ちの上限 30 秒で、越えたら待たずに進む。
2. 古い統括へ `[hangar]` の入力で、申し送りを統括専用の道具 `write_handoff`（text を 1 つ受け取る）で書くよう頼む。上限 90 秒。来なければメモ無しで進む。
3. 古い run を止め、新しい会話を起こす（`startOrchestrator`）。
4. hangar が記録から引き継ぎを作り、新しい統括の最初の入力（`[hangar]`）にする。中身：前の統括の会話 id、統括が起こした・送った会話のうち動いているもの（id と題名）、預かり中の問い、許可の方針、利用者の最近の言葉 3 つ（前の会話の利用者の入力の末尾から）、古い統括のメモ（あれば）。
5. history を更新し、柱へ状態を配る。

### 4. 役の文

- 足す：「今の会話に無いことを指されたら、答える前に `search_sessions` で前の統括の会話（引き継ぎにある id）とほかの会話を調べ、要るなら `get_transcript` で読む。見つからなければ、見つからなかったと言う。」
- 役の文の版（文のハッシュ）を run に記録する。アプリの起動時に、動いている統括の版が今の役の文と違えば、次の idle（預かりが空）で同じ会話を再開し直す（止めて `resumeWith`）。会話は切り替えない。

### 5. 太ったとき

- 自動の切り替えは、1〜4 が入ってから入れる。それまでは今の `/compact` のまま。
- 入れたあとは、`feed.ts` の `checkCompact` の `/compact` を、切り替え（`reason: auto`）に置き換える。閾値と idle の長さは今の値（15 万、2 分）から始め、実物の統括で 1 回切り替わるのを見て決め直す。

### 6. 柱の操作（試作 A）

- 開いた柱の右上の丸（今は閉じる）を押すとメニューが開く。閉じるは ⌥⌘J と、メニューの「柱を閉じる」。
- メニューの並び：先頭に状態の 1 行（考えています、待っています、止めました、止まりました（10 分に 3 回失敗））と文脈の量の細い棒。その下に「新しい会話で始め直す」「止める」または「起こす」、区切って「柱を閉じる」。
- 文脈の量の棒は、15 万を超えると作業中の色（`--busy`）になる。
- 補助のラベルや説明文は足さない。
- 動き：メニューは丸を支点に `growIn`、閉じるは `collapseOut`。切り替えると、今の会話の行が `collapseOut` で畳まれ、区切りの線が `fadeIn` で入り、新しい会話の行がその下に積まれる。棒の幅は `resizeFrom` 相当の幅の動き、丸の色は今のトークンの遷移。
- 畳んだ柱（右下の丸）は今のまま。

### 7. ローカル API

- `POST /api/orchestrator/fresh`（切り替え）、`POST /api/orchestrator/stop`（画面の停止と同じ。enabled は切らず、見張りは `stopped: user`）、`POST /api/orchestrator/wake`（止まった状態を捨てて再開）。
- 見張りの状態に `contextTokens` と、切り替え中（`switching`）を足す。

## 確かめ方

- 単体：枠（統括の URL で全プロジェクトの検索と一覧が返る、書く道具は断る、プロジェクトの URL からは統括が出ない）、系譜（切り替えで history に移る、上限、involved が系譜を含む）、切り替えの手順（メモあり、メモの時間切れ、古い統括が busy のまま）、役の文の版の違いで再開。
- 画面：メニューの開き閉じ、止まったとき、切り替えの動きを WebKit で撮る。
- 実物：Mac の統括で「新しい会話で始め直す」を押し、前の会話で話した件を新しい統括に聞いて、検索して答えるか見る。
