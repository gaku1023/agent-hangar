利用者が 2026-10-09 に試作から選んだ画面の構成を、実装できる形にまとめる。

## 1. 目的と範囲

目的は 2 つである。
全画面を選ばれた構成に作り替えることと、画面とサーバの文と注入の文を日英の辞書から出すこと（D5）である。

土台は段 2 と段 3 の骨格である。
サーバの側は、DB の書き込みを受け取って画面へ配る層（`db/notify.ts` と `events/publisher.ts`）と、資源ごとの経路（`http/routes/*.ts`）を使う。
UI の側は、`transition(state, store, input)`、Intent から API を引く表（`runtime/intentTable.ts`）、辞書の関数 `t()` を使う。
調べたのは 2026-10-09 の main（`3a1d50d`）に、プロジェクトと新しいセッションの試作の枝を合わせたものである。
この時点の main には、段 3 の PR 1、4、5、6、8、9 と、段 2 の PR 7、9 が入っている（マージの記録の枝の名前で数えた）。
段 3 の往復のイベントは一部が残っている。
段 2 の配る層と経路の分割（PR 1 から 6）はまだ入っていない（`events/` と `http/routes/` が無く、`http/app.ts` は 1,081 行のまま。`wc -l` で数えた）。
2.11 の小さい画面の決定は、2026-10-09 の main（`4c5cd37`）のコードで確かめた。

範囲は、ホーム、セッション画面、設定、プロジェクトの一覧、1 つのプロジェクトの画面、新しいセッションのダイアログ、サイドバーとヘッダー、Claude Code の設定の同期の作り直しに、小さい画面（コマンドパレット、知らせ、読み込みと失敗、始める前の確認、未解決のプロジェクト）を加えたものである。
色、書体、質感は変えない（2026-10-02 のデザイン調査で済んでいる）。
画面は常に明るい配色で、暗い配色は作らない。

## 2. 決めた構成

行数は `wc -l` で数えた、試験を除くソースの行数である。

### 2.1 画面の分け方とサイドバーとヘッダー（A）

- 画面は、ホーム、プロジェクトの一覧、1 つのプロジェクト、セッション、設定の 5 つになる。セッションの一覧の画面（`views/SessionsScreen.tsx` 114 行、`presenters/sessions.ts` 129 行）は無くなり、中身はホームの下半分へ移る。
- サイドバーの項目は「ホーム」「プロジェクト」の 2 つと「実行中」の節で、「設定」は下端に置く。いまは `presenters/shell.ts` の `NAV` が 4 項目（ホーム、プロジェクト、セッション、設定）を上から並べている。
- 節の名前は「動いている」から「実行中」に変わる（用語集 1 章）。並びを手で変える仕組みと、行の右クリックの「停止」はそのまま残す。
- ヘッダーの同期は状態を示すだけにする。`views/SyncStatus.tsx` の 2 つのボタン（今すぐ同期、同期を一時停止）を外し、状態の点と語と件数を残す。語を押すと設定の「クラウド同期」の節へ移る。
- 使用率のゲージ、アカウントの切り替え、「新しいセッション」、検索と移動の錠剤は今のまま残す。

### 2.2 ホーム（B）

いまのホーム（`views/HomeScreen.tsx` 293 行、`presenters/home.ts` 145 行）は、要対応、実行中、確かめる、最近を 1 列に積み、最近の下にプロジェクトの 1 行を置いている。

増えるもの。

- 上端の 40px の帯。要対応、実行中、確認待ちの件数を 3 つの錠剤で並べる。場所の不明なプロジェクトがあるときは、4 つ目の錠剤を足す（2.11.5）。
- 引き出し。押した群だけが帯の下に開き、1 件を 1 行で読む。朝に開いたときは要対応が開いている。要対応が無ければ実行中、それも無ければ確認待ちを開く。
- ステータスのタブ、検索の欄、絞り込みのボタンを持つ平らな一覧。タブと欄は常に出す。絞り込み（プロジェクト、期間、操作したファイル）は欄の横のボタンから出し、効いている条件の数をボタンに印で出す。
- 行の 2 段目の右端に、PR の番号とノートの印。
- 検索の結果の末尾に「さらに 50 件を読み込む」と残りの件数。
- 始める前の確認の要約と、直すものの引き出しは、初めての人だけでなく、直すものがある間は誰にでも出す（2.11.4）。一覧の空の札の「クイックセッションを開始」は、初めての人に残す。

移るもの。

- 要対応の札（入力待ちと今日のリマインダー）、実行中の札、確認待ちの札の中身は、引き出しの行へ移る。ボタン（ターミナルで回答、確定、却下、日付を変更、Done）は行に残す。
- セッションの一覧の画面のタブ、欄、チップ、条件の行、ページ送りは、ホームの一覧へ移る。
- 条件の無い一覧はページ送り（25、50、100、200。今の `mediator/paging.ts` のまま）にする。

変わる動き。

- 検索の最中は引き出しを閉じ、帯の件数だけを残す。
- 要対応も実行中も確認待ちも 0 のときは、帯の代わりに「実行中のセッションはありません」の 1 行と 2 つのボタンを出す（今の `idle` の行と同じ）。
- 行は 2 段のままにする（利用者の決定）。試作の B は 1 行の行（44px）で描いているので、見える行は減る。これは受け入れる。
- 窓の高さ 800 で見える行の数は、試作の B の見立てから数え直すと次のとおりである。試作は、忙しい朝に帯 40px と要対応の引き出し 6 行（270px）で上を 310px に止め、その下に 1 行の行が 5 行見えるとしている。行に使える高さは 44 × 5 で約 220px なので、2 段の行（今の `SESSION_ROW_H` は 56px）では 3 行になる（220 ÷ 56 は 3.9）。ふつうの朝（要対応 2 件）は、引き出しが 4 行ぶん（40 × 4 で 160px）短くなって約 380px が空き、2 段の行で 6 行になる（1 行の行なら 8 行）。どちらも試作の数からの見立てで、実際の数は PR 6 で撮って確かめる。

### 2.3 セッション画面（C）

いまのセッション画面（`views/SessionScreen.tsx` 366 行、`views/LivePane.tsx` 216 行、`presenters/session.ts` 395 行、`presenters/live.ts` 149 行）は、見出しの下に情報の行、左にターミナル、右に「いま」と目次を縦に割った右パネルを置いている。

増えるもの。

- ターミナルの真上の 2 行の帯。1 行目は状態の語と問い、右端にいまの値（コンテキスト使用量、コスト）と「ノート」の小さな札。2 行目は意図、ツール呼び出しの並び、サブエージェントとアーティファクトの数の札。
- 帯の「ノート」の札は、押すとポップオーバーが開き、そこでノートを読み書きする。中身があれば札に印を付ける。
- 他の PC で実行中の印（ロック）の札。見出しの名前の横に出す。操作できない理由なので、ポップオーバーには隠さない。
- 見出しの右端の (i) と、属性のポップオーバー（モデル、effort レベル、権限モード、開始、作業ディレクトリ、アカウント、起動、ターンとトークン、変更の数、PR、クイックセッションの印）。
- 終わったセッションの、トランスクリプトの冒頭の 1 枚。ステータスの札と終了とコスト、要約、次のステップ、変更したファイル、アーティファクト、PR、ノートを 1 枚にまとめる。ノートは、この 1 枚の中のノートの所で編集する。
- 終わったセッションの目次。いまは実行中にしか出ない。

移るもの。

- 右パネルの「いま」の段（灯、意図、メイン会話のツール呼び出し、サブエージェントのレーン、アーティファクト）は帯へ移る。レーン 1 本ずつとアーティファクトの一覧は、帯の数の札を押して開く。
- 終わった画面の右パネルの要約と変更したファイルは、冒頭の 1 枚へ移る。

変わるもの。

- 右パネルは目次だけの 240px になり、実行中も終わった後も同じ場所に同じものがある。⌘J の開閉は残す。
- 900px の窓では、目次の列をタブの列の「目次 N」の札に畳み、帯を 3 行に折り返す。

情報の行（`InfoLine`）の行き先は次のとおりである。
いまの行は、条件つきのものを含めて 15 種類の印を並べている（`InfoLine` の JSX の要素を数えた。試作の文は 11 項目と数えている）。

| いまの印 | 行き先 |
| --- | --- |
| 状態と経過 | 帯の 1 行目の左 |
| コンテキスト使用量、コスト | 帯の 1 行目の右。終わった後は冒頭の 1 枚の 1 行目 |
| ターンとトークン | (i) のポップオーバー。終わった後は冒頭の 1 枚の 1 行目にも出す |
| モデルと effort レベル、開始、作業ディレクトリ、アカウント | (i) のポップオーバー |
| PR | (i) のポップオーバー。終わった後は冒頭の 1 枚の札にも出す |
| アーティファクト | 実行中は帯の数の札、終わった後は冒頭の 1 枚の札 |
| 変更の数 | (i) のポップオーバー。終わった後は冒頭の 1 枚の札にも出す |
| ノート | 実行中は帯の右端の「ノート」の札とそのポップオーバー。終わった後は冒頭の 1 枚の中で読み書きする |
| ロックの文（他の PC で実行中、応答がありません） | 見出しの名前の横の札 |
| トランスクリプトは他の PC にあります | 見出しの名前の横の札。再開とフォークを押せない理由なので、ロックと同じ扱いにする |
| ステータスで停止した知らせ | 終わった後の冒頭の 1 枚の 1 行目（今の「終了」の語の場所） |
| クイックセッションの印、要約のみ、トランスクリプトがありません | クイックセッションの印は (i) のポップオーバー。残りの 2 つは冒頭の 1 枚の 1 行目 |

### 2.4 設定（S1）

いまの設定（`views/SettingsScreen.tsx` 523 行、`presenters/settings.ts` 170 行）は、5 つの群（必須、連携、要約器、同期、情報）を 1 枚に縦に並べ、左の目次はスクロールの位置を示している。

- 節は 6 つになる。一般、クラウド同期、連携、要約エンジン、ツール、情報である。左の目次で切り替え、右は選んだ節だけを出す。
- 目次の各行に、今の状態を 1 行添える（「クラウド同期　同期オフ」「連携　要修正 2」の形）。
- 「一般」の先頭が言語の切り替え（日本語、English）である。押した瞬間に画面の全部が切り替わり、保存のボタンも再起動も要らない。「一般」には通知、ターミナルアプリ、トランスクリプトの保持も置く。
- 「クラウド同期」は 1 頁に、状態の 1 行、操作（今すぐ同期、同期を一時停止、参加トークンを表示）、PC の一覧、Claude Code の設定の同期、Cloudflare の使用量と料金を上から並べる。上限で退いているとき（無料枠で停止、再試行待ち）は、状態の札と、使用量の上の理由とリセットの時刻の帯で示す。月の予算の行は出さない（段 5）。
- 同期を使っていない人には、1 文の説明と 2 つのボタン（クラウドを用意して始める、参加トークンで参加）と、押せないスイッチの 1 行だけを出す。2 つのボタンは、段 5 まではターミナルで打つコマンドを出す。
- 「連携」は、Claude Code との互換性、MCP サーバー、ステータスライン、シェル連携、アカウントである。「ツール」は、プロジェクトの親フォルダと 4 つのパスである。「情報」は、使用量、索引、この PC である。

節の移り方は次のとおりである。

| いまの群と節 | 新しい節 |
| --- | --- |
| 必須（ワークスペース、ツール、Node） | ツール |
| 連携（互換、MCP、statusline、外のターミナル、アカウント） | 連携 |
| 連携（通知） | 一般 |
| 要約器 | 要約エンジン |
| 同期 | クラウド同期 |
| 情報（使用量、索引、この PC） | 情報 |
| 情報（会話の保持） | 一般 |
| （無い） | 一般の先頭の言語 |

### 2.5 設定の同期の流れ（a1、b1、c2、d1、e2）

仕組みは `2026-10-09-config-sync-rebuild-design.md` のとおりで、ここは画面だけを書く。

- (a) 送るものの一覧（1 台目でスイッチを入れたとき）：種類ごとの折りたたみ。見出しに件数、`settings.json` は鍵と値を出す。
- (b) 適用内容の確認（2 台目）：操作ごとの折りたたみで、競合、削除、上書き、新規の順に置く。各群の見出しに、その操作で何が起きるかを 1 文で書く。「適用…」を押すと、殻がネイティブの確認を出す（D9）。
- (c) 届いたスキル、コマンド、エージェントの承諾：1 本の表にチェック。フックとコマンド実行の印が無い行だけを「まとめて選択」でき、印のある行は中身を開いてから 1 件ずつ選ぶ。「すべて選択」は置かない。選んで「適用…」を押すと、サーバが選択を「適用の指示書」として hangar の置き場に書き、殻がそれを読んでネイティブの確認を出す（4.2 の 13）。
- (d) 競合：1 件を 1 枚の札にし、差分を最初から出す。採用した側に「採用済み」を添える。
- (e) 送らなかったもの（落とした権限の規則、秘密らしい文字列のあった項目）：同期の節に「送らなかった項目 N 件」の行を常に置き、開くと理由と「それでも送る」を出す。送った直後は、ベルの一覧に 1 行入れて知らせる（2.11.2）。試作の e2 は通知カードだったが、右下の札を入力待ちだけにする決定に合わせて、置き場をベルに替えた（利用者の決定）。
- 「自動で適用」に切り替えるときは、その場に 1 文の注意と、キャンセル、自動にする、を出す。

### 2.6 プロジェクトの一覧（P1）と 1 つのプロジェクトの画面（Q3）

いまの一覧（`views/ProjectsScreen.tsx` 30 行、`views/ProjectCard.tsx` 45 行、`presenters/projects.ts` 64 行）は、ステータスの節ごとにカードの格子を並べている。

- 一覧は 1 行 1 プロジェクトの表になる。列は、ステータスの札、名前と場所、いま（入力待ち、実行中、確認待ち、TODO、リマインダー）、セッションの数、最後の活動、「…」である。
- 「いま」のリマインダーは、そのプロジェクトのセッションに付いたリマインダーのうち、いちばん近いものの日付である。無ければ出さない。プロジェクト自身はリマインダーを持たない。
- 節は Active、Paused、Done の順で、該当の無い節は見出しごと出さない。Archived は末尾の 1 行から開く。
- 場所は、プロジェクトの親フォルダの外にあるときだけ出す。この PC でパスが見つからないときは赤い札を出し、そこから「場所を再指定」へ進む。
- プロジェクトが無い人には、空の状態の 1 枚（何ができるようになるかの 2 文、「新しいプロジェクト」、クイックセッションを昇格する入口）を出す。

いまの 1 つのプロジェクトの画面（`views/ProjectScreen.tsx` 51 行、`presenters/project.ts` 72 行）は、左に節で読む一覧、右に TODO とメモとアーティファクトを置いている。

- 左の一覧を、ホームと同じ部品（ステータスのタブ、検索の欄、平らな行、ページ送り）に替え、このプロジェクトで絞る。
- 右パネルは TODO、ノート、アーティファクトのままである。TODO の見出しに確認待ちの数の札を足す。
- 見出しに (i) を足し、ポップオーバーに場所、セッションの数、最後の活動、場所を再指定、パスをコピー、名前を変更、一覧から削除を置く。試作にある「作成」の行は出さない（プロジェクトは作成日を持たない）。
- 見出しのステータスの選択、「VS Code で開く」「ターミナルで開く」、場所の行、右パネルの開閉は今のまま残す。

### 2.7 新しいセッションのダイアログ（N2）

いまのダイアログ（`views/NewSessionDialog.tsx` 334 行）は、プロジェクト、アカウント、名前、初期プロンプト、畳んだ詳細の順に並べている。

- 開いた直後の主役は、焦点の入った大きな初期プロンプトの欄（150px）である。
- 欄の下の 1 行に、プロジェクト、アカウント、モデル、effort レベル、権限モード、worktree の札を並べ、最後に「＋」を置く。どの札も、押すと小さい一覧が開く。値は常に札に見える。
- プロジェクトの札は今の `Listbox`（クイックスタート、最近、操作の段）を開く。選んでいなければ札は「クイックセッション」と言い、何も選ばずに ⌘↵ で始められる。
- 名前と追加ディレクトリは、札の列の最後の「＋」から足す。押すと、名前の札と追加ディレクトリの札が増える。値が入っているとき（下書き、前回の値）は、はじめから札を出す。添付があるときに追加ディレクトリを自動で足す今の振る舞いは保つ。
- 権限モードは縦の一覧にする。既定、Plan、Manual、Accept edits、Auto、Don't ask の順に並べ、線の下に Bypass permissions を赤い字と警告の印で置く。前回の値には「前回」を添える。
- Bypass permissions を選ぶと、札が赤い縁になり、起動のボタンが赤い「Bypass permissions で起動」になる。確認のダイアログは足さない。
- 前回の値で開いたときは「前回と同じ」と「既定に戻す」を札の下に出す。

#### 2.11.2 知らせ

いまの作りは次のとおりである（コードで確かめた）。
右下に積むものは、入力待ちのカード、戻る時刻を過ぎた札、通知の誘い、`error` と `info` のトーストで、`presenters/toasts.ts` と `views/ToastStack.tsx` が組む。

OS の通知は、窓が背面にあるとき、入力待ちと戻る時刻を過ぎた Paused に出している（`runtime.ts` の `notifier.show`）。
更新の案内の仕組みは無い（殻の `Cargo.toml` と `tauri.conf.json` に updater が無い）。

変わること。

- ヘッダーにベルを置く。押すと知らせの一覧が開く。ベルの数は未読の数である。
- 一覧に入るものは、今日のリマインダー、同期の失敗や一時停止、Claude Code との互換性の変更点、保持期間、設定の同期で送らなかった項目、更新の案内の 6 種類である。閉じても残る。行から、該当する設定の節へ移る。

- 6 種類のうち 4 つは、今ある事実から作れる。同期は `SyncStatusBody.state` と `error`、互換は `ReadinessDto.compat` と `GET /api/compat`、保持期間は `RetentionDto`、リマインダーは Paused のセッションの `returnOn` と `returnTime` である。送らなかった項目は、設定の同期の作り直しで足す `ConfigSyncDto` の件数から作る（4.2 の 14）。件数が 0 に戻れば行も消える。だから、一覧の行は事実から Presenter が組み、一覧そのものは保存しない。

#### 2.11.3 読み込みと失敗の画面

いまの作りは次のとおりである（コードで確かめた）。
殻の読み込みの頁（`apps/desktop/loading/index.html` と `boot.js`）は、`#status` に殻が書く 1 本の文字列を、赤い等幅で出す。
失敗の文は殻（`lib.rs`）が組む固定の文で、`status_js` が `#status` の `data-level="error"` に流す。ボタンは「もう一度試す」（殻の命令 `retry_boot`）と「ログを開く」（`open_log`）の 2 つである。
サーバが失敗の理由を殻へ渡す道は無い。サーバは `console.error(e)` を出して `process.exit(1)` するだけで（`main.ts`）、出力は殻が `desktop.log` に追記している。殻が知るのは「子が死んだ」ことだけで、`ReadyWait::Died` と `wait_for_server` の固定の文に落ちる。
5 種類の失敗の、いまの検出は次のとおりである。

| 失敗 | いまの検出 |
| --- | --- |
| サーバが起きない | 殻が子の死を見て、固定の文（「サーバが起動直後に終了しました」）を出す。理由は区別しない |
| ポートが使われている | 区別できない。`judge_existing` は hangar ではない応答を「居ない」と読み、子を起こし、サーバが listen に失敗して死ぬので、上と同じ固定の文になる |
| 互換の版が合わない別のサーバ | 区別できる。`Existing::Mismatch` を `refusal_message` が文にしている（版の数と `lsof` の命令を含む） |
| DB が古い | 起こらない。いまのマイグレーションは足し算の列で、古さを断る下限が無い。段 2 の PR 10（起点に畳む）が、起点より古い DB を断る |
| DB の控えが取れない | サーバが `DbBackupError` を投げる（`db/backup.ts`）。理由の文は `desktop.log` に入るが、殻は子の死としてしか見ない |

変わること。

- 失敗を 1 枚の札にする。ロゴは左上に小さく退ける。札の中は、見出し、何が起きたか、番号つきの次にすること、コピーできる命令、詳細（最初から開いた記録。「全文をコピー」つき）、札の下端のアプリの版と OS、「ログを開く」「もう一度試す」の順に並べる。読み込み中の絵は変えない。
- 命令と詳細だけを等幅にし、地の文は普通の書体にする。ポートと互換の失敗では、動いているサーバを止めない（利用者が起こしたものかもしれない）ことを文で言う。
- 殻は失敗の「種類」「何が起きたか」「次にすること」「記録」を別々に持ち、頁が並べる。1 本の文字列に改行で詰めるのをやめる。

| 失敗 | 何が起きたか | 次にすること | コピーできる命令 |
| --- | --- | --- | --- |

サーバが失敗の理由を殻へ渡す道（案）。

- サーバは、起動に失敗したとき、`<HANGAR_HOME>/boot-error.json` に `{ kind, params, detail }` を書いてから終わる。`kind` は上の 5 種類の名前、`params` は版の数やパス、`detail` は例外の文である。文章は書かない（D5 で、文は辞書から出すため）。
- 殻は、子の死を見たとき、このファイルを読んで種類を決める。読めなければ「サーバが起きない」に落とす。ポートが使われている失敗は、サーバが listen の `EADDRINUSE` を `kind` に写す。互換の版の合わない別のサーバは、今のとおり殻が自分で決める。
- 殻の読み込みの頁は、サーバの頁ではなく `apps/desktop/loading/` の静的な頁で、UI の辞書を持たない。この頁用の小さい日英の文の表が要る。言語は、設定ファイルの `language` を殻が読んで渡す（推測。殻が設定ファイルを読めるかは PR 31 で確かめる）。
- アプリの版は殻が持つ。OS の名前と版は殻が実行時に読む（推測。取り方は PR 31 で決める）。

#### 2.11.4 セットアップの確認

いまの作りは次のとおりである（コードで確かめた）。
`views/Onboarding.tsx` の確認リストは、セッションもプロジェクトも無い人にだけ出る（`presentOnboarding`）。内容は `GET /api/readiness` が返す `ReadinessDto` で、`presentChecks` が行にする。
行は最大 6 つ（tmux、claude、ワークスペース、MCP、statusline、Claude Code との互換）である。MCP と statusline は任意の行（`soft`）である。
`GET /api/readiness` を取るのは、セッションが 0 件のときと設定を開いたときだけである（`runtime.ts`）。

変わること。

- ホームの帯に、確認の要約（「6 つ中 3 つ」の形）を置く。直すものがある間は、初めての人だけでなく誰にでも出す。このため、`GET /api/readiness` を起動のたびに取る。
- 引き出しには、直すものだけを 1 行ずつ出す（1 行 36px）。行は、名前、説明、右端のボタン 1 つである。ボタンは、いまは「設定を開く」（親フォルダ）か「コマンドをコピー」（MCP、statusline。命令は `ReadinessDto.commands`）。命令は行の中に薄く見せる。

- 全部そろったら、帯ごと消える。残りが任意の行（MCP、statusline）だけになったときも、帯ごと消す（利用者の決定）。使わないと決めた人の帯が消えなくなるのを避けるためである。任意の行は、設定の「連携」に残る。帯の要約の分母は、任意の行を含めて数える。そろったときに、トーストを 1 回出す（「再確認」が通ったことは操作の結果にあたる）。設定の「情報」のセットアップの確認は残り、そこから「再確認」を押せる。

#### 2.11.5 未解決のプロジェクト

いまの作りは次のとおりである（コードで確かめた）。
サーバは、起動時と一定の間隔（`ROOT_CHECK_MS`）で、この PC の `project_roots` を調べ、パスが消えた行に対して `project.unresolved` を流す（`checkProjectRoots`）。
UI は、起動のたびに `bootstrap` の中の、`path` があって `resolved` が偽のプロジェクトも、同じイベントに変えて流す（`runtime.ts`）。
受けた Mediator は、`unresolvedQueue` に積み、1 件ずつ `ResolveProjectDialog` を開く。このダイアログは決めるまで閉じられず、閉じるのは「あとで」だけである（同じ起動のあいだ聞かないよう `resolveDeferred` に覚える）。
他の PC から降りたプロジェクトで、この PC に `project_roots` の行が無いものは、`checkProjectRoots` が見ないので `project.unresolved` を出さない。いまはダイアログの対象外である。

変わること。

- 作業中にダイアログを出さない。起動時にも、同期の直後にも出さない。`project.unresolved` を `Overlay` に変える道（`overlay.ts` の `openResolve`、`unresolvedQueue`、起動の読み直しの流し込み）を外す。
- ホームの帯に「場所の不明なプロジェクト N」の錠剤を足す（要対応、実行中、確認待ちに続く 4 つ目）。引き出しは 1 件 1 行で、名前、セッションの数、他の PC の名前、前のパス、「場所を再指定」「Archived にする」「一覧から削除」を置く。
- 「場所を再指定」を押したときだけ、ダイアログを出す。中身は今のとおり（前のパス、親フォルダの候補、フォルダの選択、新しいパス、Archived にする、一覧から削除、あとで）。押して開くので、閉じる手（Esc、背景、×）を持たせる。「一覧から削除」は取り消せず、同期で他の PC からも消えるので、危険色のまま確認を挟む。
- 同期で他の PC のプロジェクトが降りた直後は、トーストを 1 枚出すだけにする（「他の PC のプロジェクト N 件が届きました」。「プロジェクトで見る」「あとで決める」）。降りたことは `project.upsert` で分かる見込みだが（推測。段 2 の配る層が同期の apply から配るかは PR 33 で確かめる）、起動の読み込みで入るものはトーストにしない。
- 帯の件数に入れるのは、この PC で場所が消えたものだけにする（利用者の決定）。他の PC から届いただけで、この PC に場所を持ったことが無いものは、数えない。数えると、2 台で使う人の帯が消えなくなるからである。試作の B の絵は、他の PC の名前を引き出しの行に出しているが、件数からは外す。
- 他の PC から届いただけのものは、プロジェクトの一覧に「この PC にパスがありません」の札で出し、そこから「場所を再指定」を押せる。この PC で場所が消えたものも、決めないまま残せば、帯の錠剤と、プロジェクトの一覧の同じ札に残る。

### 4.3 URL の扱い

`#/sessions` と `#/sessions?q=` は、殻のディープリンクと、利用者の履歴に残っている。
`parseRoute` はこの 2 つを読み続け、`{ name: 'home' }` と `{ name: 'home', q }` を返す。
`formatRoute` は `#/` と `#/?q=` を書く。
殻の `deeplink.rs` は今の形のままでよい。

### 4.4 UI の状態の増減

- 引き出しのどれが開いているかは、View の中に持つ。Presenter は「朝に開く群」だけを決める。段 3 の決まり（Presenter と Mediator が読まない一時の状態は View へ）による。
- 検索の語、絞り込み、ページは、今の `State.search` のまま使う。画面がホームのときにサーバの検索を呼ぶよう、`mediator/screen.ts` で画面の名前の `'sessions'` を見ている 4 か所を替える。

- `State.sectionsOpen` と `project.section.toggle`、`presenters/sections.ts` の節の組み立ては、ホームとプロジェクトの画面の両方が平らな一覧になった時点で消す。

- ベルが開いているか、確認の引き出しの行が畳まれているかは、View の中に持つ。ベルの既読の鍵は localStorage に残し、起動時に読み戻す（2.11.2）。

## 5. 言葉

- 画面の文は辞書の鍵で書く。鍵は `画面.部品.意味` の形にする（例：`home.band.attention`、`list.search.placeholder`、`session.strip.contextUsage`、`settings.toc.cloudSync`、`launch.permission.startBypass`）。画面をまたぐ文は `common` に置く。
- 日本語と英語は同じ PR で同時に入れる。辞書は `Record<MessageKey, string>` なので、片方だけでは型検査が通らない。
- 画面 1 枚の PR で、その画面の文を全部鍵へ移す。直に書いた日本語を残さない。
- 用語集の「今の画面の語」から変わる語は、その画面の PR で変える。語だけを先に替える PR は作らない。
- データから作る文は Presenter が `translatorOf(store)` で引き、View が持つ決まった文は `useT()` で引く（段 3 の PR 6 の仕組み）。
- ステータスの札、権限モードの表示名、公式の語（Claude Code、MCP、LM Studio）は辞書に入れず、定数のまま両方の言語で同じ表記にする。
- 読み上げの名前（`aria-label`）は、見えている文字を含める（用語集の方針 7）。鍵は見える文と別に持ち、見える文を引数で受け取る形にする。
- 殻の読み込みの頁（`apps/desktop/loading/`）は、UI の辞書を使えない静的な頁なので、失敗の札の文だけを入れた小さい日英の表を、頁の側に持つ（2.11.3）。鍵は `boot.fail.<種類>.<段>` の形にし、UI の辞書と同じ用語集の語を使う。
- 辞書は画面ごとのファイルに割る（`i18n/ja/home.ts` など。1 つの `Dictionary` に束ねる）。いまの 1 ファイルのままでは、並行する PR が同じ行でぶつかる。これは PR 1 で行う。

量の目安として、いまの UI で日本語を含む行は、`views` に 603 行（89 ファイル）、`presenters` に 238 行（35 ファイル）ある。
数え方は、試験と注釈の行を除き、文字列か JSX の文に日本語の文字がある行である（手元のスクリプトで数えた）。
多い順に、`SettingsScreen.tsx` 109 行、`SessionScreen.tsx` 43 行、`NewSessionDialog.tsx` 42 行、`HomeScreen.tsx` 32 行、`ConfirmDialog.tsx` 31 行である。
1 行に複数の文があることも、同じ文が重なることもあるので、鍵の数はこの行数と一致しない。

試験の扱いは段 3 の決まりのとおりである。

- 日本語の文を直に見ている試験は、日本語の辞書で走らせる。View だけを描く試験は、言語の頂点が無ければ既定の日本語になる。
- 書き換えるのは、文が変わった所だけにする。語が用語集で変わった画面では、その画面の試験の期待の文も同じ PR で替える。
- 鍵で見るのは、同じ語を別の意味に使っていないことを確かめる用語の試験だけにする。
- 画面を作り替える PR では、その画面の試験を、層ごとの大きなファイル（`presenters.test.ts`、`screens.test.tsx`、`misc.test.tsx`）から画面ごとのファイルへ移す。全体計画の「触った機能の分だけ移す」による。並行する PR が同じ試験のファイルでぶつかるのも減る。
- 最後の PR で、UI のソースに日本語の直書きが残っていないことを確かめる禁則の試験を 1 本足す。

言語の切り替えの行は、設定の PR では作るだけにして、見えるようにするのは最後の PR にする。
辞書が埋まる前に English を選べると、半分だけ英語の画面を利用者に見せることになるからである。
それまでは、設定のファイルの `language` の値だけで切り替わる（開発と確かめのための道）。

## 6. PR の割り方

各 PR は単独で動き、main に入れたあとアプリを入れ替えられる。
画面が半分だけ新しい状態を見せないために、次の 3 つを守る。

- 新しい部品は、古い画面を残したまま先に入れる。その PR では画面に付けないか、付けても見た目を変えない。
- 画面の切り替えは 1 つの PR で行う。セッション画面は、実行中と終わった後を同じ PR で替える。
- ホームの切り替えと、セッションの一覧の画面を消すことと、サイドバーの項目を減らすことは、同じ PR で行う。

見た目の確かめ方の「重ねて撮る」は、動いているアプリの実データに、その枝の `packages/ui/dist` を重ねて WebKit で撮ることを指す。
読むだけにし、ボタンは押さない。
サーバの経路を足す PR は、重ねるだけでは新しい経路が無いので、DB の写しを置いた別の `HANGAR_HOME` でその枝のサーバを起こして撮る。

## 9. 指揮役が決めた細部（2026-10-09）

設計書を書いていて見つかった、試作と選ばれた案だけでは決まらない点である。
どれも指揮を執るセッションの判断で、利用者には事後に知らせる。
利用者が違うと言えば直す。
答えは上の該当の節に反映してある。

1. **言語の切り替えは、最後の PR（25）まで画面に出さない。** 辞書が埋まるまでは、English を選ぶと半分だけ英語になるからである。それまでは、設定のファイルの値だけで切り替わる（5 章）。
2. **ホームの一覧は 2 段の行のままにする。** 利用者の決定である。試作の B の見立てから数え直すと、窓の高さ 800 で見える行は、忙しい朝に 3 行、ふつうの朝に 6 行で、1 行の行より減るが、これは受け入れる（2.2）。
3. **セッションのノートは、実行中は帯の右端の「ノート」の札のポップオーバーで、終わった後は冒頭の 1 枚の中で編集する。** いま編集できるのはプロジェクトの画面の行の鉛筆だけで、Q3 でその行がホームと同じ部品になると場所が無くなるからである（2.3、2.9 の 17）。
4. **他の PC で実行中の印（ロック）は、見出しの名前の横に札で出す。変更の数、ターンとトークン、作業ディレクトリなどの属性は (i) のポップオーバーに入れる。** ロックは操作できない理由なので隠さず、属性は毎回見るものではないからである。この考え方で、「トランスクリプトは他の PC にあります」は見出しの札に、PR とクイックセッションの印はポップオーバーに置いた（2.3 の表）。
5. **新しいセッションの名前と追加ディレクトリは、札の列の最後の「＋」から足す。** 札の列を 6 つに保ち、たまにしか使わない 2 つを裏に置くためである。添付があるときに追加ディレクトリを自動で足す今の振る舞いは保つ（2.7）。
6. **プロジェクトにリマインダーと作成日は足さない。** プロジェクト自身はどちらも持たず、DB に足すと同期で運ぶ形が変わるからである。一覧の「リマインダー」は、そのプロジェクトのセッションのいちばん近いものを出し、ポップオーバーの「作成」は外す（2.6、4.1）。
7. **Cloudflare の月の予算で止める機能は、段 4 の設定の画面に入れない。** D4 の歯止めは、段 5 で使用量の表示と一緒に作ると段 1 の設計書が決めているからである。同期の節には、使用量の表示と、上限で退いているときの状態だけを出す（2.4、8 章）。
8. **用語集の「設定の群」と「ホームの区画」などの語は、その画面の PR で、選ばれた構成に合わせて用語集の側を直す。** 構成は試作が正で、用語集はそれより前に書いた下書きだからである。直す語は 2.10 の表にある。
9. **承諾した項目は、サーバが hangar の置き場に書く「適用の指示書」で殻へ渡す。** サーバは `~/.claude` に書かず、書くのは、指示書を読んでネイティブの確認を出した殻の命令と CLI だけなので、D9 を守れる。指示書は、適用が済むか取り消したら消す（4.2 の 13 とその下）。
10. **設定とプロジェクトの画面の 900px の絵は、試作を足さない。** 構成は決まっていて、残るのは畳み方の細部だからである。実装の PR で 900、1280、1440 の幅で撮って確かめ、崩れたらその PR で直す（7 章）。

## 10. まだ決まっていない点

- 殻の読み込みの頁が、設定ファイルの `language` を読めるか。読めなければ、頁は OS の言語で選ぶ（PR 31 で確かめる）。
