畳んだ形を考え直す — 3 案（と今の形）

どれも実際に開閉できます（ヘッダ左端のボタン、または窓の上で ⌘B）。本文には端末を置き、窓の下に「本文の幅」と、開いたときより何桁ぶん端末が広がるかを出しています。上の帯で窓の幅を変えられます（デスクトップの最小は 900px）。気に入った案の枠をクリックで選択。

畳む意味が薄く感じる理由（見立て）
  • 増える幅が 120px しかない。窓 900px だと本文 676 → 796px、端末で約 16 桁。
  • 畳んでも、図・アイコン・項目名が全部残っている。消えるものがなく、同じものが縦に詰まっただけなので、「畳んだ」手応えがない。
  • 帯の幅 88px は信号の 3 点（x 22〜82px）で決まっている。帯のまま細くするなら、3 点を帯の外（ヘッダの行）へ出すしかない。
窓の幅 ⌘B はマウスを載せた窓に効く

Sアイコンだけの細い帯（52px）

図と項目名を捨て、アイコンだけを残す。信号の 3 点が収まらないので、畳むとヘッダが左上まで伸びて 3 点を受け持ち、帯はヘッダの下から始まる。アイコンに乗せると名前が出る。どの画面にも 1 クリックのまま。

H消して、ナビはヘッダへ（0px）

サイドバーは消え、4 つの行き先はヘッダ左の小さな切り替え（Home / Projects / Sessions / Settings）に移る。畳む瞬間、アイコンが帯からヘッダへ飛んで収まる（M4 と同じ受け渡しの仕組みで作れる）。いまどこにいるかは見えたまま、本文は窓いっぱい。行き先が 4 つしかないから成り立つ形。

P消して、左端で覗く（0px）

サイドバーは消える。マウスを窓の左端に寄せると、開いたときと同じサイドバーが本文の上に重なって出る（離れると引っ込む）。ヘッダは何も増えず一番すっきりするが、いまどこにいるかはパンくずだけが頼り。
