原図は決めた段 0（端末を掛けたハンガーが右奥へ 4 本、奥ほど霞み、それぞれのカーソルが状態の色）。16px では先頭の 1 本だけにした別の図を使います。推奨で決めたこと：ブラウザのタブ（16px）の favicon は先頭 1 本の図、32px 以上は原図

4　動き

4-a動きのトークン（性格 B：なめらか）

すっと出て、長く静かに止まる。現れるときは「速く出てゆっくり止まる」曲線、消えるときは「静かに始めて速く去る」曲線を使い分けます。

4-b動きの一覧（今の 11 種をどう変えるか）

動き今これから
画面遷移120ms クロスフェード出る画面は 250ms で消え、入る画面は 420ms で、6px の移動とぼかしが晴れながら入る

5　試験と検証

5何で守り、どう確かめるか

見た目の変更は試験で守りにくいので、「決まり」を試験で固定し、見た目は実物で確かめるに分けます。

書き換える試験
  • tokens.test.ts：禁止の一覧を新しい決まりに合わせる。backdrop-filter はガラスの部品のクラスの中にだけ現れることを確かめる（読む面に紛れ込んだら落ちる）。ダーク、シマー、スケルトン、文字の影は引き続き落とす
  • コントラスト：本文と補足の文字が、白地とガラスを重ねた色の両方で 4.5:1 以上（ガラスの色は白 40% を地に重ねて計算する）
  • overlays.test.tsx などの、CSS の文字列を直接探している試験を、新しい規則に合わせる
足す試験
  • Home の Presenter：要対応・実行中の札が正しいセッションを拾う。問いの文、最新のツール呼び出し、文脈の使用率の取り出し方
  • 端末の縁：状態（busy・waiting・idle・終了）から正しい印が付く
  • 行を広げる動き：View Transitions が無い環境では、ふつうの画面遷移に落ちる。reduced motion では使わない
  • タイトルバー：窓を動かす権限が 127.0.0.1:4177 だけに、start-dragging の 1 つだけ与えられている（設定ファイルを読んで確かめる）
実物で確かめること
  • ブラウザと .app の両方で、全画面を目で見る（画面の写しを残す）
  • .app：信号の 3 点の位置、ヘッダを掴んで窓が動くこと、起動画面の動き
  • 重さ：1,000 件の一覧のスクロールと、端末の出力が流れている最中に、ぼかしで引っかからないこと
  • reduced motion を有効にして、動きと光が止まること
進め方の決まり（いつもの作法）
  • 直したら返す前に必ずビルドする（UI の vite と、デスクトップの bundle-server ＋ tauri build）。ビルドしたら、利用者の npm run dev のサーバ（4177）を一度落とす（自分の PID だけ）
  • design.md の「画面」と「見た目と動き」を、実装と同じコミットの流れで書き換える
  • .superpowers/ を .gitignore に足す
