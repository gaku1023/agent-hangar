# セッション画面の動き 設計

## この文書の位置づけ

セッション画面（ターミナルが写る画面）の開閉と更新に、動きを足す設計である。
あわせて、左右の欄を畳んだときに空いた幅を本文が使い切るようにし、「いま」と目次の境目を自由に動かせるようにする。
見た目の試作は `2026-10-02-session-motion/motion-proto.html` にある。
操作盤の各欄で「今」と案を切り替えて比べられる。

実装が済んだら、本体の設計書 `docs/design.md` の該当箇所へ内容を移す。

## 目的

利用者の困りごとは次の 4 つである。

- 開いたとき、右の欄を閉じたとき、ターンが増えたときに、画面がその場で切り替わるだけで、何が変わったか目で追えない。
- 左のナビを畳んでも、帯が細くなるだけで本文は広がらない。
- 右の欄を閉じても、28px の列が残る。
- 「いま」と目次の境目を動かせる幅が狭く、目次を小さくできない。

うまくいった状態とは、次の 3 つがそろうことである。

- 画面に何かが入る・出る・動くとき、プロジェクト一覧と同じ語彙（ぼかしが晴れながら --rise だけ浮かぶ）で動き、どこが変わったか分かる。
- 左右のどちらの欄を畳んでも、空いた分をターミナルが使う。
- 境目は、見出しの 1 行を残す所まで、どちらへでも引ける。

## 利用者の決定（2026-10-02）

- 畳む対象は、左の全体のナビと右の「いま」の欄の両方である。
- 左のナビを畳んだとき、本文は帯のすぐ右から始める（左の余白 16px）。ヘッダのロゴの右端に揃える式は、本文には使わない。
- 右の欄を閉じたとき、列ごと消す。開くボタンは、閉じている間だけタブの帯の右端に置く。開いている間は今のまま欄の中に置く。⌘J は今のまま。
- 左右の欄が開閉してターミナルの幅が変わる間は、ターミナルを折り返さない。動きが終わってから 1 回だけ合わせる（今の左のナビと同じ）。
- 動かすもの：ターンの目次の新しい行、「いま」の意図と手、サブエージェントのレーンと成果物、見出し周りとタブ。
- 追加で動かすもの：開いた直後の空白、会話が終わったときの切り替わり、ターミナルの上の案内の帯、出ていくときの動き。
- 案の選択は、すべて試作のおすすめに従う。
  - 右の欄：A「下へ潜る」。
  - ターン：A「浮かぶ」。
  - 境目：B「引いた所が境目、端まで引くと畳む」。
  - 意図：A「入れ替え」。
  - 開いた直後：A「仮の行とふわっと」。
  - ほかは「動かす」。
- 動かさないもの：ターミナルの中身、毎秒変わる経過時間。

## 範囲

- セッション画面の実行中の形（ターミナルと右の欄）。
- セッション画面の終わった形（本文と右のまとめの欄）の右の欄の開閉。開閉の仕組みが同じなので揃える。
- 左のナビを畳んだときの本文の左の余白。これは全画面に効く。

範囲外は次の 3 つである。

- ほかの画面のトーストとダイアログの出ていく動き。
- ターミナルの中身の描き方。
- 動きのトークンの値の変更。今の値（--dur 420ms、--ease-out など）を使う。

## 共通の約束

- 長さと曲線は、すべて動きのトークン（`styles/tokens.css`）を通す。CSS にも JS にも数値を直書きしない（`styles/motion.test.ts` が見張る）。
- **入る形**：opacity 0、translateY(--rise)、blur(--blur-in) から入り、ぼかしは 20% で晴らし切る。長さは --dur、曲線は --ease-out。今の `enter` と `useFlip` と同じ形である。
- **伸びて入る形**：入る形に、高さ（タブは幅）を 0 から伸ばす動きを重ねる。下の行は押し下げられて滑る。リストの途中に入るもの（手、レーン、成果物、案内の帯、ターンの中身、タブ）はこちらを使う。
- **畳んで出る形**：薄れながら高さ（タブは幅）を 0 に畳み、終わったら外す。下の行は詰まって滑る。長さは --dur-exit と --dur-fast の和で、曲線は --ease-in。試作と同じである。
- 並びが変わった要素は、前の位置から滑らせる（FLIP、--dur、--ease-out）。
- 最初の描画では動かさない。画面に入る動き（`.screen` の enter）と View Transitions に任せる。
- reduced motion ではトークンが 0 になる。そのため、入る・出る・滑るがすべて即座になる。出る要素は 0ms で外れる。
- `el.animate` の無い環境（jsdom）では、何もせずに最後の形にする。

## 共通の部品

### `views/primitives/motionKit.ts`

キーフレームを作る関数を集める。
`useFlip` と `sidebarMotion` に散っている形を、ここから読むように寄せる。

- `riseIn(el)`：入る形。
- `growIn(el, axis)`：伸びて入る形。axis は 'y' か 'x'。
- `collapseOut(el, axis)`：畳んで出る形。Promise を返し、終わったら解決する。
- `flashHit(el)`：地を淡い黄（--hit）から薄れさせる。`.tr-flash` と同じ長さと遅れを使う。

### `views/primitives/useMotionList.ts`

リストの出入りをまとめるフックである。

```ts
function useMotionList<T>(items: T[], keyOf: (t: T) => string, opts: { enter: 'rise' | 'grow'; axis?: 'y' | 'x'; flash?: boolean }):
  { list: { item: T; key: string; leaving: boolean }[]; ref: (key: string) => (el: HTMLElement | null) => void };
```

- 前の描画に無かった key の要素は、入る形（または伸びて入る形）で入れる。
- 消えた key の要素は、すぐには外さない。`leaving: true` で最後の中身のまま描き続け、畳んで出る形が終わってから list から落とす。
- 残った要素は FLIP で滑らせる。
- 初回の描画では動かさない（今の `useFlip` と同じく、前の位置が空なら動かさない）。
- leaving の要素は `aria-hidden` にし、押せないようにする。

今の `useFlip`（プロジェクト一覧）は、これの enter: 'rise' で置き換えられる。
置き換えるかは実装の手間で決め、置き換えないなら両方を残す。

### `views/primitives/layoutMotion.ts`

左のナビにだけある「動いている間は端末を合わせない」仕組みを、右の欄と案内の帯にも使えるよう一般化する。

- 印を `data-layout-moving` に改める。付ける場所は、動いている箱（`.shell`、`.split`、`.session-body`、`.term-pane`）である。
- `TerminalPane` は、`el.closest('[data-layout-moving]')` が真の間は ResizeObserver の fit を見送る。
- 動きが終わったら `hangar:layout-settled` を出す（今と同じ）。端末はここで 1 回だけ fit する。
- `sidebarMotion.ts` の `MOVING_ATTR` と `LAYOUT_SETTLED` は、ここから読むように移す。
- 印で消している吹き出しの規則（`.shell[data-sidebar-moving] .toggle-tip` など）も、新しい名前に改める。

### `views/primitives/paneMotion.ts`

右の欄の開閉の動きである。左のナビの `playSidebarMotion` と同じく、前の形と今の形を同じ描画の中で測り、差を Web Animations で埋める。

- 列は `getComputedStyle(box).gridTemplateColumns` の計算値（px の並び）を前後で測り、`gridTemplateColumns` と `columnGap` を --dur、--ease-out で動かす。px どうしなので補間が効く。
  - 今の CSS の `transition: grid-template-columns` は、`minmax(240px, 26%)` と `28px` の間で補間されないので外す。
- 動いている間、箱に `data-layout-moving` を付ける。
- 欄の中身は、動きの間だけ開いたときの幅（px）に固定する。列が狭まっても中身は折り返さず、列の端に切られて「下へ潜る」。
- 閉じるとき：中身を --dur-exit、--ease-in で薄れさせ、ぼかす。列は 0 まで畳む。
- 開くとき：中身は、ぼかしが 35% で晴れながら --dur で現れる。

## 各箇所の振る舞い

### ① 左のナビを畳む

- 本文の左の余白 `--gutter-l` は、どの形でも `calc(var(--u) * 4)`（16px）にする。
- 今の式 `max(16px, head-end − col1 − box-l)` は、新しい変数 `--gutter-head` に移す。使うのはヘッダの検索欄（`.header-row > .search-pill`）だけにする。
  - 検索欄はヘッダの中でロゴの右に並ぶので、ロゴとの重なりを避ける式が要る。
- 畳むと、ほかの画面でも本文が帯のすぐ右から始まる。
  - そのため、畳んでいる間は本文の左端と検索欄の左端が揃わなくなる。これは利用者の決定による。
- 幅の広い窓で本文が中央に寄っている画面（--main-w 1200px）は、今と同じく中央のままにする。
- 動きは今の `playSidebarMotion` のまま。--col1 と一緒に --gutter-l も変わらなくなるので、本文の左端は帯の右端に付いて動く。

### ② 右の欄の開閉

- 閉じた形の列は `minmax(0, 1fr) 0px` で、列の間の隙間も 0 にする。28px の列は無くす。
- 欄の中身は、閉じる動きが終わるまで描き続ける（`usePresence` 相当の小さな状態を `SessionScreen` に持つ）。終わったら外す。
- 開くボタンの置き場所：
  - 閉じている間は、`TabStrip` の右端（`.tabs` の末尾）に置く。アイコンと「いま」の文字（終わった run では「ターン」）、⌘J の印を並べる。入る形で現れる。
  - 開いている間は、今のまま欄の見出しの行（LivePane の lead、TurnIndex の lead）に置く。タブの帯のボタンは、開き始めにその場で外す（目は開いていく欄に向くので、出る動きは付けない）。
- 終わった形（`.session-body` と `.session-rail`）も同じ `paneMotion` で開閉する。
  - 開閉のボタンは今のまま本文の面の右上（`.transcript-toggles`）に置く。列はもともと消える作りなので、置き場所は変えない。

### ③ ターンの目次

- 新しい行は、入る形で末尾に入る（`useMotionList`、enter: 'rise'）。
- 何も開いていない間は、末尾へ滑らかに追従する（`scrollTo({ behavior: 'smooth' })`）。
  - reduced motion と初回の描画では、今と同じく即座に追従する。
- ターンを開いたときの中身（`.turn-body`）は、伸びて入る形で開き、畳んで出る形で閉じる。寄せる動き（`revealWithin`）は、伸びた後の位置へ滑らかに動かす。
- 見出しの数（ターン N）は `RollingNumber` で回す。
- 古いターンを読み込んで先頭に足したときは動かさない（読み込みの結果で、新しい出来事ではないため）。
  - スクロールの位置は今のまま保つ。

### ④ 「いま」と目次の境目

- 境目は、上の段（`.live-top`）の高さの上限ではなく、高さそのものにする。
  - `flex: 0 0 calc(var(--live-split) * 100%)` に改め、`max-height` を外す。
  - 中身が短ければ、上の段の下に余白が残る。
- 比率の丸めを、0.2〜0.8 から 0〜1 に広げる（`clampLivePaneSplit`）。
  - 保存済みの値（0.2〜0.8）は、そのまま使える。
- 端の下限は CSS の min-height で持つ。
  - 上の段は、ランプの 1 行を残す。
  - 目次（`.live-toc`）は、見出しの 1 行と「最新へ」の行を残す。
  - 今の `min-height: calc(var(--row-h) * 5)` は外す。
- 離したときに、どちらかの端まで 24px 以内なら、その端へ畳む（比率を 0 か 1 にする）。
  - 畳む動きは、--live-split を `@property` で登録し、ドラッグしていない間だけ `flex-basis` に --dur の transition をかけて滑らせる。
  - ダブルクリックで既定の比率へ戻すときも、同じ transition で滑る。
- 上の段を畳んだ（比率 0）ときは、ランプの行だけを見せる。下の続きは、今と同じく下端のぼかしで示す。
- キーの ↑↓（2% ずつ）は今のまま。0〜1 の範囲で動く。

### ⑤ 「いま」の意図と手

- 意図の文が変わったとき（A「入れ替え」）：
  - 古い文は、上へ --rise だけ抜けながら、薄れてぼける（--dur-exit、--ease-in）。古い文は箱の中に重ねて描き、`aria-hidden` にする。
  - 新しい文は、入る形で現れる。開始は --dur-exit の半分だけ遅らせる。
  - 箱の高さは、古い高さから新しい高さへ --dur で滑る。
  - 古くなったときに薄くなる動き（stale の opacity）は今のまま。
- 手：
  - 新しい手は、伸びて入る形で入る。
  - 済んだ手の印（● から ✓）は、1 度だけ膨らむ。`StatusDot` と同じく scale で、長さは --dur。
  - 並びからあふれて落ちる手は、畳んで出る形で出る。
  - 手には安定した key が要る。今の `key={i}` を改め、`presenters/live.ts` で手ごとに key を持たせる。

### ⑥ サブエージェントのレーンと成果物

- 新しいレーンは、伸びて入る形で入る。
- 終わったレーンの色の変わり目（作業中から済み・失敗）は、`.live-lane` と `.live-lane-line` に --dur の transition をかけて滑らかにする。
- 並びから消えるレーンは、畳んで出る形で出る。
- 新しい成果物は、伸びて入る形で入り、地を淡い黄から薄れさせる（`flashHit`）。並びの残りは FLIP で滑る。

### ⑦ 見出し周りとタブ

- 要約の一行（`.session-oneliner`）は、初めて届いたときと文が変わったときに、左から 6px（--rise）浮かんで入る。
- 情報の行の数（コスト、変更、ターン、コンテキスト）は `RollingNumber` で回す。経過時間は回さない。
- タブは、足されたら幅を伸ばして入り、閉じたら幅を畳んで出る（`useMotionList`、axis: 'x'）。
- 分割の開始と終了（`SplitPane`）は、今の `.split-h` の transition のままにする。

### ⑧ ターミナルの上の案内の帯

- 信頼の案内、終了の案内、transcript の帯（「最新へ」）の 3 つが対象である。
- 出るときは伸びて入る形、消えるときは畳んで出る形にする。
- 帯の高さが変わる間は、端末の板に `data-layout-moving` を付ける。動きが終わってから 1 回だけ fit する。

### ⑨ 開いた直後

- 目次：最初の events が届くまでは、淡い仮の行（6 行、幅を少しずつ変える）を出す。届いたら、行を一度に入れて末尾へ即座に寄せる。そのあと一覧全体を --dur で薄れから現す。
  - 仮の行はゆっくり流れる光で示す。reduced motion では流さない。
  - 仮の行を出すのは `rows.length === 0 && loading` の間だけである。届いて 0 件なら、今の「まだ指示がありません」を出す。
- ターミナル：初めてつなぐときは、最初のデータが届くまで端末の面を透明にしておく。届いたら --dur で現す。
  - 届いたかどうかは、TerminalHost に「最初の描画が済んだか」の印を持たせて読む。
  - 「接続しています」は今のまま右下に出す。
  - 一度開いたタブ（xterm を付け替えるだけのとき）は、前の内容があるので透明にしない。

### ⑩ 会話が終わったとき

- 実行中の右の欄から「いま」の段が消えるとき：
  - 先にランプの色と文が終わりの形へ --dur で変わる。
  - 次に、見出し、上の段、境目が --dur-exit で薄れてぼける。
  - そのあと目次だけの形に替わる。目次は、前の位置から上へ伸びて滑る（FLIP）。
  - 消える間は、最後の `livePane` を描き続ける（②と同じく、出る動きが終わるまで外さない）。
- 再開して「いま」の段が戻るときは、逆の順にする。目次が下へ滑り、上の段が入る形で入る。
- 端末の縁の灯は、今と同じく状態の印で切り替わる。止まるときに急に消えないよう、`.term-pane` の `box-shadow` の transition（今ある）に任せる。
- 目次は、今の作りでは LivePane の中と外で親が替わり、作り直される。スクロールの位置が飛ばないよう、外へ出すときも同じ key で描く（親の替わらない形に組み直す）。

## テスト

単体テスト（vitest、jsdom）で確かめるもの：

- `clampLivePaneSplit` が 0〜1 に丸める。
  - `mediator/transition.test.ts` の 0.2 の期待を改める。
- `useMotionList`：消えた key を leaving として残し、`el.animate` の無い環境では次の描画で落とす。初回の描画は leaving も入る動きも出さない。
- `layoutMotion`：`data-layout-moving` の間は TerminalPane が fit しない。`hangar:layout-settled` で 1 回 fit する。
  - 今の `TerminalPane.test.tsx` の左のナビの場合を、右の欄と案内の帯にも広げる。
- `SessionScreen`：
  - 右の欄を閉じると、列が 0 になり、開くボタンがタブの帯に出る。
  - 開くと、ボタンは欄の中へ戻る。
- CSS の文字列テスト（今の `session.test.ts`、`header.test.ts` と同じ書き方）：
  - `--gutter-l` は 16px で、検索欄は `--gutter-head` を使う。
  - `.split` に grid-template-columns の transition が無い。
  - `.live-top` は flex-basis で高さを持ち、`.live-toc` に 5 行の下限が無い。
  - 新しい長さはすべてトークンを通している（`motion.test.ts`）。

目で確かめるもの：

- デスクトップのビルド（Tauri の WebKit）で、①〜⑩を等速と reduced motion の両方で見る。
- WebKit は scrollIntoView と細いぼかしの丸めに癖がある（memory: WebKit scrollIntoView）。そのため Chrome だけで済ませない。
- 右の欄の開閉で、tmux の描き直しが 1 回で済むことを確かめる。サーバへの resize の回数で見る。

## 実装の順

1. 共通の部品（motionKit、useMotionList、layoutMotion）と、`TerminalPane` の印の付け替え。
2. ① 左の余白、② 右の欄の開閉とボタンの置き場所。
3. ④ 境目。
4. ③ ターン、⑤ 意図と手、⑥ レーンと成果物。
5. ⑦ 見出し周りとタブ、⑧ 案内の帯。
6. ⑨ 開いた直後、⑩ 会話が終わったとき。

## 検討して捨てた案

- **右の欄：B「引き出し」**（欄が右へ 24px ずれながら薄れる）。
  - A より動きが大きく、閉じるたびに目が右へ引かれる。
- **右の欄の開くボタン：いつもタブの帯に置く**。
  - 開いている間にボタンが 2 か所に並ぶ。
- **右の欄：細い帯を残して状態を出す／ターミナルに重ねる**。
  - 前者は幅を使い切れない。後者はターミナルの文字を隠す。
- **ターン：B「浮かぶと光る」**。
  - 新しいターンは自分が送った指示なので、光らせて知らせる必要が無い。
- **ターン：C「押し上げ」**。
  - 末尾へ追従する動きと重なり、二重に動いて見える。
- **意図：B「転がる」**。
  - 2 行以上の文では、行の切れ目で文字が切れて見える。
- **意図：C「その場で光る」**。
  - 文が替わったことより、箱が光ったことが目立つ。
- **境目：A「引いた所が境目」だけ**（端で畳まない）。
  - B は A に端で畳む動きを足しただけで、A の自由さはそのまま残る。A だけでは、端まで寄せ切る手間が残る。
- **開いた直後：B「空のまま現す」**。
  - 届くまでの間、目次が壊れているように見える。
- **ターミナルの折り返し：動きに合わせて何度も折り返す／先に折り返してから動かす**。
  - 前者は tmux の描き直しが何度も走る。後者は、狭まる側で文字が一瞬切れる。
