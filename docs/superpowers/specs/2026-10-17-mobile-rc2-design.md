# スマホ版 0.8.0-rc.2：入口、起動の画面、指示の欄、呼び鈴

2026-10-17。
rc.1（`2026-10-17-mobile-pwa-design.md`）を利用者が iPhone で試した結果と、2 つの試作で利用者が選んだ案から書く。
rc.1 の設計の決定（暗号、券、上限を PC 側に設けない、など）はそのまま引き継ぎ、ここには変える所と足す所だけを書く。

## 意図

rc.1 で、一覧と起動の骨組みは動いた。
使ってみて困ったのは次の 5 つである。

- Safari で接続してからホーム画面に追加すると、ホーム画面のアプリは未接続で開く（保存場所が別）。2 回接続することになる。
- 新しい会話の画面で、プロジェクトの一覧が長く、権限モードとモデルの欄が常に場所を取る。effort を選べない。
- 「始める」の後、PC が受け取るまで最大 30 秒待つ。その間と結果の見せ方が薄い。
- Remote Control の会話は起こしたアカウントの Claude アプリにだけ出るのに、受信箱の行からはどのアカウントか分からない。
- 最初の指示に、PC の指示欄にある `/`（スキル）、`@`（ファイル）、画像の添付が無い。

## 利用者が選んだ案

画面の試作は `proto.html`（A〜E）と `composer-proto.html`（指示の欄）。どちらも `~/workspace/hangar-explainers/mobile-rc2-2026-10-17/` にある（リポジトリの外）。

- **A1 入口。** Safari（ホーム画面のアプリでない）で開いたら、接続より先に「ホーム画面に追加して、そこから開く」を案内する。ホーム画面のアプリは、アプリの中で QR を読む（貼る欄も残す）。QR は PC の画面に出ている残り時間の間は有効。
- **B1 プロジェクト。** 「すぐ始める（フォルダなし）」を先頭に、最近 5 件の札、検索欄、「すべて N 件」のシート。PC は選んだプロジェクトを持つものだけ。
- **C3 詳しい設定。** 権限モード、モデル、effort を「詳しい設定」に畳み、閉じているときは 1 行の要約を出す。effort を足す（デフォルト、low、medium、high、xhigh、max）。
- **D2 始めた後。** 「〈PC〉で始める」の後は、受信箱の上に下から出るシートで、送信 → PC が受け取り → 始まった → 会話の札（プロジェクトと題、PC、アカウント、状態、意図、「Claude アプリで開く」は URL が分かってから）。失敗と「受け取りましたが結果が届いていません」もこのシートで出す。
- **E1 アカウントの札。** 受信箱の各行にアカウントの札（色の丸と名前）を出し、開くボタンを「〈アカウント〉のアカウントで開く ›」にする。
- **指示の欄。** 道具の列は「＋」「/」「@」の 3 つ。
  - `/`：候補はキーボードの上のシート（4〜5 行、行は大きく）。選んだ PC とアカウントとプロジェクトのスキルとコマンド。
  - `@`：「@」の直後は最近変えたファイル（変更ありの印）、続けて打てば全体から探す。問い合わせ中と、PC が応答しない状態を出す。
  - 画像：「＋」で写真とカメラのシート。1 枚 5 MB、4 枚まで。サムネイル、送っている間の進み、失敗したら押して送り直し、×で外す。
- **呼び鈴。** `@` と `/` の候補を 1〜3 秒で返し、起動の依頼もすぐ拾うために、Worker に Durable Object を 1 つ足し、PC と WebSocket でつなぎっぱなしにする（Durable Object の案を利用者が選んだ。ほかの案は、スマホが居る間だけ PC が速く聞く案と、待たない形に変える案だった）。

## 目標にしないもの

- スマホでの会話の閲覧、返事、承認（rc.1 と同じく `/rc` に任せる）。
- 画像以外のファイルの添付（試作の「ファイル」は参考で、rc.2 では作らない）。
- 呼び鈴での受信箱の即時の更新（受信箱は今の読み直しのまま）。
- プッシュ通知。

## 失敗とみなすもの

rc.1 の一覧に足す。

- `@` の問い合わせの中身（打った文字、ファイルのパス）と `/` の候補、画像の中身が、平文で Worker、Durable Object、D1、R2 に置かれたり、通ったりすること。
- 呼び鈴の WebSocket に、スマホのトークンや解除した PC のトークンでつなげること。宛先でない PC に問い合わせや画像が渡ること。
- 呼び鈴が無い Worker（rc.1 のまま再配備していない）や、つながらない PC で、起動ができなくなること（30 秒の pull に戻る）。
- 呼び鈴のつなぎっぱなしで、Durable Object の無料枠（1 日 10 万リクエスト、時間の枠）が目に見えて減ること。
- 画像が R2 に残り続けること。スマホのトークンで R2 のほかの鍵を読み書きできること。
- 問い合わせの答えに、プロジェクトの外のパスや、上限を超える量が入ること。
- 指示の欄の候補や画像の名前が、画面でスクリプトとして実行される形で出ること。

## 流れ

### 1. 呼び鈴（Durable Object）

- Worker に Durable Object のクラス `HangarBell` を 1 つ足し、名前の決まった 1 つの実体（`idFromName('bell')`）だけを使う。SQLite 型（無料プランで使えるのはこれだけ）。
- **PC のつなぎ方。** PC は `GET /m/bell`（Upgrade: websocket、`Authorization: Bearer <PC のトークン>`）でつなぐ。Worker が authMiddleware と requireKind('pc') を通してから、端末の ID を添えて Durable Object へ渡す。Durable Object は Hibernation API（`acceptWebSocket`、`serializeAttachment` に端末 ID）で受ける。スマホのトークンと解除した PC は Worker で断る。
- **生存の確かめ。** PC は 30 秒ごとに `ping` を送り、Durable Object は `setWebSocketAutoResponse` で `pong` を返す（Durable Object を起こさず、リクエストに数えない）。PC は 75 秒 `pong` が来なければつなぎ直す。つなぎ直しは 1 秒から倍々で 60 秒まで待つ。
- **鳴らす。** スマホの起動の依頼（`POST /m/launches`）が行を入れたら、Worker は Durable Object に宛先の PC を鳴らさせる（`{t:'launch'}`）。PC は鳴ったら `engine.pullNow()` を呼び、今の pull の道で依頼を受け取る。鳴らすのに失敗しても依頼は成功として返す（PC は 30 秒の pull で拾う）。
- **問い合わせ。** スマホは `POST /m/ask`（スマホのトークン、本文は `{ id, targetDevice, sealed }`）を送る。Worker は Durable Object に渡し、Durable Object は宛先の PC の WebSocket に `{t:'ask', id, sealed}` を送って、PC の `{t:'reply', id, sealed}` を最大 5 秒待ち、そのまま返す。宛先の PC がつないでいなければすぐに 503（`pc-offline`）、5 秒で答えが無ければ 504（`pc-timeout`）。**D1 には書かない。** 問い合わせの本文はスマホが封をし、Durable Object と Worker は読めない。
- **問い合わせの上限。** 本文は 4 KiB、答えは 64 KiB。スマホ 1 台から 10 秒に 20 回まで（Durable Object のメモリで数える。眠れば消える緩い上限）。
- **古い Worker と古い PC。** 互換の版を 8 に上げる。PC は Worker の版が 8 未満なら呼び鈴を張らない。呼び鈴が無いとき、起動は今の 30 秒の pull のまま動き、スマホの `/` と `@` は「この PC は候補を返せません（hangar を更新してください）」と出して、指示は手で打てる。`MIN_DEVICE_COMPAT` は上げない。

### 2. 問い合わせの種類（封の中身）

封の AAD は `ask|<id>|<宛先>` と `reply|<id>`。封の中身は JSON。

- `{ kind: 'files', projectId, q }` → `{ files: [{ path, changed }] }`。`q` が空なら、git の変更ありのファイルと、変更時刻が新しいファイルを合わせて最大 30 件（変更ありを先に）。`q` があれば PC の指示欄と同じ検索（`listProjectFiles`）で最大 50 件。パスはプロジェクトの根からの相対で、外に出るものは返さない。git でないフォルダは変更時刻だけで並べる。
- `{ kind: 'commands', projectId | null, accountId }` → `{ commands: [{ name, description, kind: 'skill' | 'command' }] }`。PC の指示欄と同じ `listPromptCommands` を、そのアカウントの設定フォルダで呼ぶ。最大 200 件、説明は 120 字で切る。
- 答えの失敗は `{ error: 'project-missing' | 'account-missing' | 'bad-request' }`。
- スマホは答えを画面の間だけ覚える（同じ PC、プロジェクト、アカウントの `/` は 1 回、`@` は同じ `q` を 30 秒）。打つたびの問い合わせは 250 ms 待ってから出す。

handoff では `/` の候補を受信箱の素に載せる案だったが、プロジェクトのスキルまで載せると素が膨らみ、PC が落ちていれば起動もできないので、`@` と同じ問い合わせに寄せた。

### 3. 画像

- スマホは選んだ画像を、送る前に長い辺 2048 px、JPEG（品質 0.85）に縮める。縮めた後で 5 MB を超えるものと、5 枚目は受け付けない（試作の文言）。
- 画像ごとに `sealBytes(key, aad, bytes)`（AES-GCM、AAD は `image|<依頼の ID>|<番号>`）で封をし、`PUT /m/blobs/<依頼の ID>/<番号>`（スマホのトークン、本文は封をしたバイト列そのまま）で R2 の `mobile/<スマホの ID>/<依頼の ID>/<番号>` に置く。番号は 0〜3。
- 起動の依頼の封の中身に `images: [{ n, mime, bytes }]` を足す。依頼は画像を全部置いてから出す。
- PC は依頼を受け取ったら、`GET /m/blobs/<依頼の ID>/<番号>`（PC のトークン。宛先がその PC の依頼の画像だけ）で取り、開き、PC の指示欄と同じ `saveDrop` で drops に置いて、PC の指示欄と同じ形（`composePrompt` と同じ並び）で最初の指示の末尾にパスを足す。取れなかった画像があれば起動せず、`images-missing` で失敗を返す。
- 消す時期：PC が答えを返したとき（started でも failed でも）、Worker がその依頼の画像を消す。答えが来ない画像は、スマホが次に画像を置くときと依頼を出すときに、Worker が `mobile/<スマホの ID>/` の下で 24 時間を過ぎたものを消す。
- 上限：1 枚 5 MiB（封の分を足す）、1 件の依頼に 4 枚、1 台のスマホの置いたままの画像は 40 枚まで（R2 の一覧で数える）。
- スマホのトークンで触れる R2 の鍵は `mobile/<自分の ID>/` の下の置くことだけ。PC のトークンで触れるのは自分宛ての依頼の画像を読むことだけ。今の `files` の口（`validKey`）は変えない。
- CSP の `img-src` に `blob:` を足す（サムネイルの表示）。

### 4. effort

- `EFFORT_VALUES`（''、low、medium、high、xhigh、max）を shared に置き、PC の画面（`LaunchChips.tsx`）とスマホと PC の受け取りで共有する。
- `MobileLaunchPayload` に `effort?: string` を足す（v は 1 のまま。無ければデフォルト）。PC の受け取り（`isPayload`）は値表で確かめ、`paramsOf` で `LaunchParams.effort` に写す。

### 5. 画面

試作の動きと文言に合わせる。動きはアプリの決まった動き（`presence.ts` の `usePresence`、`styles.css` の `m-fade`、`m-grow`、`m-collapse`、`sheet-in`、`sheet-out`、長さと曲線のトークン、reduced-motion で 0）にそろえる。

- **A1。** 起動時に、ホーム画面のアプリかどうか（`display-mode: standalone` か `navigator.standalone`）を見る。iPhone と iPad の Safari で、ホーム画面のアプリでなく、未接続なら、案内の画面（共有ボタン → ホーム画面に追加 → ホーム画面から開く）を先に出す。「このまま Safari で使う」も小さく残す。ホーム画面のアプリでは、接続の画面でアプリの中のカメラで QR を読む（今の `scanQr`）。カメラが使えないときは貼る欄。
- **E1。** 受信箱の行に、アカウントの札（色の丸と名前、受信箱の素の `accounts` から）。開くボタンの文言を「〈アカウント〉のアカウントで開く ›」。URL が分からない行は今のとおり claude.ai/code を開く（文言は同じ札つき）。
- **B1。** 新しい会話の画面のプロジェクトの欄は、「すぐ始める」、最近 5 件の札、検索欄、「すべて N 件」で開くシート（検索つき、最近使った順）。
- **C3。** 「詳しい設定」は閉じて 1 行の要約（例：「デフォルト権限 · Opus · effort 既定」）。開くと権限モード、モデル、effort。開き閉じは `m-grow` と `m-collapse`。
- **D2。** 「始める」を押したら、画面を受信箱に戻し、その上に下からシートを出す（`sheet-in`）。段は「送信」「PC が受け取り」「始まった」の 3 つで、進むごとに印が変わる。始まったら会話の札（プロジェクトと題、PC、アカウントの札、状態、意図）を出し、受信箱の素にその会話の `rcUrl` が来たら「〈アカウント〉のアカウントで Claude アプリで開く」を出す。失敗、時間切れ、「受け取りましたが結果が届いていません」もここで出す。閉じても依頼は続き、受信箱の行に出る。
- **指示の欄。** 欄の下の道具の列に「＋」「/」「@」。
  - 「/」を押すか行頭で「/」を打つと、キーボードの上のシートに候補（見出しはスキルとコマンド）。打った文字で絞る。押すと「/名前 」が入る。PC を選んでいなければ「先に PC を選んでください」。
  - 「@」を押すか「@」を打つと、同じシートに「最近変えたファイル」（変更ありの印）。続けて打てば検索。問い合わせ中は 3 行の骨組み、PC が応答しなければ「PC が応答しません」と再試行。押すと「@パス 」が入る。
  - 「＋」で写真とカメラのシート（上限の説明を書く）。選んだ画像は欄の上にサムネイルで並び（`m-grow`）、送る間は進み、失敗は押して送り直し、×で外す（`m-collapse`）。
- **プロジェクトの最近の札、候補のシート、D2 のシートの状態**は、試作 `proto.html` と `composer-proto.html` の見た目に合わせる。

### 6. 軽い直し

- `packages/mobile/_headers` の `/app/` の明示の段を外す（`/app/*` と重なり見出しが二重に付く）。
- PC の `mobile_launches`（重複を防ぐ手元の表）の古い行を消す（7 日）。
- 最後のスマホを解除したら、その PC の受信箱の素（`mobile_feeds` の行）を Worker から消す（`DELETE /m/feed`）。
- `cloud.json` を替えた直後の 5 分、スマホが有るという覚えが古いまま残るのを、つなぎ先が変わったら捨てる。

## 無料枠の見積もり

1 日に、PC 2 台、スマホ 1 台、起動 10 回、`@` と `/` の問い合わせ 200 回、画像 10 枚として。

| 物 | 1 日の量 | 無料枠 |
|---|---|---|
| Durable Object のリクエスト | 問い合わせ 200 ＋ 鳴らす 10 ＋ PC のつなぎ直し 数十 ＋ WebSocket の受信（20 通で 1 回）20 ほど ≒ 300 | 10 万 |
| Durable Object の時間 | 問い合わせを待つ間だけ（最大 5 秒 × 200）。眠っている間は数えない | 13,000 GB-s |
| WebSocket の ping | 自動応答なので数えない | |
| D1 の書き込み | 増えない（問い合わせは D1 に書かない） | 10 万行 |
| D1 の読み取り | 起動の状態の読み直しを 3 秒から 2 秒に縮めた分だけ増える（1 回の起動で 10 回ほど、1 行ずつ） | 500 万行 |
| R2 の Class A（置く、一覧） | 画像 10 ＋ 一覧 20 | 月 100 万 |
| R2 の Class B（読む） | 10 | 月 1,000 万 |
| R2 の保存 | 置いたままは最大 40 枚 × 5 MiB | 10 GB |

## 制約

- 試験は miniflare（`packages/cloud/test/harness.ts`）で、Durable Object と WebSocket も miniflare で試せる。束ねたもの（`scripts/build-worker.ts`）にクラスの書き出しと束縛が要る。
- 実物の配備は `hangar setup cloud`（`packages/cli/src/cloud.ts` の `writeWranglerConfig`）。`durable_objects.bindings` と `migrations`（`new_sqlite_classes: ['HangarBell']`）を足す。ローカルの `packages/cloud/wrangler.jsonc` も同じ。
- PC は Node 22。WebSocket は `ws`（既に依存にある）でヘッダを付けてつなぐ。
- 互換の版の写しは `packages/server/test/fake-cloud.test.ts` と `apps/desktop/src-tauri/src/health.rs` にもある。
- 公開リポジトリなので、試験や文書に実際のプロジェクト名、ファイル名、会話の題を書かない。
