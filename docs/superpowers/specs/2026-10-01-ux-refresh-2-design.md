| 軸 | 採った案 |
|---|---|

## 2 本文の表示（`transcript-render.html`）

| 軸 | 採った案 |
|---|---|
| M 返答の器 | M2 返答は地の文にし、吹き出しをやめる |
| T ツール行 | T1 1 行 |
| K ツール名の札 | K1 色分けの札（読む＝青、書く＝緑、実行＝杏、web＝紫、その他＝灰） |
| D 差分 | D1 統合表示 |
| F 長い本文 | F1 高さで切って下端をぼかし、「全文を表示（残り N 行）」 |
| S 本文の検索 | S1 ⌘F の欄は右上に浮くガラス、スクロールバーに一致の印 |
| J 検索から開く | J1 一致へ跳び、返答の地を淡い黄から薄れさせる |

Markdown は表、箇条書き、番号付き、リンク、見出し、囲みのコード（言語名とコピーのボタン）を読む。
HTML は今までどおり解釈しない。
ツールは種類ごとに中身を描き分ける（Edit と MultiEdit は差分、Write はパスとコード、Bash はコマンドと出力、Read はパスと行の範囲、WebFetch と WebSearch、Grep、Task、その他は整形した引数）。
生の JSON は「生の記録」のトグルの側にだけ残す。
入れ子のスクロールはやめる。
検索の結果から開くときは、`session.open` に `seq` と検索語を持たせ、その周りを読んで跳ぶ。
手の種類（読む、書く、走らせる、コミット、失敗、その他）の規則は live-explainer が `packages/shared` に置く予定なので、先に入った側の規則を使い、二重に持たない。

## 8 ダイアログ（`dialogs.html`）

| 軸 | 採った案 |
|---|---|
| A 殻 | A1 見出しと下端を固定し、中身だけスクロール（上下にスクロールの影） |
| B ⌘Enter の表示 | B1 起動ボタンの中にキー帽 |
| C 下書き | C1 見出しの右に「下書き」の札と「消す」 |
| D 前回値 | D1 詳細の見出しに「前回と同じ」と中身、「既定に戻す」 |
| E 危険の色 | E1 赤い丸のアイコンと赤く塗ったボタン（①の `.btn-danger-fill` を使う） |

ダイアログの共通の殻（`Dialog` 部品）は、開いたら最初の安全な操作へフォーカス、Tab の閉じ込め、閉じたら元へフォーカスを返す、`role="dialog"` と `aria-labelledby`、高さの上限、入力のあるダイアログは背景のクリックで閉じない、を持つ。
新しいセッションのダイアログは、⌘Enter で起動、書きかけの Esc は下書きとして残す、詳細はプロジェクトごとの前回値を初期値にする。
