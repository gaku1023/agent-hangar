## 目的

利用者が挙げた不満は次の 4 つである。

- 地味で個性がない。
- ブランドとロゴが弱い（favicon は青い四角、起動画面にロゴが無い）。
- 動きが静的で硬い。
- 情報の見せ方が古い（Home がただの一覧、表が詰め込みすぎ、セッション画面、画面と操作の流れ）。

判断の物差しは、利用者の言葉で「シンプルで見やすい」である。
新しく見せるための飾りでも、読みやすさを削るものは入れない。

成功の基準は次のとおりとする。

- 開いた瞬間に、いまどのセッションが動いていて、どれが自分を待っているかが分かる。
- ロゴと起動画面で、このアプリだと分かる。
- 画面の移動や状態の変化を目で追える。
- 一覧とトランスクリプトの読みやすさ（文字のコントラスト、行の情報量）が今より落ちない。

## 決定の要約

| 項目 | 決定 |
|---|---|
| 方向性 | 光と層。その中でも macOS 26 の Liquid Glass に揃える |
| ガラスの下 | 淡い光（青と紫の 2 つの光がゆっくり漂う） |
| ガラスを使う所 | 浮く部品だけ（ヘッダ、サイドバー、⌘K、ダイアログ、通知）。読む面は不透明 |
| ロゴ | 端末を掛けたハンガーが右奥へ 4 本重なり、奥ほど霞む。カーソルは札ごとの状態の色 |
| 画面の骨格 | 今の構成（サイドバー、ヘッダ、メイン）を保ち、中身を作り直す（試作の案 A「管制盤」） |
| Home | 要対応、実行中の札、最近、プロジェクト |
| 一覧 | 2 段の行。右端に出すものを画面の役目で変える |
| セッション画面 | 構成は今のまま。端末は墨の板で、縁がそのセッションの状態で灯る。タブはフォルダの耳 |
| 動きの性格 | なめらか（速く出てゆっくり止まる、420ms、ぼかしが晴れながら現れる） |
| 決めの動き | 起動画面（ハンガーが流れ続ける）と、行がセッション画面へ広がる動き |
| .app のタイトルバー | ガラスに溶かす。ヘッダを窓の上辺に付いた帯にし、信号の 3 点は VS Code と同じ位置でその左端に載る（サイドバーの開閉に関わらず同じ所）。窓はヘッダを掴んで動かす |

| ダークモード | 持たない（2026-09-17 の決定を維持） |

## 1 見た目の言語

### 層

画面は奥から 3 枚の層で組む。

1. **光の背景**。
   地は `#eef1f7` で、その上に青 `#cfe0ff` と紫 `#e5d6ff` の放射状の淡い光を 2 つ置く。
   光は 1 枚の固定レイヤー（`body::before` か専用の要素）に描き、24 秒かけて往復で漂わせる。
   reduced motion では止める。
2. **読む面**。
   一覧、カード、会話、設定の中身、プロジェクトの右レールである。
   白で不透明、角 14px、影はごく薄い（`0 1px 2px` 程度）。
3. **浮くガラス**。
   ヘッダ、サイドバー、⌘K パレット、ダイアログ、通知だけに使う。
   読む面の上にガラスを重ねない。

### ガラス

| 部品 | 地 | ぼかし | 縁と影 |
|---|---|---|---|
| サイドバー | 白 40% | `blur(12px) saturate(1.9)` | 上縁に白 95% の 1px の鏡面光、内側に白 50% の 1px の縁、`0 10px 28px -12px` の落ち影 |
| ヘッダ（窓の上辺に付いた帯） | 白 40% | `blur(12px) saturate(1.9)` | 下縁に白 60% の 1px の線、`0 6px 18px -12px` の下へ落ちる薄い影。角は丸めない |
| ⌘K パレット | 白 62% | `blur(18px) saturate(1.8)` | 同じ縁、`0 24px 50px -16px` の落ち影 |
| ダイアログ | 白 72% | `blur(18px) saturate(1.6)` | パレットと同じ |
| 通知 | 白 82% | `blur(14px)` | 同じ縁、`0 14px 28px -10px` の落ち影 |

`backdrop-filter` には、macOS 13 と 14 の WKWebView のために `-webkit-backdrop-filter` を併記する。
ぼかしは上の 4 種の部品のクラスの中にだけ書き、それ以外の規則には書かない（試験で固定する）。
ヘッダは窓の上辺と左右の端に付いたガラスの帯（高さ 34px、角なし、縁は下だけ）で、一覧はその下をくぐって流れる。
メイン領域は、ヘッダの高さ（34px）とその下の隙間（8px）の分だけ上に余白を取ってから始める（2026-09-30 に、浮いた錠剤（高さ 40px、上の隙間 8px）から改めた。信号の 3 点を VS Code と同じ位置に揃えるため。検討した案は `traffic-align.html`）。

### 端末の板と縁の灯

端末は墨色（`--term-bg: #1c1b2e`、文字 `--term-fg: #e8e6f0`）の不透明な板で、角は 14px とし、タブにつながる左上だけを角張らせる。
縁は、そのセッションの状態で 1.5px だけ灯す。

| 状態 | 縁 |
|---|---|
| busy（作業中） | 杏 `--busy` の 1.5px の輪と、外側に 22px の淡い光。3.2 秒で明暗をゆっくり往復する |
| waiting（入力待ち） | 赤 `--waiting` の 1.5px の輪と光。動かない |
| idle（休み） | 灯さない。板を持ち上げる影だけ |
| 終了 | 灯さない |

状態が変わったときは、色が 420ms で移る。
reduced motion では往復を止め、静止した輪だけを残す。

### 形

| 角 | 使う所 |
|---|---|
| 8px（`--r`） | 入力欄、チップの中身、行の中の小さな札 |
| 14px（`--r-lg`） | 読む面、カード、端末の板 |
| 16px（`--r-xl`） | 浮くガラス（サイドバー）。ダイアログとパレットは 18px |
| 99px | ボタン、検索欄、ヘッダ、サイドバーで選択中の項目 |

ボタンはホバーで 1px 浮き、押すと 97% に縮む。
主ボタンだけ、上 `--accent-hi` から下 `--accent` へのグラデーションを持つ。

### 色

| トークン | 値 | 役目 | 白地のコントラスト |
|---|---|---|---|
| `--bg` | `#eef1f7` | 光の背景の地 | |
| `--surface` | `#ffffff` | 読む面 | |
| `--surface-2` | `#f3f4f9` | 吹き出し、ホバー | |
| `--line` | `#eceef5` | 行の区切り | |
| `--line-strong` | `#d9dbe6` | 入力欄の縁 | |
| `--ink` | `#1c1b2e` | 本文 | 16.9 : 1 |
| `--ink-2` | `#5f5e78` | 補足の文 | 6.3 : 1 |
| `--ink-3` | `#6e6d88` | 注記、時刻 | 5.0 : 1 |
| `--accent` | `#4a63e8` | 主ボタン（白文字）、リンク、選択 | 5.0 : 1 |
| `--accent-hi` | `#6b8cff` | 主ボタンのグラデーションの上端 | |
| `--accent-soft` | `#eef2ff` | 選択中の行 | |

状態の色（`--busy`、`--idle`、`--waiting`、`--ended`、`--error`）とプロジェクトのステータスの色（`--st-*`）は、今の値のまま使う。
状態の点のような図形は、WCAG の図形の基準（3 : 1）で見る。
`--ink-3` は今の `#9a968e`（約 2.9 : 1）から上げた。
その後、小さな時刻が読みにくかったので `#8a89a0`（約 3.4 : 1）から `#6e6d88` に上げ、注記も白地で 4.5 : 1 を満たすようにした。
本文に使う色は 4.5 : 1 以上を保つ。

### 文字

書体（Inter 系、Hiragino Sans、JetBrains Mono 系）と文字の大きさ（11、12、13、15、20px）は今のまま使う。
見出し（15px と 20px）だけ、字間を −1% 詰めて太さを 650 にする。

### design.md の決まりの書き換え

- 参照先を Linear から macOS 26 の Liquid Glass に変える。
- 新しく許すもの：ガラス（浮く部品だけ）、グラデーション（主ボタンと背景の光だけ）、影（浮く部品と、持ち上げた端末の板だけ）、脈動（端末の縁の作業中だけ）。
- 引き続き禁じるもの：読む面へのガラス、シマー、スケルトン、タイピング風の表示、文字の影、光る文字、ダークモード。
- アイコンは Lucide の 16px、線幅 1.5 のまま使う。

## 2 ロゴと資産

### 原図

端末の窓を掛けたハンガーが、右奥へ向かって 4 本重なる。
1 本の札は、フック、ハンガーの三角（竿が窓の上辺を兼ねる）、墨色の窓、窓の左上の信号の 3 点、プロンプトの `>` とカーソルでできている。
並べ方は次の値で決める。

| 値 | 中身 |
|---|---|
| 本数 | 4 |
| 縮小率 | 1 本奥へ行くごとに 0.85 倍 |
| 横の送り | 手前の札の幅の 13% |
| 縦の送り | 札の高さの 3.5% ずつ上へ |
| 霞 | 奥へ行くほど、色を `#e2e7ff` へ混ぜる（奥の札で 86%）。透明にはしない |
| カーソルの色 | 手前から杏 `#ffb86b`、赤 `#e5533d`、灰 `#b5b2c4`、杏。奥の札のカーソルは霞を半分だけかける |
| 竿 | フックを貫く直線。手前は墨色で、奥へ向かって霞の色へ溶ける |

群れ全体を、アイコンの枠の中央の幅 70%、高さ 66% に収める。
原図の座標は試作の `logo-compact.html` と `2-5-assets-screens-motion-tests.html` の生成コードが正であり、実装ではそれを SVG の原本（`packages/ui/src/brand/logo.svg` と、先頭 1 本だけの `logo-front.svg`）に書き出す。

### 寸法ごとの形

| 使う所 | 形 |
|---|---|
| アプリアイコン（`.icns`、16 から 1024px） | 原図。地は白から淡い青紫へのグラデーションの角丸の四角（macOS のアイコンの角） |
| ブラウザのタブ（favicon、16px） | 先頭の 1 本だけの図 |
| サイドバーのワードマーク（44px、畳んだ帯では出さない） | 原図の余白を切り落とした図（`logo-mark.svg`、地の四角なし）と「Hangar」の文字（20px、太さ 720、字間 −3%）。文字の語尾に、手前の札と同じ杏 `#ffb86b` の下線のカーソルを置く。動かさず、カーソルも点滅させない（2026-09-30 に 22px から改めた。検討した案は `wordmark-options.html`） |
| 起動画面 | 原図を動かす（下の「起動画面」） |

今の `apps/desktop/src-tauri/icon.svg`（アーチと扉）と `icons/*` は、この原図から作り直す。
`packages/ui/index.html` の favicon（青い四角）も置き換える。
表示名は「Hangar」に揃える（サイドバーの文字、窓の題、ブラウザのタブの題）。
リポジトリとパッケージの名前は `agent-hangar` のまま使う。

### 起動画面

`.app` の起動画面（`apps/desktop/loading/index.html`）は、ロゴそのものを読み込み中の表示にする。
ハンガーが竿の上を流れ続ける。

- 1 周期は 1.6 秒である。
  前の 34% で、新しい札が手前に上から降りてきて掛かる。
  続く 34% で、全体が奥へ 1 本分ずれる。
  いちばん奥の札は霞に溶けて消える。
- 送りは手前の札から順に、札ごとに周期の 7% ずつ遅れて始まる（波で送る）。
- 掛かり方は振り子である。
  札は降りながら 5° まで傾き、掛かった瞬間の角度のまま減衰する振り子として揺れる。
  角速度は 6.3 rad/s（約 1 往復／秒）、減衰は 2.4 /s である。
  送りの間は札が後ろへ遅れ、止まると前へ振れて戻る。
  角度と位置は、掛かる前後、送りの前後、周期の境目のどこでも途切れない（試作の初版は掛かった瞬間に角度が 0° から 8° へ跳ねて不自然だった）。
- ロゴは 128px にし、その中心を窓の中心に置く。その下に「Hangar」の文字と、状態の文を出す（文字の大きさは変えない）。
  96 / 128 / 160 / 200px を試作で比べて決めた（2026-09-30）。
  状態の文は「読み込み中」で、後ろの点がハンガーの 1 周期で 1 つ、2 つ、3 つと増えて戻る。点の数が変わっても語は動かない。
  起動が 3 秒を超えたら、秒数を「読み込み中...（5 秒）」のように添える。
  失敗の表示は今の文言のまま使う。
- 最初の周の境目（1.6 秒）を過ぎてもまだ済んでいなければ、状態の文の下に、何をしているかを小さく添える。
  サーバの応答を待つ間は「サーバを起動中」、索引づけの間は「セッションを索引中 412 / 987 件」のように件数を出す。
  件数はサーバの `/health` に載る索引の進み具合（段階、済み件数、全体件数）から取る。鍵の要らない経路なので、載せるのは段階と件数だけにする。
- 殻は `/health` が返った後も、サーバの起動の手続き（最初の索引づけと紐づけ）が済むまで起動画面に残る（上限 120 秒。過ぎたら済まないまま移る）。
  実測（2026-09-30、転記 987 件）では、ふだんの起動は 0.2 秒で済むので、起動はほとんど長くならない。
  済むまで待つのは初回（空の DB で 17.7 秒）と、新しいセッションが溜まっていたとき（30 件で 1.0 秒、100 件で 2.9 秒）で、そのときだけ件数が見える。
  済む前に移ると、UI は索引づけの間 API の応答を最大 1.4 秒待たされていた。
  待つ間にサーバが終わったか、応答が 10 秒途切れたら、落ちたサーバへ移らず失敗の文を出す。
- 済んだら、周の境目を待たずに、読み込みが終わった合図を打つ（K3「波紋が画面に広がる」、0.5 秒）。
  送りの途中の札は行き先まで運び切り、揺れは今の角度から収める。手前に降りている途中の札はそのまま掛け、無ければ新しい札を素早く降ろす。
  どこから入っても、最後は 4 枚の原図になり、ロゴが小さく一度弾む。
  そこから光の輪が二重に画面の端まで広がり、状態の文は「ようこそ」に替わる。
  合図には、待っている間のループが一度もしない動き（弾む、輪が広がる）を使い、終わったことをはっきり分からせる。
- 合図に続けて、ロゴの奥から UI の背景の光（青と藤色）が画面いっぱいに満ち、ロゴと文字は少し浮きながら溶ける（F4「光の色が満ちる」、0.4 秒）。
  満ち切った絵は UI の背景（`.shell::before`）そのものなので、画面が替わっても継ぎ目が無い。
  殻は合図を打たせてから光が満ち切るまで（0.9 秒）待って画面を移す。
- UI 側は、その光の上にサイドバーが左から、ヘッダが上から浮かんで来る。
  読み込み中の文は、ガラスが浮かび終わってから出す。
- reduced motion では、静止した原図と文字だけを出す。
  状態の文の点は増やさず 3 つのまま出す。
  合図は文の差し替えと、光と文字の溶かし合いだけにする（弾み、輪、移動は無い）。

値と式は `boot-animation.html` の生成コード（`ENTRY.pendulum` と `frameOf`）が正である。
合図と光は `boot-finish.html` の K3 と F4 が正である。
試作では合図の終わりで光の輪が止まって見えたが、実装では輪を広げ切り、輪を追って光が満ちるようにした。
起動画面は依存を持たない 1 枚の HTML なので、SVG を `requestAnimationFrame` で描き直す実装をそのまま移す。

## 3 画面

### 骨格

サイドバー（幅 180px 前後）とヘッダは、中身の上に浮くガラスである。
サイドバーの項目は今の 4 つ（ホーム、プロジェクト、セッション、設定）のままとする。名前は日本語にし、パンくずと各画面の見出しも同じ名前にする（2026-09-30 に Home / Projects / Sessions / Settings から改めた。見出しや他の文言と言語を揃えるため）。
項目名は 14px、アイコンは 18px、行の高さは 36px とする。畳んだ帯のアイコンと開閉のボタンも 18px に揃える（2026-09-30 に 15px、20px、38px から改めた。日本語の項目名は字面が四角く詰まり、15px では本文やパンくずの 13px より目立ちすぎたため。検討した案は `sidebar-type.html`）。
ヘッダは窓の横いっぱいに渡り、サイドバーはその下から浮いて始まる。デスクトップの殻では、信号の 3 点がヘッダの左端に載る。
⌘B とサイドバーの開閉のボタンで、アイコンだけの細い帯（52px）に畳める。開閉で変わるのは帯の幅だけで、ヘッダと 3 点は動かない。開閉のボタンはサイドバーが持ち、開いた帯ではワードマークの右端、畳んだ帯ではワードマークがあった一番上に置く（ヘッダには置かない）。畳んだ帯では図と名前は出さず、項目名はアイコンに乗せたときとキーボードで届いたときの吹き出しになる。窓 900px で本文が 216px 広がる（2026-09-30 に、図と項目名を残した 88px の帯から改めた。広がりが 120px しかなく、何も消えないので畳んだ手応えがなかった。検討した案は `sidebar-shrink.html`）。
ヘッダには今と同じ部品（パンくず、検索欄、同期の状態、5 時間と 7 日のゲージ、新規セッションのボタン）を置く。
検索欄には「⌘K」の印を添える。

### .app のタイトルバー

標準のタイトルバーを消し、中身を窓の上端まで広げる。

- `tauri.conf.json` の窓に `titleBarStyle: "Overlay"` と `hiddenTitle: true` を付け、`trafficLightPosition`（x 11、y 19）で信号の 3 点を VS Code と同じ位置（窓の左から 11pt、縦の中心は上から 17pt）に置く。ヘッダの高さ 34px の中心と揃う。
- ヘッダは、デスクトップの殻の中でだけ、左に信号の 3 点の分の余白を取る（2026-09-30 に、サイドバーの上に置いていたのを改めた。サイドバーを畳むと 3 点が収まらず、開閉で 3 点の居場所が変わったため）。
  殻の中にいることは、今の `window.__hangarPhaseAware` と同じ経路（殻が頁に注入する印）で知らせる。
  ブラウザではその余白を取らない。
- 窓はヘッダの空いた所を掴んで動かす。
  ヘッダの要素に `data-tauri-drag-region` を付け、ボタンや入力欄のような操作する部品には付けない。
  同じ空いた所をダブルクリックすると、窓が拡大する（最大化であり、フルスクリーンではない）。
- そのために、UI の出どころ（`http://127.0.0.1:4177`）に、窓を動かす権限（`core:window:allow-start-dragging`）と、ダブルクリックで拡大する権限（`core:window:allow-internal-toggle-maximize`）の 2 つだけ与える。
  `capabilities` の新しい項目に `remote.urls` でこの出どころだけを書き、ほかの権限は与えない。
  今の `default.json` は変えない。

この変更は、フェーズ 5 で決めた「Tauri のためのコードを UI に足さない」「Tauri 固有の見た目を足さない」を、タイトルバーに限ってゆるめる。
UI に足すのは、ヘッダの `data-tauri-drag-region` の印と、殻の中でだけ効くヘッダの左の余白の 2 つである。
どちらもブラウザでは何もしない。

### Home（管制盤）

上から次の区画を置く。
要対応と実行中が無いときは、その区画ごと省く。

1. **要対応**。
   入力待ち（`live.status === 'waiting'`）のセッションを、1 件 1 枚の横長の札で出す。
   札には、名前、プロジェクト、待っている時間、待っている問いの文、「ターミナルで答える」を置く。
   「ターミナルで答える」は、そのセッションのセッション画面を開いて端末にフォーカスする。
   その場で答えさせることはしない（選択肢を画面から選ばせるには、端末の TUI を外から操ることになって壊れやすい）。
2. **実行中**。
   実行中のセッションを、3 列の札で出す。
   札には、名前、経過時間、プロジェクト、モデルと effort、いま何をしているか（最新のツール呼び出しの 1 行、墨の地）、文脈の使用率のゲージを置く。
   休み（idle）の札は、何をしているかの代わりに「休み。最後の返答から N 分」を出す。
   札を押すと、決めの動き（行が画面へ広がる）でセッション画面へ移る。
3. **最近**（左、幅 1.6）と**プロジェクト**（右、幅 1）を横に並べる。
   最近は 2 段の行で、右端は時刻だけにする。
   プロジェクトは、active なプロジェクトの小さな一覧（状態の点、名前、実行中と TODO と要対応の数）にする。
   プロジェクトのカードは Projects 画面だけに置く。

#### データの流れ（新しく足すもの）

文脈の使用率は、今の `stats.contextPercent` を使う。
最新のツール呼び出しと待っている問いの文は、今は Home に届いていない。
そこで、サーバが実行中のセッションごとに、正規化したトランスクリプトの末尾から次の 2 つを取り出し、セッションに欄として載せる。
今の `SessionDto.live` は状態の文字列で欄を足せないので、実装では同じ中身を `SessionDto.activity`（`{ tool, summary, question }`）に載せた（2 回目の計画 `docs/plans/ui-refresh-2-home.md`）。

| 欄 | 取り出し方 | 取れないとき |
|---|---|---|
| `live.activity` | 最後の `tool_call` の `name` と `summary`（例：`Edit`、`packages/ui/src/keys.ts`） | 空。札は「作業中」とだけ出す |
| `live.question` | waiting のとき、最後の `tool_call` が AskUserQuestion なら、その `input` の最初の問いの文 | 空。札は「入力を待っています」とだけ出す |

取り出しは、ライブトランスクリプトの追記を読んでいる経路に載せ、Home を開いたときにまとめて読み直すことはしない。
欄はどちらも任意とし、古いクライアントとクラウド同期の形式には影響させない（同期の対象に入れない）。

### セッション画面

構成は今のまま（端末が主、会話が従、上にタブ）とする。

- 上段に、状態の点、名前（15px）、要約の 1 文、操作（VS Code で開く、ターミナルで開く）を置く。
- その下に、チップの列（状態と経過、モデルと effort、文脈の使用率、推定コスト、変更数、1 行メモ）を置く。
- 端末は墨の板で、縁がそのセッションの状態で灯る（1 の「端末の板と縁の灯」）。
- タブは板から生えたフォルダの耳で、選んだタブが板とつながる。
  タブ 0 が Claude、以降がシェルである点、⌘1 から ⌘9、⌘W、分割（⌘\）、トランスクリプトの開閉（⌘J）は今のまま使う。
- 会話は右の読む面に吹き出しで描き、ツール呼び出しは 1 行に畳む。
- 過去のセッション（トランスクリプトだけ）は、端末の板の場所に会話を広げ、右に要約、TODO、変更を置く。

### 一覧の行

どの一覧も 2 段の行（1 段目に名前、2 段目に要約の 1 文）にする。
右端に何を出すかは、画面の役目で変える。

| 画面 | 右端 | 2 段目 |
|---|---|---|
| Home の最近 | 時刻だけ | 要約の 1 文 |
| プロジェクト詳細 | モデルと effort、変更数、PR、推定コスト（小さな文字で 1 行）と、その下に時刻 | 要約の 1 文と、あれば 1 行メモ（✎）。`m` で編集 |
| Sessions（検索） | 時刻 | 一致箇所の抜粋（一致した語に淡い印）。1 段目の名前の隣にプロジェクト名 |
| Settings の使用量 | 表のまま | |

行の高さは 44px とする（今の 28px の 1 段から変わる）。
`SessionRows` の `rowHeight` の見積もりもこれに合わせる。
キー操作（j、k、Enter、o、e、m）は今のまま使う。

### ほかの画面と部品

Projects のカード、プロジェクト詳細の右レール、Settings、ダイアログ、⌘K、通知、接続の帯は、構成を変えずに 1 の見た目の言語だけを当てる。

## 4 動き

### 性格とトークン

性格は「なめらか」である。
すっと出て、長く静かに止まる。
現れるものは、ぼかしが晴れながら来る。

| トークン | 値 | 使う所 |
|---|---|---|
| `--dur-fast` | 200ms | ホバー、押下 |
| `--dur` | 420ms | 現れる、移る、状態の色の遷移 |
| `--dur-exit` | 250ms | 消える |
| `--ease-out` | `cubic-bezier(.16,1,.3,1)` | 現れる、移る、ホバー |
| `--ease-in` | `cubic-bezier(.4,0,1,1)` | 消える |
| `--rise` | 6px | 現れるときの縦の移動 |
| `--blur-in` | 6px | 現れるときのぼかし |

今のトークンは次のように置き換える。
`--dur-fast`（80ms）と `--dur`（150ms）は上の値に変え、`--dur-slow`（250ms）は `--dur-exit` に改め、`--dur-pop`（120ms）は `--dur` に寄せて消す。
`--ease` は `--ease-out` に改め、`--ease-in` を足す。
長さは必ずトークンを通して書き、CSS にも JS にも数値を直書きしない（今の `flip.ts` と `.memo-pencil` の直書きもトークンへ寄せる）。
reduced motion では、長さのトークンがすべて 0 になり、背景の光と端末の縁の往復も止まる。

### 動きの一覧

| 動き | 今 | これから |
|---|---|---|
| 画面遷移 | 120ms のクロスフェード | 出る画面は `--dur-exit` で消え、入る画面は `--dur` で `--rise` の移動とぼかしが晴れながら入る |
| 行を開いてセッション画面へ（新） | なし | 決めの動き。下で述べる |
| 一覧への差し込みと削除 | フェードとわずかな縦移動 | 新しい行はぼかしから現れ、ほかの行は FLIP で滑って場所を空ける |
| ⌘K パレット | 98% から 100%、120ms | ヘッダの検索欄の錠剤から、ガラスが広がって開く。閉じると錠剤へ戻る |
| ダイアログ | pop 120ms | 96% から、ぼかしが晴れながら `--dur` で開く |
| 通知 | 右下からスライド | 右下から、ぼかしが晴れながら滑り込む |
| 状態の点、ゲージ、TODO の線 | 色の遷移 | 長さを `--dur` に揃える。状態の点は変わる瞬間に 1 度だけ小さく膨らむ |
| 端末の縁の灯（新） | なし | 作業中は 3.2 秒で往復。状態が変わると色が `--dur` で移る |
| サイドバーの開閉（新、⌘B） | なし | 幅と中身を `--dur` と `--ease-out` で受け渡す。開閉のボタンは帯の右端に付いて、ワードマークの右と帯の一番上の間を移る。アイコンは帯へ滑り込み、項目名と図と名前（Hangar_）は、閉じるときは早めに薄れながら細くなる帯に切られ、開くときは項目と一緒に帯の上から下りてくる（名前は、帯が広がるにつれて開閉のボタンの陰から現れる）。開くとき、図のハンガーは起動画面と同じ振り子（6.3 rad/s、減衰 2.4 /s、振れ幅 7°）で揺れて止まる。動いている間は端末の寸法合わせを止め、止まってから一度だけ合わせる。検討した案は `collapse-motion.html`（採ったのは M4） |
| 背景の光（新） | なし | 24 秒かけて往復で漂う |
| 起動画面（新） | 静的な文字 | 2 の「起動画面」 |
| ホバーと押下 | 80ms、98% | `--dur-fast` で 1px 浮く、押すと 97% |
| 折りたたみ、タブの下線、分割の幅、数字の回転、新着への追従 | 各種 | 長さと曲線だけ新しいトークンに揃える。動き方は変えない |

### 決めの動き：行がセッション画面へ広がる

一覧の行か Home の実行中の札を開くと、その行が、そのままセッション画面の上段へ広がる。
名前と状態の点は、同じ場所から動いて上段の位置に着く。
戻ると、縮んで元の行へ帰る。

- View Transitions API（`document.startViewTransition`）で作る。
  開く行と、セッション画面の上段に、同じ `view-transition-name` を遷移の間だけ付ける。
  Mediator がハッシュの変化を描き直す箇所を `startViewTransition` で包み、React の描画は `flushSync` で同期させる。
- View Transitions が無い環境（macOS 13 と 14 の WKWebView）では、ふつうの画面遷移に落とす。
- reduced motion では使わない。

採らなかった決めの動き（新しい札が掛かる、入力待ちが降りてくる、縁の灯が一周する、終わった札が奥へ霞む）は、範囲外として末尾に残す。

## 5 試験と検証

見た目は試験で守りにくいので、「決まり」を試験で固定し、見た目は実物で確かめる。

### 書き換える試験

- `packages/ui/src/styles/tokens.test.ts`
  - 禁止の一覧を新しい決まりに合わせる。
    ダーク（`prefers-color-scheme`、`data-theme`）、`@keyframes shimmer`、スケルトン、`text-shadow` は引き続き落とす。
  - `backdrop-filter` は、ガラスの部品のクラスの規則の中にだけ現れることを確かめる。
    読む面の規則に紛れ込んだら落ちる。
  - `animation: pop var(--dur-pop) var(--ease)` のような今の文字列の一致は、新しいトークン名に合わせて直す。
    「長さを直書きしない」という守りは残す。
  - コントラスト：`--ink` と `--ink-2` が、白地と、ガラスを重ねた色（白 40% を `--bg` に重ねた色）の両方で 4.5 : 1 以上であること。
    ステータスの文字と淡い地の 4.5 : 1 の試験は残す。
- `packages/ui/src/views/overlays.test.tsx` などの、CSS の文字列を直接探している試験を、新しい規則に合わせる。

### 足す試験

- Home の Presenter：要対応と実行中の札が、正しいセッションを正しい順で拾うこと。
  問いの文、最新のツール呼び出し、文脈の使用率が、欄が空のときも含めて正しく出ること。
- サーバ：トランスクリプトの末尾から `live.activity` と `live.question` を取り出すこと。
  AskUserQuestion でない呼び出し、入力の形が崩れている呼び出し、呼び出しが無いときに空になること。
- 端末の縁：状態（busy、waiting、idle、終了）から正しい印が付くこと。
- 行が広がる動き：View Transitions が無い環境ではふつうの画面遷移に落ちること、reduced motion では使わないこと。
- タイトルバー：窓を動かす権限（`start-dragging`）と、ダブルクリックで拡大する権限（`internal-toggle-maximize`）が、`127.0.0.1:4177` の出どころにだけ、この 2 つだけ与えられていること（設定ファイルを読んで確かめる）。
- 行の高さ：`SessionRows` の見積もりが 44px を基準にすること。

### 実物で確かめること

- ブラウザと `.app` の両方で全画面を目で見て、画面の写しを残す。
- `.app`：信号の 3 点の位置、ヘッダを掴んで窓が動くこと、ボタンは掴めずに押せること、起動画面の動きと止まり方。
- 重さ：1,000 件の一覧のスクロールと、端末の出力が流れている最中に、ぼかしで引っかからないこと。
- reduced motion を有効にして、動きと光が止まること。

### 進め方の決まり

- 直したら返す前に必ずビルドする（UI の vite と、デスクトップの bundle-server と tauri build）。
  ビルドしたら、利用者の `npm run dev` のサーバ（4177）を一度落とす。止めるのは起動ログで確かめた PID だけで、ポート番号で止めない。
- `docs/design.md` の「画面」と「見た目と動き」を、実装と同じ流れで書き換える。
- 日本語の文書とコメントは一文ごとに改行し、地の文でダッシュと中黒を使わない。
  コミットメッセージは英語の Conventional Commits とする。

## 届け方

3 回に分けて届け、回ごとに実物で確かめてから `main` に入れる。
どの回の終わりでも、画面が壊れた見た目にならないようにする。

1. **見た目の言語、ロゴ、タイトルバー**。
   トークン、ガラス、読む面、形、色、文字、ロゴの原本とアプリアイコンと favicon、表示名、タイトルバーの溶け込み。
   窓を掴んで動かす仕組みは、この回の最初に実物で試す。
   効かなければ、代わりの手を試した結果と一緒に利用者に諮る。
2. **Home と一覧の行とサーバの新しい欄**。
   管制盤の Home、2 段の行（44px）、`live.activity` と `live.question`。
3. **セッション画面と動きと起動画面**。
   端末の縁の灯、フォルダの耳のタブ、動きのトークンと一覧、行が広がる動き、起動画面。

同じ時期に決めたこととして、行は 44px の 2 段とし、密度の切り替えは持たない。
要対応の札は、端末を開いてフォーカスするだけにする。

3 回目の実装（`docs/plans/ui-refresh-3-motion.md`）で、次のように決めた。

- 画面遷移の「出る画面は `--dur-exit` で消える」は、View Transitions の root を出る画面と入る画面で同じ長さと曲線にして重ねる形にした。長さを変えると、変わらないヘッダとサイドバーが途中で明滅するためである。
- ⌘K パレットは、開く動きを Web Animations で、閉じる動きを View Transitions で作った。開く側を View Transitions にすると描き替えが遅れ、打った文字を落とすためである。
- 行が広がる動きは、押した行か、フォーカスのある札か、一覧のカーソルの行からだけ始める。パレットやキーボードの近道から開いたときは、ふつうの画面遷移にする。
- セッション画面のチップの列の後ろに、cwd、ターン、トークン、時刻、run を注記の文字で残した。

## 未確かめとリスク

- **`data-tauri-drag-region` が、リモートの出どころの頁で効くか。**
  Tauri の IPC を `127.0.0.1:4177` に開く設定（`remote.urls`）で足りるはずだが、実物で試していない。
  実装の最初に確かめ、効かなければ代わりの手（殻が窓の上端に透明のつまみを置く、標準のタイトルバーへ戻す）を利用者に諮る。
- **ぼかしの重さ。**
  xterm の描画と 1,000 件の一覧の上で、WKWebView のぼかしが引っかからないかは測っていない。
  引っかかるなら、ぼかしの強さを下げるか、スクロール中だけ地を不透明に寄せる。
- **AskUserQuestion の入力の形。**
  問いの文の取り出しは、トランスクリプトに残る `input` の形に依る。
  実物のトランスクリプトで形を確かめてから書く。
- **macOS 13 と 14。**
  `-webkit-backdrop-filter` の併記と、View Transitions が無いときの落とし方で扱うが、その OS の実機では確かめられない。
