# プロジェクトを直接作る 設計

## この文書の位置づけ

新しいセッションのダイアログとプロジェクト画面から、プロジェクトを直接作れるようにする機能の設計である。
見た目の試作は `2026-10-01-new-project-ui/structure.html` にある（構成 P5）。
入口の置き方を 7 通り比べた試作は `2026-10-01-new-project-ui/entry.html` にある。
実装が済んだら、本体の設計書 `docs/design.md` の該当箇所（Intent の一覧、起動ダイアログ、Projects、プロジェクトの同定、決めた前提）へ内容を移す。

## 目的

いまプロジェクトができる経路は 3 つある。

- ワークスペースの直下で、セッションが 1 件以上あるフォルダの自動登録。走るのはサーバの起動時と、設定でワークスペースを変えたときだけである。
- スクラッチのセッションの昇格。
- `POST /api/projects { name, path }` による既存フォルダの登録。サーバにはあるが、UI から呼ぶ所が無い。

`project.new.open` と `project.new.submit` の Intent も定義だけあって、`NOT_YET_INTENTS` に入ったまま毎フェーズ先送りされてきた。
その結果、次のことができない。

- hangar から新しいフォルダで始める。いまはスクラッチで始めて昇格する遠回りしかない。
- セッションがまだ無いフォルダ（2026-10-01 の実測で ~/workspace 直下 112 個のうち 67 個）で始める。起動ダイアログは `projectId` かスクラッチしか受け付けない。
- アプリを開いたまま、ターミナルで新しいフォルダの claude を始めたときに、そのフォルダをプロジェクトにする。次にアプリを起動するまで未分類のまま残る。

うまくいった状態とは、⌘N から語を打って Enter と ⌘↵ だけで新しいフォルダのセッションが始まり、未登録のフォルダも検索で見つけて同じ手数で始められ、プロジェクト画面からはセッションを始めずにプロジェクトだけを作れることである。

## 利用者の決定（2026-10-01）

- 作り方は「新しいフォルダを作る（git init を選べる）」と「既存のフォルダを登録する」の両方を持つ。
- フォルダは、ワークスペースの未登録フォルダの一覧、パスの入力、macOS のフォルダ選択ダイアログ（Finder）の 3 つから選べる。
- 構成は P5 にする。起動ダイアログでは始める「場所」を選び、起動と同時にプロジェクトにする。プロジェクト画面には作成のダイアログを置く。
- アプリを開いている間に、ワークスペース直下の新しいフォルダでセッションが現れたら、その場でプロジェクトにする。設計書の決めた前提「ここで勝手にプロジェクトを作ることはしない」を、ワークスペースの外に限る形へ改める。

## 範囲の外

- 未登録フォルダの棚卸し（まとめて登録する、以後は候補に出さないと決める）。プロジェクト画面に未登録を並べる切り替えも作らない。
- ワークスペース直下より深い階層のフォルダを、未登録の候補に出すこと。深い階層は Finder かパスの入力で選ぶ。
- 起動ダイアログで、新しいフォルダの作り先をワークスペース以外にすること。

## 構成

### 2 つの入口の役割

2 つの入口は、来る目的が違う。

- 新しいセッションのダイアログに来た利用者の目的は、セッションを始めることである。プロジェクトを作ることは手段なので、作成と起動を 1 つのボタン（起動）にまとめる。
- プロジェクト画面に来た利用者の目的は、プロジェクトそのものである。作成で終えられるようにし、「作成して始める」を次の一手として並べる。

2 つの入口が共有するのは、サーバの処理（フォルダを作る、登録する）と、未登録フォルダの一覧の取り方である。
見た目の部品は共有しない。

### サーバ

#### 作る処理を 1 つにまとめる

`projects/create.ts` に次の 2 つを置く。

- `createProjectDir(deps, { name, gitInit })`：`<workspaceRoot>/<name>` を作り、選ばれていれば `git init` し、プロジェクト行とこの端末の `project_roots` を作る。名前の検証、`mkdir` を recursive にせず EEXIST で 409 にすること、`git init` に失敗したら作ったものを片付けること（`removeFreshDir`）は、いまの `promote.ts` の手順 1 と 2 をそのまま移す。
- `registerProjectDir(deps, { path, name? })`：既存のディレクトリを登録する。いまの `POST /api/projects` の中身（`normalizeDir`、ディレクトリの実在の確認、同じパスが登録済みなら既存を返す）を移す。名前を省いたら basename にする。登録済みのプロジェクトがアーカイブなら、Active に戻して返す（登録し直す操作は、使うという意思の表れなので）。

`promoteSession` の手順 1 と 2 は `createProjectDir` を呼ぶ形にし、昇格の振る舞いは変えない。
エラーは `ProjectCreateError`（status と文言）にまとめ、`PromoteError` はその上に乗せる。

#### API

- `POST /api/projects` の本文を 2 つの形にする。
  - `{ kind: 'newDir', name, gitInit }`：`createProjectDir`。作ったら 201。
  - `{ kind: 'dir', path, name? }`：`registerProjectDir`。新しく登録したら 201、登録済みなら 200。`kind` を省いた `{ name, path }` も `dir` として受ける（互換）。
  - どちらも `project.upsert` を配り、`ProjectDto` を返す。
- `GET /api/workspace/dirs`：ワークスペース直下の、隠しでなく、この端末で登録済みのルートに当たらないディレクトリを、名前順に `{ name, path }[]` で返す。比較は `normalizeDir`（NFC）でそろえる。一覧から削除したプロジェクトのフォルダは、ルートが論理削除されているので未登録に数える。

#### その場の自動登録

`server.ts` の `sessionChanged` で、未分類のセッションを `assignSession` で紐づけられなかったときに、次を行う。

1. cwd がワークスペースの直下のディレクトリ（またはその下）にあり、そのディレクトリが実在し、隠しでなく、まだ登録されていなければ、起動時の `syncProjectsFromWorkspace` と同じ規則でプロジェクトを作る。
2. `assignSession` をもう一度呼び、`project.upsert` と `session.upsert` を配る。
3. 当たらなければ、いまと同じく `tellUnassigned` で 1 度だけ知らせる。知らせはワークスペースの外の cwd だけになる。

この処理は `registry.ts` に `registerWorkspaceChildOf(db, deviceId, workspaceRoot, cwd)` として置く。
同じセッションで何度も試さないよう、試したセッションを `toldUnassigned` と同じく覚える。
起動の途中（`started` が偽）は行わない。起動時の全走査は `syncProjectsFromWorkspace` が受け持つ。

### デスクトップの殻

- `tauri-plugin-dialog` を足し、殻の命令 `pick_folder` を作る。中で `app.dialog().file().blocking_pick_folder()` を呼び、選んだパスの文字列か、取り消しなら null を返す。既定の開く場所はワークスペースのルートにし、引数で受ける。
- 頁に許すのは `pick_folder` の 1 つだけで、プラグインの JS の権限は与えない。capability は `remote-pick-folder.json` を足し、出どころを `http://127.0.0.1:4177/*` に絞る。`build.rs` の `COMMANDS` に載せる。
- UI の `DesktopBridge` に `pickFolder(defaultPath): Promise<string | null>` を足す。ブラウザでは口が無いので、Finder の操作を出さない。

### 新しいセッションのダイアログ

#### 一覧

始める場所の一覧の中身は、いまと同じ（すぐ始める、最近、すべて）である。
次の 2 つを足す。

- **未登録のフォルダ**：`GET /api/workspace/dirs` の結果を、検索欄に語があるときだけ一覧に混ぜる。何も打っていない一覧には出さない。行はフォルダのアイコン、名前、パス、「未登録」の札である。
- **下端の操作**：行の下、キーの案内の上に、スクロールしても動かない操作の段を置く。
  - 1 行目は、語が無ければ「新しいフォルダを作る…」。語があり、それと同じ名前のプロジェクトも未登録のフォルダも無ければ「『<語>』を新しいフォルダとして作る」にし、右に `~/workspace/<語>` を添える。同じ名前があるときは 1 行目を「新しいフォルダを作る…」のままにする。
  - 2 行目は「ほかの場所を選ぶ…（Finder）」。殻の中だけで出す。

下端の操作は、矢印キーで行の続きとして辿れ、Enter で選べる。
語が一致する行が無いときは、最初の操作に印を置き、そのまま Enter で選べるようにする。

この 2 つのために `Listbox` に次を足す。

- 選択肢の `searchOnly`：語があるときだけ一覧に出す。
- `actions`：語を受けて操作の配列を返す関数。操作は `{ value, label, sub?, icon }` で、選ぶと `onAction(value, query)` を呼ぶ（`onChange` は呼ばない）。

#### 選んだ後

選んだ場所によって、見出しと、一覧の直下の 1 行が変わる。
ボタンはどれも「起動」のままで、見出しで何が起きるかを言う。

| 選んだもの | 見出し | 一覧の直下 |
|---|---|---|
| プロジェクト | 新しいセッション | なし（いまのまま） |
| スクラッチ | スクラッチで始める | いまの説明 |
| 新しいフォルダ | 新しいフォルダで始める | 「フォルダの名前」の欄（打った語を入れる）、「~/workspace/<名前> を作り、プロジェクトに登録して起動します」、git init のチェック（既定はオン） |
| 未登録のフォルダ | フォルダを登録して始める | 「~/workspace/<名前> はまだプロジェクトではありません。起動すると登録します」 |
| Finder で選んだフォルダ（ワークスペースの直下） | フォルダを登録して始める | 未登録のフォルダと同じ |
| Finder で選んだフォルダ（ワークスペースの外か深い階層） | フォルダを登録して始める | 「ワークスペースの外のフォルダです。この PC でのパスだけを覚えます。ほかの PC では、開いたときに場所を聞きます」 |

Finder で選んだパスが登録済みのプロジェクトのルートなら、そのプロジェクトを選んだ状態にする（見出しも「新しいセッション」）。
Finder を取り消したら、選択を変えない。

一覧の顔（閉じた欄）は、新しいフォルダならフォルダに＋のアイコンと「<名前>　~/workspace/<名前>（新しく作る）」、未登録と Finder のフォルダならフォルダのアイコンと名前とパスを出す。

詳細（model など）の初期値は、新しいフォルダと未登録のフォルダでは前回値が無いので既定である。

#### 起動の流れ

送信の params に、場所の指定 `place` を足す。

- `{ kind: 'newDir', name, gitInit }`
- `{ kind: 'dir', path }`

`place` があるときは、Mediator が `api.createProjectThenLaunch` の副作用を出し、runtime が次の順に行う。

1. `POST /api/projects` で作るか登録する。失敗したら `launch.failed` を返して終える（プロジェクトはできていない）。
2. できたプロジェクトを store に入れ、`project.created { projectId, from: 'newSession' }` を Mediator へ送る。Mediator はダイアログの選択をこのプロジェクトに差し替え（`overlay.projectId`）、送った詳細をこのプロジェクトの前回値にする。
3. `projectId` を入れた params で、いまの `api.launch` と同じ起動をする。結果は `launch.done` か `launch.failed` である。

2 の後に起動が失敗したら、プロジェクトは残し、ダイアログはできたプロジェクトを選んだまま失敗の文言を出す。
押し直しても、もう一度作ることはない。
ダイアログは `projectId` を開いたときにだけ読むので、`overlay.projectId` が変わったら選択を合わせる。

### プロジェクト画面

#### 入口

見出しの行の右端（アーカイブを表示の右）に、主のボタン「＋ 新しいプロジェクト」を置く。
押すと `project.new.open` を送り、作成のダイアログを開く。
パレットのコマンドにも「新しいプロジェクト」を足す。

#### 作成のダイアログ

見出しは「新しいプロジェクト」（フォルダに＋のアイコン）で、本文の頭に「新しいフォルダを作る／既存のフォルダを登録」の切り替えを置く。

- **新しいフォルダを作る**：「プロジェクト名」の欄（等幅、「ワークスペースに作るディレクトリの名前」）、「~/workspace/<名前> を作ります」、git init のチェック（既定はオン）。昇格のダイアログの見た目にそろえる。
- **既存のフォルダを登録**：未登録のフォルダの検索付きの一覧（`GET /api/workspace/dirs`）、「ほかの場所を選ぶ…（Finder）」のボタン、パスの入力の欄。どれかで選んだフォルダの basename を「プロジェクト名」の欄に入れる（直せる）。

下端は「やめる」「作成」「作成して始める」（主）である。

- 「作成」：作ったらダイアログを閉じ、そのプロジェクトの画面へ移る。
- 「作成して始める」：作ったら、新しいセッションのダイアログを、そのプロジェクトを選んだ状態で開く。

送信中は両方のボタンを押せなくする。
失敗の文言はダイアログの中に出し、入力は残す。
背景を押しても閉じない（書きかけを失わないため）。
Enter は、名前とパスの欄では送信（「作成して始める」）にし、一覧の中では選択にする。

#### Intent と状態

Intent を次の形に改める。

```ts
| { type: 'project.new.open' }
| { type: 'project.new.submit'; place: ProjectPlace; startSession: boolean }
```

`ProjectPlace` は shared に置き、`{ kind: 'newDir'; name: string; gitInit: boolean } | { kind: 'dir'; path: string; name?: string }` とする。起動の `place` も同じ型を使い、起動ダイアログは `dir` の `name` を省く（basename になる）。
overlay に `{ kind: 'newProject' }` を足し、`state.projectCreate`（idle、submitting、failed）を持つ。
`NOT_YET_INTENTS` から `project.new.open` と `project.new.submit` を外す。

### 未登録フォルダの一覧と Finder の結果の受け渡し

- 新しいセッションのダイアログと作成のダイアログを開いたときに、Mediator が `api.workspaceDirs` を出し、結果を `workspaceDirs.loaded` で `state.workspaceDirs` に入れる。プロジェクトが作られたら（`project.upsert`）、そのパスを一覧から外す。
- Finder は `desktop.pickFolder` の副作用で開き、結果を `folder.picked { path }` で返す。Mediator は開いているダイアログに渡すため、`state.pickedFolder = { path, n }` に入れる（n は同じパスをもう一度選んでも気付くための回数）。取り消しは何もしない。

### エッジケース

- 名前が空、`.`、`..`、`/` や `\` を含む：サーバが 400 で断り、ダイアログに文言を出す。UI では送る前に止めない（判定をサーバの 1 か所に置く）。
- 同じ名前のフォルダが既にある：起動ダイアログでは「作る」の操作を出さず、未登録かプロジェクトの行として見せる。サーバも 409 で断る。
- 選んだパスがディレクトリでない、無い：サーバが 400 で断る。
- 選んだフォルダが別のプロジェクトの中にある：登録してよい。セッションは最も深いルートに紐づく（いまの `longestMatch`）。
- 作った直後に同期を受けたほかの PC：その PC にはルートが無いので、プロジェクトは「見つかりません」になり、いまの再指定のダイアログが扱う。
- 新しいフォルダでは Claude が信頼確認のダイアログを出す。起動ダイアログの末尾の注意書きはそのまま残す。

## 試験

- サーバ：`createProjectDir`（作る、git init、片付け、409、名前の検証）、`registerProjectDir`（正規化、登録済み、アーカイブから戻す、basename）、`POST /api/projects` の 2 つの形と互換、`GET /api/workspace/dirs`（隠し、登録済み、NFD、論理削除）、`registerWorkspaceChildOf` と `sessionChanged` のその場の登録（直下、深い階層、外、起動の途中）、昇格の振る舞いが変わらないこと。
- UI：`Listbox` の `searchOnly` と `actions`（表示の条件、矢印キー、Enter、一致が無いときの印）、起動ダイアログの選択ごとの見出しと 1 行、`place` の送信、作成後の起動の失敗で選択が差し替わること、作成のダイアログの 2 つのモードと 2 つのボタン、Mediator の遷移（`project.new.*`、`project.created`、`workspaceDirs.loaded`、`folder.picked`）。
- 殻：`build.rs` の `COMMANDS` と `lib.rs` の命令と capability の突き合わせ（`apps/desktop/test/config.test.ts`）。
- 実物：ビルドしたアプリで、新しいフォルダ、未登録のフォルダ、Finder の 3 つで起動し、プロジェクト画面から作成と作成して始めるを確かめる。ターミナルで新しいフォルダの claude を始め、その場で登録されることを確かめる。
