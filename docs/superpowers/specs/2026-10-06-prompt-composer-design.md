# 初期プロンプト欄の候補と添付

2026-10-06。試作は利用者の手元の `~/workspace/hangar-explainers/prompt-input-2026-10-06/index.html`（この PC のスキルの名前と回数が入るので、リポジトリには置かない）。

## 利用者の要望

- 新しいセッションのダイアログの初期プロンプト欄でも、スキルなどを呼び出したい。候補に出るようにしたい。
- 画像も入れられるようにしたい。Claude Code の入力欄でできる主なことは網羅したい。

## 確かめたこと

起動引数の末尾に置く初期プロンプトは、いまのまま使える。専用の tmux で claude を対話で起動して確かめた（Claude Code 2.1.289）。

| 渡したもの | 結果 |

| `/スキル名 引数` | スキルとして実行された |
| 文章＋画像の絶対パス | Claude が画像を読んで答えた |
| `@note.txt` と `@red.png` | 起動と同時に 2 つとも読み込まれた |

| 同じ文を `--add-dir <置き場>` つきで渡す（Claude Code 2.1.290） | 尋ねられずに画像を読んで答えた |

利用者の履歴では、最初の一言の約 2 割が `/` 始まりだった。その中でいちばん多いのは `/model` と `/effort`（ダイアログの詳細に欄があるもの）で、次にスキルが続いた。

## 決定

### 範囲

`/` の候補、画像とファイルの添付、`@` のファイル指定の 3 つを入れる。実装もこの順にする。

### `/` の候補に出すもの

- 自分のスキルとコマンド（`<claudeDir>/skills/*/SKILL.md`、`<claudeDir>/commands/**/*.md`）。
- 選んだプロジェクトのスキルとコマンド（プロジェクトの `.claude/skills`、`.claude/commands`）。スクラッチでは無い。
- 有効なプラグインのスキルとコマンド（`installed_plugins.json` の置き場から読み、`プラグイン:名前` の形にする）。
- 組み込みのうち最初の一言になるもの。ファイルから読めないので、コードに短い一覧を持つ（`init`、`review`、`code-review`、`security-review`、`loop`、`schedule`）。

出さないもの。

- 会話の途中でしか意味がないもの（`compact`、`clear`、`copy`、`context`、`resume`、`exit` など）と、端末の設定のもの（`login`、`mcp`、`doctor`、`plugins` など）。
- `model` と `effort`。ダイアログの詳細に欄がある。
- frontmatter が `user-invocable: false` のスキル。

### 並べ方と行（A1）

- 打つ前は群で並べる。「よく使う」（回数の上位 5 つ、回数が 0 のものは入れない）、「このプロジェクト」「自分の」「プラグイン」「組み込み」の順。
- 回数は、`history.jsonl` でセッションの最初の一言になった数にする。
- 打ち始めたら群を解く。名前の頭の一致、名前の途中の一致、説明の一致の順に並べ、同じなら回数の多い順。
- 行は 2 段。1 段目に `/名前` と引数の形（`argument-hint`）、2 段目に説明の 1 行目、右に出どころの札。一致した部分を塗る。
- 見た目と置き方は Listbox に合わせる。ダイアログの外へはみ出して開き、下に収まらなければ上に開く。

### きっかけとキー

- `/` は欄の先頭だけ。先頭から空白までの語にカーソルがある間、候補を出す。Claude Code がコマンドとして読むのは先頭だけだからである。
- `/` の後の語に 2 つ目の `/` が入ったら、候補を出さない。スキルの名前に `/` は入らず、貼ったパス（`/Users/x`）の下に「一致するものはありません」を出しても邪魔なだけだからである。`@` の語はパスなので、`/` が入ってよい。
- `@` は欄の先頭か空白の直後。そこから空白までの語にカーソルがある間、候補を出す。
- 候補が開いている間、↑↓ で選び、Enter か Tab で確定する。Esc は候補だけを閉じ、ダイアログには届かせない。
- Shift+Tab は逆向きの移動、⌘Enter と Ctrl+Enter は起動なので、候補を使わずにそのまま通す。
- 行が無いとき（一致なし、読めなかった。`/` の読み込み中も）は、↑↓ と Enter と Tab も通す。複数行の欄で、カーソルの移動と改行を奪わないためである。
- ただし `@` で、いまの問いの返事をまだ受けていない間（前の問いの一覧を薄く残している間と、最初の読み込み中）は、Enter と Tab を通さず、何も入れずに止める。通すと Enter が欄の改行になり、`@` の語がそこで終わるためである。↑↓ と Shift+Tab と ⌘Enter は通す。返事が来たら、いつもどおり入れる。
- 変換中（IME）の Enter と Esc は、確定にも取り消しにも使わず、ダイアログにも届かせない。変換の確定と取り消しは IME に任せる。
- 候補が閉じている間の Enter は改行、⌘Enter は起動で、いまのまま。

### 確定したときの文

- 確定は、きっかけからカーソルまでを `/名前 ` か `@パス ` に置き換える。カーソルの後ろの文は、ひとつも消さない。「スキル」と「ファイル」のボタンはカーソルの前に記号だけを入れるので、後ろには利用者が打った文が続いていることがある。語の末尾まで置き換えると、日本語の文では語が文の残り全部になり、打った文を黙って消すことになる。
- 後ろがすでに空白で始まるなら、空白は足さずに、そこへカーソルを置く。
- 空白を含むパスは `@"パス"` の形で囲む。そのままでは空白で語が切れる。Claude Code が起動時にこの形を読むことは、「確かめたこと」の表のとおり。`/` の名前は囲まない。

### 添付（B1）

- 経路は 3 つ。欄へのドロップ、⌘V での貼り付け（クリップボードにファイルがあるとき）、道具の段の添付ボタン。
- 欄の下に札で並べる。画像は 44px の絵、それ以外は拡張子の印。名前と大きさを添え、× で外す。絵が読めなければ（置き場から消えたときなど）、拡張子の印に替える。
- 送っている間は、1 件ごとに「送っています」の札を出す。札は渡された順に並べ、後のものが先に終わっても、先のものが終わるまで確定を待つ。
- 1 件でも送っている間は、起動ボタンを押せなくして「添付を送っています」と読ませ、⌘Enter も起動しない。添付が抜けたまま起動しないためである。
- ダイアログを閉じた後に送り終えたものは、着いた添付だけを、そのときの下書きへ足す（`session.new.draft.attach`。名前と本文には触れない。下書きが無ければ、名前と本文が空のものを作る）。閉じるときの名前と本文で下書きを置き換えると、開き直したダイアログの書きかけを上書きしたり、起動して消えた下書きを蘇らせたりするためである。起動を送った後なら足さない（起動し終えたら下書きは消える）。
- 貼り付けにファイルと文字が一緒にあるとき（表計算や文書ソフトからのコピーは、セルの絵と文字を同時に置く）は、ファイルを添付にし、文字も欄に貼る。文字がファイル名だけの行（Finder でファイルをコピーしたとき）なら、文字は貼らない。
- 送信は 60 秒で打ち切り、「失敗のとき」と同じに扱う。
- ブラウザでは、欄を少し外してファイルを落としてもページがそのファイルへ移らないよう、部品がある間は窓全体でファイルのドラッグと落とす動きの既定の動きだけを止める。欄の外では何も添付しない。
- 置き場は `~/.agent-hangar/drops/`。端末へのドロップと同じで、7 日で消える。
- 起動のとき、UI が「本文、空行、添付のパスを 1 行ずつ」を初期プロンプトとして組み立てる。起動の API と MCP の `create_session` は、入口も形も変えない。変わるのは、サーバが置き場を自分で足すことだけである。本文が空で添付だけでも起動できる。
- 初期プロンプトに添付のパスの行（置き場の直下のファイルのパスだけの行。空白を含むものは単一引用符で包んだ行）があるときは、サーバが置き場を `--add-dir` で claude に渡す。置き場は作業ディレクトリの外なので、渡さないと Claude Code は読む前に許可を尋ねて止まる（「確かめたこと」の表のとおり）。利用者に尋ねて決めた。引き換えに、そのセッションは置き場の全体（7 日分の添付。ほかのプロジェクトのために置いたものも含む）を、尋ねられずに読み書きできる。
  - 利用者が自分で渡した `addDirs` が先で、置き場は後ろに 1 度だけ足す。すでに渡してあれば重ねない。
  - 足すのは新規の起動だけで、再開、フォーク、引き取り、ターミナルからの起動には足さない。MCP の `create_session` も同じ起動の処理を通るので、本文に添付のパスの行があれば同じに足す。
  - 足すのは claude に渡す引数だけで、run に残す起動の設定は送られたままにする。画面が「前回の設定」として覚える `addDirs` に、置き場が混ざらないためである。
- 1 件 20 MB まで。
- 下書きは、名前と本文に加えて添付も覚える。添付だけが残っていても下書きとして持つ。戻したときに置き場から消えていた添付は外す。確かめられなかったときは残す（外して失うより、起動の文に残るほうが害が小さい）。

### `@` のファイル

- 選んだプロジェクトのファイルを候補に出す。打つ前は最近変えたもの 20 件、打ったら一致するものを 50 件まで。
- 並べ方は、ファイル名の頭の一致、ファイル名の途中の一致、パスの途中の一致の順で、同じなら短いパスを先にする。問いに `/` が入っていれば、パスの一致だけを見る。
- 行は 1 段。ファイル名を太く、フォルダを薄く。「最近変えたファイル」の見出しは、問いが空のときだけ出す。
- 問いは、打ち終わってから 120 ミリ秒待って送る。問いが空（`@` だけ、「ファイル」ボタン）のときは待たない。
- 新しい返事を待つ間は、同じ `@` の前の問いの一覧（空でないもの）を、薄くして出したままにする。打鍵のたびに「読み込んでいます」へ替わると、一覧がちらつくためである。薄い一覧は見せるだけで、Enter、Tab、押すことのどれでも入れられない。いま打った語の候補ではないからである。
- 一覧は 1 つの `@` の間だけ持つ。閉じるか、別の `@` に移るか、プロジェクトを選び直したら捨てる。無関係な一覧を、新しい `@` の最初に見せないためである。
- スクラッチとパスの無いプロジェクトでは出さない。道具の段のボタンは押せなくし、理由を添える。

### 入口（C2）

- 欄を箱にし、下端に道具の段を置く。「/ スキル」「@ ファイル」「添付」の 3 つのボタンと、右に「画像は ⌘V でも貼れます」。
- ボタンは、打ったときと同じ状態にする（`/` は先頭に入れて候補を開く、`@` はカーソルの位置に入れて候補を開く）。
- 欄は行数に合わせて伸び、上限で止まって中で送る。

### 試作で退けたもの

- 一覧の形 A2（1 段の詰めた行）と A3（一覧＋右に詳細）。
- 添付の見せ方 B2（箱の中の小さな札）と B3（文の中の `[画像 1]` の印。印を手で消すと添付とずれる）。
- 入口 C1（プレースホルダだけ）と C3（注記の 1 行）。

## 作り

### サーバ

| 口 | 返すもの |
|---|---|
| `GET /api/prompt/commands?projectId=` | `{ commands: [{ name, description, argumentHint?, source, uses }] }`。`source` は `project`・`user`・`plugin`・`builtin` |
| `GET /api/prompt/files?projectId=&q=` | `{ files: string[] }`。プロジェクトの根からの相対パス |
| `POST /api/drops?name=` | 本文をそのまま受け取り（`application/octet-stream`）、`{ path, name, size }` を 201 で返す。空の本文は 400、20 MB を超えるものは断る |
| `POST /api/drops/existing` | 本文は `{ paths }`。そのうち、絶対パスでいまも存在するものを `{ paths }` で返す。下書きから戻した添付のうち、置き場から消えたものを外すために使う |
| `GET /api/drops/:name` | 置き場のファイル。札の絵に使う。画像の種類（png、jpeg、gif、webp）だけを画像として返し、ほかは `application/octet-stream` にして `nosniff` を付ける |

- スキルの読み取りは `packages/server/src/prompt/commands.ts` に置く。frontmatter の `name`、`description`、`argument-hint`、`user-invocable` を読む。読めないファイルは飛ばす。
- 回数は `history.jsonl` を読んで数え、ファイルの更新時刻が変わるまで覚えておく。
- ファイルの一覧は `packages/server/src/prompt/files.ts` に置く。次の作りにする。
  - git の呼び出しは非同期で行い、5 秒で打ち切る。git でないフォルダの歩きと、その最近変えたファイルの `stat` は同期だが、上限がある（深さ 6、5,000 件、訪ねるフォルダ 2,000。`stat` も歩いた 5,000 件まで）。同期の呼び出しで単一プロセスのサーバを長く止めないためである。
  - 同じプロジェクトへ同時に来た呼び出しは、1 つの仕事を分け合う。できた一覧は 10 秒覚え、覚えておく根は最近使った 8 つまでにする。
  - 作業ツリーかどうかは、`.git` の有無ではなく `git rev-parse --is-inside-work-tree` で尋ねる。リポジトリの下のフォルダをプロジェクトにしていても、`.gitignore` が効く。
  - 作業ツリーなら `git ls-files -c -o --exclude-standard`（追跡しているものと、追跡外で無視されていないもの）を使い、覚える件数は 20 万件までにする。
  - 作業ツリーでないとき（終了コード 128）は、歩いて探す。深さ 6、5,000 件、訪ねるフォルダ 2,000 までにする。`.` で始まるフォルダと `node_modules` には入らず、シンボリックリンクはたどらない。
  - git が止まったり壊れたりしたら、その根では 60 秒、git を呼び直さずに歩く探し方で答える。打つたびに git を待たせないためである。
  - 一覧にあっても、いまは無いファイルは返さない。落とした分を補えるよう、少し多めに取ってから 50 件に切る。
  - 問いが空のときの「最近変えたファイル」は、git のプロジェクトでは、作業ツリーの変更（新しい順に最大 200 件を見る）、続けて最近 30 件のコミットで触れたファイルの順に 20 件を返す。全件の `stat` はしない。git でないプロジェクトでは、歩いた結果を更新時刻の新しい順に返す。
- `drops` は名前を殻（`filedrop.rs` の `sanitize`）と同じ規則で直し、`<時刻>-<連番>-<名前>` で置く。読むのも書くのも置き場の中だけにし、外へ抜けるパスは断る。置き場の中のシンボリックリンクは返さない（`lstat` で見て、通常のファイルだけを返す）。リンクを辿ると、置き場の中から外のファイルを読ませてしまうからである。
- 本文を持つ要求の型は JSON だけという入口の規則（`docs/design.md` の「入口の 3 つの検査」）に、動詞と経路が完全に一致する 1 つだけの例外を足す。`POST /api/drops` に限って `application/octet-stream` を通す。例外が保つものは次のとおり。
  - この型は、前検査（preflight）の要らない「単純な要求」で使える型（`text/plain` など）ではない。別のサイトのページから送ると前検査が起き、CORS の許可を返さないので、届かない。JSON だけにしている理由は、この型でも保たれる。
  - トークン、Origin、`Sec-Fetch-Site` の検査はそのまま効く。
  - 例外は表で持ち、動詞、経路、型がそろったものだけを通す。「単純でない型なら通す」には広げない。

### UI

- `views/primitives/PromptComposer.tsx`：欄の箱、道具の段、候補、添付の札。
- `views/primitives/promptComposerModel.ts`：きっかけの判定、並べ方、確定したときの文、起動のときの文の組み立て。画面を持たない関数にして単体で試験する。
- 候補と添付の読み書きは、`ResolveProjectDialog` の候補と同じく、Root が api を呼び、`PromptAssistContext`（`views/primitives/promptAssist.ts`）で部品に配る。画面は fetch を呼ばない。Context の無い場所（部品だけの試験）では、何も返さない既定を使う。Intent で運ぶのは下書き（`session.new.draft`。添付を含む）と、遅れて着いた添付を足す `session.new.draft.attach` だけである。
- プロジェクトを選び直したら候補を読み直す。
- 殻からの `hangar:drop` は、落とした位置が欄なら添付に回す（`main.tsx` の受け口に行き先を足す）。端末に落としたときの動きは変えない。
- ドラッグ中に欄の色を変えるため、殻が `hangar:drag` を送る。動いている間は落とす位置の座標を送り続け、出たときと落としたときは null を送る。殻の窓では Web 側にドラッグのイベントが届かないからである。欄は、座標が欄の上かどうかで色を変える。ブラウザで開いたときは Web のドラッグのイベントを使う。
- 下書きから戻した添付は、開いたときに 1 度だけ `POST /api/drops/existing` で確かめる。

### 失敗のとき

- 保存に失敗したら右下の知らせを出し、札は足さない。20 MB を超えたものも同じ。
- 候補が読めなければ、候補の中に「読めませんでした」と出す。欄はそのまま打てる。

## 試験と確かめ

- 単体：きっかけの判定、並べ方、文の組み立て、スキルの読み取り（frontmatter、プラグイン、`user-invocable`）、回数、ファイルの一覧、`drops` の経路の閉じ込め。
- 画面：候補の開閉とキー、変換中の Enter、Esc がダイアログを閉じないこと、添付の足し引き、下書きの復元。
- 実物：WebKit で撮る。ビルドしたアプリで、`/スキル`＋画像＋`@ファイル` の初期プロンプトから実際に起動する。

## 残り

意図して残した、知っていることである。

- 欄は `role="combobox"` を持たない。付けると、既存の画面の探し方（textbox）の試験とぶつかり、複数行の欄としても読まれなくなる。`aria-autocomplete`、`aria-controls`、`aria-activedescendant` は付けるが、候補が開いていることは読み上げに伝わらない。
- 札の行へのドロップは、落とし先にならない。落とせるのは欄の箱の中だけである。
- フォルダを落としたときは、元のパスのまま添付になる。置き場の下ではないので、Claude Code は読む前に許可を尋ねる。
- hangar の home のパスに単一引用符が含まれると、置き場の自動の `--add-dir` は付かない。
