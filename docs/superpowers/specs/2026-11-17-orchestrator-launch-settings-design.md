# 統括の起動の設定（アプリ・アカウント・モデル・effort）設計

2026-11-17。利用者と決めた。試作は scratchpad の `orch-settings.html`（案 A を採用）。

## なぜ

- 統括は常駐していて、Claude の週の枠を食う。統括だけ別のアカウントや安いモデル、Codex やローカルの LLM（opencode）で動かしたい。
- アプリごとに統括の役が務まるかを比べたい。
- Claude を契約していない一般の利用者にも統括を使えるようにしたい。

今は Claude Code を既定のアカウントで起こすだけである。設定の model と effort は起動に渡るが、画面から変える手段が無い。統括の欄は「Claude Code」の節にある入り切りのスイッチ 1 つだけである。

## 目標

- 設定の目次に独立の「統括」の節を立て、入り切り・起動の札（アプリ・アカウント・モデル・effort）・声を 1 か所にまとめる。「Claude Code」の節からは外す。
- 選べる項目と札は新規のダイアログと同じにする（`LaunchChips` を使い回す）。アプリを変えると、そのアプリの札に入れ替わる（opencode はアカウントと effort が無く、モデルは接続先ごとにまとまる）。
- 動いている間に変えたとき：
  - アカウント・モデル・effort は同じ会話に当てる。統括が idle なら（busy なら idle になってから）、同じ会話を止めて新しい指定で再開する。この止め方は利用者の停止と区別し、入り切りを切にしない。
  - アプリを変えたら新しい会話に切り替える。前の会話は消さない。#702 の段 2（系譜と申し送り）ができたら、その切り替えを使う。それまでは申し送りなしで新しい会話を起こす。
- Codex と opencode の統括は、Claude と同じ安全の境界を持つ（手を動かす道具を使えない、Remote Control を付けない、プロジェクトの段を足さない）。

## 目標でないもの

- 統括を動かす PC を選ぶこと（PC ごとに 1 本のまま）。
- 統括の会話の作り直しそのもの（#702 の範囲）。

## 案

| 案 | 中身 | 得失 |
|---|---|---|
| 置き場 A 独立の節（採用） | 「統括」の節に入り切り、札の行、声を縦に並べる。切ると下が畳まれる | 見つけやすい。声もここへ寄せられる |
| 置き場 B 1 行 | 入り切りの行に札を横に並べる | 狭い窓で札が折り返す |
| 置き場 C 柱で選ぶ | 柱の丸のメニューで選ぶ | 試しに変えるのは速いが、設定を探した人が見つけにくい |
| 進め方：段階（採用） | 段 1 Claude の札と節、段 2 Codex とアプリの切り替え、段 3 opencode | 早く出せる。安全の境界をアプリごとに確かめられる |
| 進め方：まとめて | #702 の後に 3 つ一度に | 届くまでが長く、#702 と同じ所を同時に触る |

## 中身

### 段 1：「統括」の節と Claude の札

- `OrchestratorSetting` に `account: string | null`（null は既定のアカウント）を足す。PATCH は `enabled・model・effort・account` を受ける。知らないアカウントの id は 400。
- `startOrchestrator` と見張りの再開は、設定のアカウントで起こす（再開は前に使ったアカウントではなく、設定の値を優先する）。
- 設定のアカウント・モデル・effort が変わり、統括が動いていたら、idle で同じ会話を止めて新しい指定で再開する（上の「動いている間に変えたとき」）。
- `SETTINGS_SECTIONS` に `orchestrator` を `sessions` の次に足す。節は、入り切りの行、札の行（アカウント・モデル・effort。段 1 ではアプリの札を出さない）、声（今の `VoiceSettings` をここへ移す）。切ると札の行と声が `collapseOut` で畳まれ、入れると `growIn` で出る。
- 古いサーバ（orchestrator を返さない）では節を目次に出さない。

### 段 2：Codex とアプリの切り替え

- `OrchestratorSetting` に `agent: AgentKind`（既定は Claude Code）を足し、札の行の先頭にアプリの札を出す。並べるのは設定で有効にしたアプリだけ。
- 統括の起動を driver ごとにする：役の文（developer instructions）、MCP、安全の境界（Codex は sandbox を read-only にし、hangar の MCP の道具は通す）。統括の印（`markOrchestrator`）、`[hangar]` の入力の渡し方、太ったときの手当ては、Codex でも効くようにする。
- 安全の境界は実物で確かめる。統括にファイルを書かせる・シェルを打たせると断られること。

### 段 3：opencode

- opencode の `permissions` で edit・write・bash を断る規則を統括に重ねる。モデルは LM Studio と Zen ごとにまとめて並べる。
- ローカルのモデル（Qwen3.5-9B など）で統括の道具の呼び出しが務まるかを実物で試し、結果を残す。

## 作り手に任せること

- 再開し直しの待ち方（idle の見張り方、何秒まで待つか）。
- 札の部品の切り出し方（`LaunchChips` をそのまま使うか、薄い包みを作るか）。
- 画面の文言は Gemini に当てて決める（決まりどおり）。
