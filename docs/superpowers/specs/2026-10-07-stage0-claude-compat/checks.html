確認リストの 6 行目「Claude Code との互換」 試作

spec「段 0」の「画面」の節の試作。状態は 3 つ（問題なし／未確認の版／ずれ N 件）。見本の値は、確かめた版 2.1.292、手元の版 2.1.300、ずれ 3 件（うち 2 件が機能を止め、1 件は記録だけ）。案は 3 つの軸で分け、どの案も 3 つの状態を並べる。色と書体は packages/ui/src/styles のトークンを写した。

いまの確認リストの描かれ方

  • 5 行の確認リスト（presentChecks）は views/Onboarding.tsx の CheckRow が描く。CSS は styles/readiness.css の .ck-*。
  • 出るのは初回の札だけ。セッションも、スクラッチ以外のプロジェクトも無いときの空のホームである（presenters/onboarding.ts）。
  • 設定画面に確認リストは無い。同じ判定を、欄の下の 1 行（VerifyRow、.verify）、節の見出しの札（Badge、.badge）、群の見出しの「直すもの N 件」と目次の点で出している。
  • このため spec の「設定の確認リストに 6 行目」をそのまま入れると、使い始めたあとのずれはどこにも出ない。置き場を軸 3 で比べる。

軸 1　ずれの中身の開き方 文言はどれも B1、置き場は初回の札（上の 5 行は statusline だけ薄く残す）

得る札の高さがほかの行とそろい、6 行が一目で見渡せる。中身は押せばその場で開く。
失う止めた機能は開くまで見えない。「何が使えないか」を知るのに 1 手要る。

A2行の下に小さな表を常に出す

得る押さずに全部見える。報告するときもそのまま読める。
失う件数だけ札が伸び、値や版のように利用者が手を打てない文字が常に並ぶ。620px の札では表が詰まる。

A3別のダイアログで開く

得る札は 1 行のまま。広い表と「報告用に写す」を置く余裕がある。
失う読むだけのものに重ね窓を開く。札と見比べられず、止めた機能も開くまで見えない。

A4止めた機能は常に出し、細目（契約・値・版・時刻）だけ畳む推す

得る「何が止まっているか」は押さずに見え、値・版・時刻は報告するときだけ開けばよい。
失う1 行の中に 2 段（機能の列挙と畳んだ表）を持ち、作りが少し重い。止めた機能が多いと札が伸びる。

軸 2　行の文言と添え物 版の出し方・件数の出し方・止めた機能の言い方。開き方はどれも A4（閉じた形）

B1版は場所の欄に「X（Y）」で、件数は「ずれ 3 件」、機能は「〜を止めています」推す

得るtmux・claude の行（パス（版））と同じ文法で読める。「止めています」で、hangar が意図して止めたと分かる。
失う「ずれ」は内側の言葉なので、説明の行が要る。版が 1 つしか見えない状態がある（問題なしでは手元の版を書かない）。

B2右端の札で状態を言い、版は説明の行に、機能は「影響：〜」

得る設定の見出しの札（登録済み・まだです）と同じ形で、状態が右端で一目に分かる。
失う右端はほかの行では「設定で変える」のボタンの場所で、札とボタンが混ざる。「影響」は止めたのか壊れたのかが曖昧。

B3止めた機能を主語にし、ずれの数は畳んだ中だけ

得る利用者の問い（何が使えないか）に最初に答える。
失う止めた機能の無いずれ（記録だけのもの）が数に出ない。「使えません」は hangar の故障に読める。

B4手元と確かめた版を常に対で出し、未確認は緑の ✓ に灰色の札

得る版がいつも見えるので、報告にそのまま使える。未確認は「動いている」ことが色で分かる。
失う2 つの数を見比べさせる。未確認が問題なしとほぼ同じ見た目になり、気づきにくい。

軸 3　置き場 開き方は A4、文言は B1。薄い部分はまわりの見本

C1初回の札（空のホーム）の 6 行目だけ。spec の文面どおり

得る作る所が presentChecks の 1 か所で済む。
失う初回の札はセッションもプロジェクトも無いときだけ出る。使い始めたあと（Claude Code を上げたあと）のずれは、どこにも出ない。

C2設定の「連携」群の先頭に節を足す。初回の札の 6 行目も同じ判定で出す推す

得るいつでも見に行ける場所があり、MCP・statusline と同じ「見出し＋札」の形で並ぶ。初回の札とは判定を共有する。
失う設定を開かないと気づかない（範囲外の決めどおり、ヘッダーや知らせには出さない）。目次の点を灯すかは別に決める。

C3設定の claude の欄の下に、検証の 2 行目として添える

得るclaude のパスと版の真下にあり、版の話が 1 か所にまとまる。
失う半分の幅の欄の下なので、止めた機能や表を出す余地が無い。欄の検証（パスが使えるか）と意味が混ざる。

C4設定の頭に、確認リストを詰めた形（1 行ずつ）で置く

得るspec の「設定の確認リスト」が文字どおりでき、初回の札と同じ部品を使い回せる。
失う各節の札や欄の下の検証と、同じ判定を 2 度見せる。設定の頭が毎回 6 行ぶん下がる。

あわせて決めること

  • 未確認の版を「6 つ中 N つ」に数えるか。試作では数える（止めていないので）。ずれがあるときだけ数から外す。
  • ずれのとき、設定の目次の点と群の見出しの「直すもの」を灯すか。利用者が直せるものではないので、試作では灯さない。灯すなら「直すもの」とは別の言葉が要る。
  • 「報告用に写す」を置くか。spec には無い足し物。表を Markdown で写す。
  • 未確認の版の調子。試作は灰色の ⓘ（新しい調子 info）。いまの soft（茶の !）は「入れていない MCP・statusline」に使っているので、別にした。B4 は緑の ✓ に灰色の札。
