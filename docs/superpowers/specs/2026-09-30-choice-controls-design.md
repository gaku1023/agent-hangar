# 選ぶ部品の作り直し（設計）

## この文書の位置づけ

この文書は、2026-09-30 の brainstorming で、試作を見比べながら決めた「選ぶ部品」の作り直しをまとめたものである。
`2026-09-29-ui-refresh-design.md`（UI 刷新）の見た目の言語をそのまま使い、選択肢を出す部品だけを差し替える。
実装が入るときに、`docs/design.md` の該当する画面の記述を同じ内容へ書き換える。
試作は `docs/superpowers/specs/2026-09-29-ui-refresh/choice-controls.html` に置いた。
ブラウザで直接開けば動き、各節の灰色の地が差し替える前の姿である。
値や部品の形で迷ったら、この文書より先に試作を見る。

## 目的

hangar で選択肢を出している部品の多くは、ブラウザ標準の `select` と `input type=checkbox` のままである。
`select` を開くと macOS の素のメニューが出て、ガラスと光の見た目から浮く。
新しいセッションの model、effort、permission mode は、取りうる値が決まっているのに自由入力で、値を覚えていないと打てない。
利用者の言葉では「パッとしない」「もっと選びやすく」であり、この 2 つを直す。

成功の基準は次のとおりとする。

- 選択肢を開いても、見た目がアプリの外へ出ない（素のメニューが一度も出ない）。
- 数十件のプロジェクトから、名前かパスの一部を打って選べる。
- model、effort、permission mode を、値を覚えていなくても選べる。
- キーボードだけで、いまと同じ操作ができる。読み上げでも、いまと同じ名前で部品を見つけられる。

## 決定の要約

試作の記号で、採った案を並べる。

| 箇所 | 採った案 | 中身 |
|---|---|---|
| 新しいセッションのプロジェクト | PB | 検索できる一覧。上に「最近」、下に「すべて」 |
| プロジェクトのステータス | S1 | 色の点とひとことの意味を添えた一覧 |
| セッション一覧の絞り込み | F1 | 期間と状態は切り替えの帯、プロジェクトは PB の一覧 |
| 新しいセッションの詳細 | D1 | model はチップ、effort は強さの棒つきの帯、permission mode は意味を添えたカード |
| 設定のオン・オフ | T1 | スイッチ。2 択の select は帯にする |
| セッション画面の表示切り替え | T2 | 押すと灯るチップ。サブエージェントは帯 |
| プロジェクトに昇格 | T3 | 何が起きるかを 1 行添えたカード |
| プロジェクトの TODO | T4 | 丸い印。押すと緑に満ち、文字に線が引かれる |
| 設定の 1 時間の上限 | N1 | − と ＋ のボタン。数字は直接打てる |

進め方として、利用者は次の 3 つを決めた。

- 部品は自前で作る。見た目のない部品集（React Aria、Radix）は入れない。
- 設定のスイッチと帯は、切り替えた時点で保存する。ただし「手元の外にある要約器を許す」をオンにするときだけ、送り先を示して確かめる。
- permission mode の「確認なし」は、カードを赤で縁取り、下に 1 行の警告を出す。起動ボタンはそのまま押せる。

## 部品

共通の部品は `packages/ui/src/views/primitives/` に置く。
どの部品も制御された部品（値と変更の通知を親から受ける）として作り、自分では選んだ値を持たない。
フォームから値を読む画面のために、`name` を渡された部品は同じ名前の hidden input を描く。

### Listbox（ガラスの一覧）

閉じているときの顔と、開いたときのガラスの面からなる。
顔はボタンで、選んだ項目の点、名前、補足（パスなど）、下向きの矢印を描く。
何も選んでいないときは、置き文字（「選んでください」など）を薄く描く。

項目は次の形で渡す。

```ts
type ListboxOption = {
  value: string;
  label: string;
  sub?: string;          // 2 段目。パスは mono、説明文は地の書体
  meta?: string;         // 右端の薄い文字。「2 分前」など
  status?: ProjectStatus; // 色の点
  icon?: IconName;
  danger?: boolean;      // 名前を赤で描く
};
```

開いたときの面は、上から検索欄、行、キーの案内の 3 段に分ける。
検索欄とキーの案内は固定し、行だけをスクロールさせる。
行が少しでもスクロールしたら、検索欄の下に薄い影を出して、下をくぐっていることを示す。
検索欄とキーの案内は、項目が 8 件以上のときだけ出す。
それより少ないと、打つより目で探すほうが速いからである。

検索は、名前と補足のどちらかに、打った文字列が大文字小文字を区別せずに含まれる項目を残す。
一致した部分は薄い青で塗る。
群（「最近」「すべて」など）を渡されたときは、群の見出しを行の間に挟む。
検索で絞っている間は群を解き、一致した項目を 1 列に並べる。
一致がないときは「一致するものはありません」を出す。

面は `document.body` への portal に描き、`position: fixed` で顔の直下に置く。
下に収まらないときは顔の上に開く。
portal にするのは、一覧やカードの `overflow: hidden` で面が切られないようにするためである。
面の幅は、顔の幅と、呼び出し側が渡す最小幅の大きいほうにする。
開くときは `--dur-fast` と `--ease-out` で、薄く、わずかに縦に動き、ぼかしが晴れながら現れる。

キーボードの操作は次のとおりとする。

- 顔で ↓、Enter、Space を押すと開く。
- 開いている間は、↑ ↓ で行を移り、Home と End で端へ跳び、Enter で決める。
- Esc で閉じ、フォーカスを顔へ返す。Tab でも閉じる。
- 検索欄では、日本語の変換を確定する Enter（`ime.ts` の `isComposing`）を決定に使わない。
- 開いている間の Enter と Esc は、`stopPropagation` で親へ伝えない。起動ダイアログの Enter（起動）と Esc（閉じる）が同時に走らないようにするためである。

面の外を押すと閉じる。
行の上にポインタを載せると、その行が選ばれかけの行になる。

読み上げのために、次の役割を付ける。

- 顔：`button`。`aria-haspopup="listbox"`、`aria-expanded`、`aria-label` は呼び出し側が渡す名前。
- 検索欄があるとき：検索欄が `combobox` で、`aria-controls` が一覧を指し、`aria-activedescendant` が選ばれかけの行を指す。
- 検索欄がないとき：一覧そのものにフォーカスを移し、一覧が `aria-activedescendant` を持つ。
- 一覧：`listbox`。行：`option` と `aria-selected`。

portal の中の出来事も、React の木では呼び出し側の子として泡立つ。
カードの中に置くステータスのように、親が押されると画面を移る場所では、呼び出し側の包みで `click` と `keydown` を止める（いまの `StatusSelect` と同じ）。

### Segmented（切り替えの帯）

2 から 6 個の択一を、横に並べた帯で見せる。
選んだ項目の下に白い玉を置き、選び直すと玉が `--dur` と `--ease-out` で滑る。
項目は文字のほかに、先頭のアイコンや強さの棒（effort）を持てる。
読み上げの役割は `radiogroup` と `radio`、← → で選び直す。
大きさは 2 つ持ち、どちらも高さは 22px である。
ふつうの形は文字が 12px で、絞り込み、設定、サブエージェントに使う。
詰めた形は文字が 11.5px で左右の余白を狭め、項目が 6 個ある effort に使う。

### Switch（スイッチ）

オン・オフの設定に使う。
役割は `switch` と `aria-checked` とし、押している間は玉が少し横に伸びる。
オンのときの地は `--accent-hi` から `--accent` への縦のグラデーションにする（主ボタンと同じ）。

### Chip（チップ）

角の丸い小さな札で、2 つの使い方がある。

- 押すと灯るチップ：`aria-pressed` を持つ表示の切り替え（セッション画面の「思考」「生の記録」）。
- 択一のチップ：`radiogroup` の中の `radio`（新しいセッションの model）。

灯ったときは `--accent-soft` の地に、`--accent` の文字と縁を描く。

### OptionCard（意味を添えたカード）

アイコン、名前、1 行の説明、必要なら値そのもの（mono の小さな文字）を並べたカードである。
択一（`radio`）と複数選択（`checkbox`）のどちらにも使う。
選んだカードは白地に `--accent` の縁を描き、`danger` のカードは縁と名前を `--error` で描く。
複数選択のときは右端に四角い印を置き、選ぶと印が満ちてチェックが描かれる。

### Stepper（増減のボタン）

数の入力欄を、− と ＋ の丸いボタンで挟む。
入力欄はそのまま打てる `input` として残し、`aria-label` もいまのまま付ける。
ボタンは最小値と最大値で止まり、止まった側は押せなくなる。
範囲の外の値を打ったときの扱い（保存の前に案内を出す）は、いまの設定画面のまま変えない。

### TODO の丸い印

TODO の一覧の中だけで使うので、共通の部品にはせず `TodoList` の中に書く。
役割は `checkbox` とし、押すと `--st-done` の緑に満ち、チェックの線が描かれ、文字に線が引かれて薄くなる。
線はどれも `--dur` と `--ease-out` で動かす。

## 画面ごとの差し替え

### 新しいセッションのダイアログ

プロジェクトの欄を Listbox にする。
群は 2 つで、「最近」は最後に使った時刻（`lastActivityAt`）の新しい順に上位 5 件、「すべて」は残りを名前順に並べる。
行の補足にパス、右端に最後に使った時期（「2 分前」など）を出し、点はステータスの色にする。
アーカイブ済みとスクラッチを外すのは、いまの presenter のままである。
そのために presenter が渡す項目に、ステータスと最後に使った時刻を足す。

詳細は、いまと同じ折りたたみの中に置き、中身を D1 にする。

- model：択一のチップで「既定」「fable」「opus」「sonnet」「haiku」「ほか」。「ほか」を押すと、その場のチップが入力欄に変わり、打った名前を model にする。
- effort：切り替えの帯で「既定」「low」「medium」「high」「xhigh」「max」。既定以外は、強さを 5 段の棒で添える。
- permission mode：意味を添えたカードを 2 列に並べる。

| 値 | 名前 | 説明 |
|---|---|---|
| （空） | 既定 | Claude Code の設定に従う |
| `manual` | 都度たずねる | 編集もコマンドも確認する |
| `acceptEdits` | 編集は任せる | ファイルの編集は確認しない |
| `plan` | 計画だけ | 読むだけで何も変えない |
| `auto` | 自動 | 安全なものは自動で許す |
| `dontAsk` | たずねずに断る | 許可済みのもの以外は断る |
| `bypassPermissions` | 確認なし | すべて確認せずに実行する |

値の一覧は、`claude --help` の `--effort` と `--permission-mode` の選択肢と、`--model` の説明に挙がる別名に合わせた。
「確認なし」を選ぶと、カードを赤で縁取り、カードの下に「ファイルの削除やコマンドも、確認せずに実行します」を `--error` の色で出す。

「既定」はどれも空の値であり、いまと同じく params に含めない。
worktree と追加ディレクトリは、自由入力のまま残す。

折りたたみの見出しは、既定以外を選んだ値があれば、その値を並べて出す（例：`詳細　opus、high、自動`）。
すべて既定なら、いまの見出し（「詳細（model、effort、permission mode、worktree、追加ディレクトリ）」）のままにする。

このダイアログは、いまは入力欄をすべて非制御にして、送信のときにフォームから値を読んでいる。
プロジェクト、model、effort、permission mode の 4 つは、ダイアログの中の `useState` で持つように変える。
折りたたみの見出しに選んだ値を出すには、送信の前に値を読める必要があるからである。
名前、初期プロンプト、worktree、追加ディレクトリは、いまのまま非制御で残す。

### プロジェクトのステータス

`StatusSelect` の中身を Listbox に差し替える。
顔はいまの札（ステータスの色の地に、名前、点、矢印）のままにする。
項目は 4 つで、点、名前、ひとことの意味を持つ。

| 値 | 意味 |
|---|---|
| `active` | いま進めている |
| `paused` | いったん止めている |
| `done` | やり終えた |
| `archived` | 一覧の奥へしまう |

カードの右下に置かれることが多いので、面は下に収まらなければ上に開く（Listbox の既定の振る舞いで足りる）。

### セッション一覧の絞り込み

プロジェクトは Listbox にし、先頭に「すべてのプロジェクト」を置く。
項目が 8 件以上になるので、検索欄が出る。
顔は丸い札の形（高さ 28px）にする。

期間は切り替えの帯で「全期間」「今日」「7 日」「30 日」にする。
実行中は切り替えの帯で「すべて」「実行中」「終了」にし、帯の名前を「状態」に改める。
「実行中」という名前の帯の中に「実行中」という項目があると、読み上げで区別しにくいからである。
「実行中」の項目には、動いていることを示す緑の点を添える。

### セッション画面

「思考を表示」と「生の記録を表示」を、押すと灯るチップにする。
チップの文字は「思考」「生の記録」とし、読み上げの名前はいまのまま残す。
サブエージェントは、主線と 3 つまでなら切り替えの帯にし、それより多ければ Listbox にする。
帯の項目は、ロボットのアイコンとサブエージェントの ID である。

### 設定

チェックボックスをスイッチにし、行の右端に置く。
ターミナルアプリは、アプリのアイコンを添えた切り替えの帯にする。
要約器のモデルは Listbox にする（件数は LM Studio が返すモデルの数で決まり、8 件以上なら検索欄が出る）。
1 時間の上限は Stepper にする。

保存の扱いは次のとおりに変える。

| 項目 | 保存 |
|---|---|
| ターミナルアプリ | 切り替えた時点で `settings.update` を出す |
| LM Studio が使えないとき Claude へ切り替える | 切り替えた時点 |
| Claude Code の設定を同期する | 切り替えた時点（いまと同じ） |
| 手元の外にある要約器を許す | オフにするときは切り替えた時点。オンにするときは確かめてから |
| LM Studio の URL、モデル、1 時間の上限 | いまと同じく「要約器の設定を保存」 |
| パスの欄（tmux、code、claude、Node） | いまと同じく各節の保存ボタン |

ターミナルアプリが保存ボタンの対象から外れるので、「ツールの設定を保存」はパスの 3 つだけを見る。
同じく「要約器の設定を保存」は、URL、モデル、上限の 3 つだけを見る。

「手元の外にある要約器を許す」をオンにしようとすると、スイッチはまだオンにせず、その下に確かめの帯を出す。
帯には「会話の本文（利用者の発言とアシスタントの応答）が <保存済みの URL> へ送られます」と、「許す」「やめる」の 2 つのボタンを置く。
「許す」で `settings.update` を出し、「やめる」で帯を閉じる。
宛先に保存済みの URL を出すのは、送られる先が保存済みの URL だからである（URL の欄を書き換えただけでは宛先は変わらない）。
いまスイッチの下に出している警告の文は、オンの間だけ出す扱いをそのまま残す。

### プロジェクトに昇格

「git init する」と「ファイルを移動する」を、複数選択の OptionCard にする。
説明は、それぞれ「空のリポジトリを作ってから移します」「スクラッチのファイルをワークスペースへ移します」とする。
実行中のセッションがあるときにファイルの移動を選べないのは、いまのまま（カードを押せなくする）である。

### プロジェクトの TODO

済みの印を、丸い印にする。
読み上げの名前（「<文言>（<n> 件目）」）は、いまのまま残す。

## 見た目の決まりとの関係

浮くガラスは、`glass.test.ts` が決まった部品にだけ許している。
Listbox の面は浮く部品なので、その一覧に面の選択子（`.listbox-pop`）を足す。
ぼかしの値は、⌘K と同じ `--glass-blur-strong` を使い、`-webkit-` を併記する。

動きの長さは、どれも `--dur-fast`、`--dur`、`--dur-exit` を通して書く（`motion.test.ts` が見張る）。
reduced motion では、トークンが 0 になることで、玉の滑りも印の描画も止まる。

## 試験

部品ごとに試験を書く。
見るのは、読み上げの役割と名前、キーボードの操作、変換中の Enter、そして値の変更が親へ届くことである。

- Listbox：開く、閉じる、↑ ↓ と Enter で選ぶ、Esc で顔へフォーカスが戻る、検索で絞れる、一致がないときの文、8 件未満では検索欄が出ない、群の見出し、開いている間の Enter と Esc が親へ伝わらない、変換中の Enter で決まらない、`name` を渡すと hidden input に値が入る。
- Segmented：`radio` の数と `aria-checked`、押すと値が届く、← → で選び直す。
- Switch：`switch` と `aria-checked`、押すと反転した値が届く。
- Chip：`aria-pressed` の反転と、択一のときの `radio`。
- OptionCard：択一と複数選択の役割、`danger` の見た目の印（`data-danger`）、押せないときに値が届かない。
- Stepper：± で 1 ずつ動く、最小値と最大値で止まる、打った値が届く。

画面の試験のうち、`select` と `checkbox` を前提にしているものは、新しい役割で引き直す。
たとえばいまは `fireEvent.change` で `select` の値を変えている試験（新しいセッションのプロジェクト、セッション一覧の絞り込み、ステータス、サブエージェント、設定のターミナルアプリと要約器のモデル）は、顔を押して行を選ぶ操作に書き換える。
設定の試験には、スイッチを切り替えた時点で `settings.update` が 1 つの項目だけで出ること、外部の要約器をオンにするときは確かめの帯を経ることを足す。
新しいセッションの試験には、既定のままなら model、effort、permission mode が params に入らないこと、「ほか」で打った model が入ること、「確認なし」で警告が出ることを足す。

## 範囲の外

- 検索のあいまい一致（打ち間違いを許す一致）は入れない。部分一致で足りるかは、使ってから決める。
- コマンドパレット（⌘K）とプロジェクトの場所を確かめるダイアログの候補一覧は、すでに自前の部品なので触らない。
- 自由入力の欄（パス、URL、名前、メモ）の見た目は変えない。
