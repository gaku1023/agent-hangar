# agent-hangar

Claude Code のセッションをプロジェクト単位で束ね、起動、観察、検索、記録を一箇所で行う個人用のローカルアプリです。
設計は `docs/design.md`、実装計画は `docs/plans/` にあります。
手引きは日本語です。
画面は英語にも切り替わります（設定の「一般」の最初の行で選びます）。

## できること

macOS の `.app` か Windows のインストーラを入れると、サーバの起動をアプリに任せて使えます（入れ方は「[入れる（macOS）](#入れるmacos)」と「[入れる（Windows）](#入れるwindows)」にあります）。
使えるものは、tmux でのセッション起動、ブラウザに埋め込んだターミナル、セッション内のシェルタブ、MCP、外部アプリとの連携、使用量、アーティファクト、TODO とメモ、スクラッチと昇格、タブの分割、事後要約、コマンドパレットです。
自分の Cloudflare アカウントに Worker と D1 と R2 を置き、自分の端末の間でセッションのメタデータと本文と Claude Code の設定を同期するクラウド同期もあります。
これは上級者向けのベータです（始め方と、何を平文で置くかは「[クラウド同期](#クラウド同期上級者向けのベータ)」の節にあります）。
実行中のセッションを他端末から奪う「引き継ぎ」は作りません。

確かめた Claude Code の版は `2.1.300` です（見本は `packages/server/test/fixtures/claude/` にあります）。
より新しい版でも動かしますが、hangar が知らない形式に出会うと、`~/.agent-hangar/compat.json` に記録し、設定の「連携」の節と、初回の確認リストで知らせます。

## 入れる（macOS）

対象は macOS 13 以降の Apple silicon と、Windows 11（x64）です。
配布物は GitHub Releases に置いています（最初の版は `v0.1.0` で、macOS だけでした。Windows のインストーラは `v0.2.0-rc.1` から添えています）。
v0.1.0 から入れ替える人は、先に「[v0.1.0 からの移行](#v010-からの移行)」を読んでください。
ふだんは Latest の印の付いた版を使ってください。
Pre-release の印の付いた版（`v0.2.0-rc.1` など）は試しの版で、確かめが済むまでの間だけ置きます。
試しの版を入れると、自動更新は次の試しの版と、その後の正式な版を知らせます（手順は [docs/release.md](docs/release.md)）。

この節の残りは macOS の手順です。
Windows では「[入れる（Windows）](#入れるwindows)」の節へ進んでください。

macOS の配布物は dmg が主で、zip は予備です。
Apple の Developer ID では署名せず、公証もしません。
代わりに自作の証明書で署名します（仕組みは [docs/signing.md](docs/signing.md) にあります）。
自作の証明書は macOS に信頼されていないので、初めて開くときに「"Hangar" は開いていません」という警告が出ます。
その越え方は、手順の 3 段目に書きました。

### 前提

Hangar を動かすには、次の 3 つが先に要ります。

- Node 22.14 以上。
  Hangar のデータベースと端末の部品は Node-API 10 を使うため、それを持つ版が要ります（23 の系列では 23.6 以上）。
  Node 24 など新しい版でも動きます。
  アプリは Node を同梱していません。
- tmux。セッションは tmux の中で起こします。
- `claude`（Claude Code 本体）。セッションを起こすのは Claude Code です。

Homebrew なら、Node と tmux はまとめて入ります。

```sh
brew install node tmux
```

これだけで足ります。
アプリと `hangar` コマンドは PATH を見ずに、決まった場所から Node を探し、Node-API 10 以上で同じアーキテクチャのものを使います。

すでに 22.14 より古い Node を使っていて、それを置き換えたくないときは、`brew install node@22` で入れます。
`node@22` は既定の `node` を置き換えません。
探す場所には Homebrew の `node@` の入れ先（`/opt/homebrew/opt/node@22`）が入っているので、`brew link` は要りません。

nvm、fnm、Volta、mise、asdf、nodenv で入れた Node も、そのまま見つけます。
探す順は、Settings で指定したパス、`/opt/homebrew/bin/node`、`/usr/local/bin/node`、Homebrew の `node@` の入れ先、nvm、fnm、Volta、mise、asdf、nodenv（それぞれ新しい版から）です。

これら以外の場所に入れたときは、Settings 画面の「Node のパス」か `~/.agent-hangar/settings.json` の `nodePath` に、その `node` の実行ファイルのフルパスを指定します。
読み込み画面が合う Node を見つけられないと告げたときは、その画面の「node を選ぶ…」で選んでも指定できます。
`node` のような名前だけや相対のパス、`~` で始まるパスは使えません（`~` は展開しないので、`/Users/名前/...` のように書きます）。
Settings 画面と「node を選ぶ…」は、保存する前にその Node が Node-API 10 以上で同じアーキテクチャかを確かめ、合わなければ理由を出して保存しません。
`hangar` コマンドは、環境変数 `HANGAR_NODE` に `node` のフルパスを入れておけば、それを先に使います。
アプリは `HANGAR_NODE` を見ません。Finder から開いたアプリには端末の環境変数が届かないので、アプリに指すときは `nodePath` を使います。
`/opt/homebrew/bin/node` へリンクして見つけさせる手もあります（`brew link --overwrite --force node@22`。別の `node` を入れていれば置き換わります）。

Homebrew の版によっては `node@22` が keg-only（Homebrew が既定の場所へリンクしない入れ方）になり、端末で `node` が見つかりません。
そのときは PATH に通します（zsh の例です）。
アプリの探索には関わりません。

```sh
echo 'export PATH="/opt/homebrew/opt/node@22/bin:$PATH"' >> ~/.zshrc
```

`claude` の入れ方は Claude Code の案内に従ってください。
どれが入っているかは、手順の 4 段目の `hangar setup` が報告します。

次の 2 つは無くても動きます。

- git。一覧と (i) のブランチと未コミットの件数、変更したファイルの差分に使います。macOS はコマンドライン・デベロッパツール（`xcode-select --install`）、Windows は Git for Windows（`winget install --id Git.Git -e`）で入ります。
- エディタ。「<名前> で開く」で使います。VS Code、Cursor、Windsurf、Zed、IntelliJ IDEA、WebStorm を自動で見つけ、Settings の「一般」の「エディタ」で選べます。ほかのエディタは「任意のコマンド」に `subl {path}:{line}` のように書きます。

どちらも、ホームの「セットアップの確認」に任意の行として出ます。

### 手順

1. Releases から `Hangar-vX.Y.Z-macos-arm64.dmg` を落とします。
   checksum を確かめるには、同じ場所の `.sha256` も落として `shasum -a 256 -c Hangar-vX.Y.Z-macos-arm64.dmg.sha256` を実行します。

2. dmg を開き、中の `Hangar.app` を隣の `Applications` へドラッグします。
   入れ終わったら、Finder のサイドバーで dmg を取り出してかまいません。

   dmg の中の `Hangar.app` を、そのままダブルクリックして使わないでください。
   読み取り専用の場所から開くと、macOS が `.app` を別の読み取り専用の場所へ写して起動することがあります（App Translocation）。
   写しの中ではアプリが自分の同梱物の検疫属性を外せないので、同梱サーバを起こせません。
   アプリは自分が写しの中にいると気付くと `/Applications` へ移すよう案内しますが、その前に macOS の警告が出ることがあります。

3. `/Applications/Hangar.app` を初めて開きます。

   初めて開くと、次の警告が出ます。

   > "Hangar" は開いていません
   > Apple は、"Hangar" に Mac に損害を与えたり、プライバシーを侵害する可能性のあるマルウェアが含まれていないことを検証できませんでした。

   ボタンは「ゴミ箱に入れる」と「完了」だけです。
   Hangar に問題が見つかったという意味ではなく、Apple の公証を受けていないアプリに出る警告です。
   次の順で開きます。

   1. 「完了」を押して、警告を閉じます（「ゴミ箱に入れる」は押しません）。
   2. システム設定を開き、「プライバシーとセキュリティ」を選びます。
   3. 画面を下へ送り、「セキュリティ」の欄（見出しが「アプリケーションの実行許可」と出る版もあります）にある、「…"Hangar"がブロックされました。」という行を探して、右の「このまま開く」を押します。
      行の文言は macOS の版によって違うので、「Hangar」と「ブロック」の語を手がかりに探してください。
   4. 「Mac に損害を与えたり、プライバシーを侵害する可能性のあるアプリを開こうとしています」と出て、「プライバシーとセキュリティで続けるには、管理者の名前とパスワードを入力してください。」と求められます。管理者のパスワードを入れると、Hangar が開きます。

   この行は、警告を一度出した後にだけ現れます。
   警告を出す前に、システム設定を開いても見つかりません。

   Finder での右クリックの「開く」は、実機で試した版の macOS では効きませんでした（同じ警告の画面になり、開く道は出ませんでした）。
   そのため、主の手順には入れていません。
   macOS の版によっては効くことがあります。

   上の手順でも開けないときの最後の手段として、端末から検疫属性を外す道もあります。

   ```sh
   xattr -rd com.apple.quarantine /Applications/Hangar.app
   ```

   開いたアプリは、同梱サーバを子プロセスとして起こす前に、同梱物の検疫属性を自分で外します。
   この処理は Node を探すより前に走るので、前提の Node がまだでも効きます。
   ただし 4177 で既に動いているサーバを見つけた回は、サーバを起こさないのでこの処理も走りません。
   どちらにしても、これが効くのは `/Applications` へ移した後だけです。

   合う Node（22.14 以上）がまだ無ければ、読み込み画面がそう告げます。
   その場合は「[前提](#前提)」の手順で入れてから開き直すか、画面の「node を選ぶ…」で入れた Node を選んでください。

4. `hangar` コマンドを使えるようにして、初期設定を走らせます。

   ```sh
   sudo mkdir -p /usr/local/bin
   sudo ln -sf /Applications/Hangar.app/Contents/Resources/server/bin/hangar /usr/local/bin/hangar
   hangar setup
   ```

   まっさらな Mac（特に Apple silicon）には `/usr/local/bin` がまだありません。
   1 行目の `mkdir -p` はそのためで、すでにあれば何も起こりません。
   これを省くと、`ln` が「No such file or directory」で止まります。
   `/usr/local/bin` は macOS の初めからの `PATH` に入っているので、作れば `hangar` はそのまま呼べます。
   `sudo` を使いたくないときは、Homebrew の `/opt/homebrew/bin` に同じリンクを張っても構いません（そこが `PATH` にあることが前提です）。

   `bin/hangar` はリンク越しに呼ばれても自分の実体を辿るので、同梱物と Node を見失いません。
   `hangar setup` は `~/.agent-hangar` を用意し、tmux と claude と git の有無を報告します。

5. `Hangar.app` を開きます。

   同じ画面はブラウザからも使えますが、入口は鍵付きの URL だけです。
   `hangar url` を実行し、印字された `http://127.0.0.1:4177/?t=<トークン>` を開いてください。
   鍵の無い `http://127.0.0.1:4177/` は 401 になり、`hangar url` を案内する画面を返します。
   `/usr/local/bin/hangar` のリンク越しに `hangar url` を叩いても、正しい鍵付きの URL が出ます。
   4177 は同じ機械で動くどのプログラムからも叩けるので、鍵が無ければセッションの本文を誰からでも読み出されてしまうためです。
   開いた後の鍵の扱いは「[画面を開く](#画面を開く)」に書いてあります。

   `open hangar://session/<id>` のようなリンクでアプリの画面を直接開けます。
   受け付ける形は `hangar://session/<id>`、`hangar://project/<id>`、`hangar://search?q=<検索語>` の三つです。

起動の記録は `~/.agent-hangar/desktop.log` に残ります。
うまく起動しないときは、「[困ったとき](#困ったとき)」を見てください。

`.app` の版はタグと同じで、設定の更新の節に出ます。
同梱のサーバも同じ版を名乗ります（サーバの版は `/health` が返します）。

### v0.1.0 からの移行

v0.1.0 には自動更新が無いので、v0.1.0 のアプリは新しい版を知らせません。
v0.2.0 以降の dmg を、上の手順の 1 から 3 のとおり手で入れ直してください。
Hangar が動いていたら、先に終了してから `/Applications` の `Hangar.app` を置き換えます。
`~/.agent-hangar` の中身（設定、索引、メモ、クラウド同期の設定）は、そのまま引き継がれます。
データベースの版が上がるときは、上げる前の控えを同じ置き場に取ります。

署名が変わるので、入れ直しの初回だけ、次の 2 つが起きます。
v0.1.0 は署名なしの build で、v0.2.0 からは自作の証明書で署名します。
macOS は署名の違うアプリを別のアプリとして扱います。

- 手順の 3 段目の初回の警告がもう一度出ます。同じ手順で越えます。
- ローカルネットワークや、ファイルとフォルダなどの許可を、一度だけ取り直します。
  アプリが尋ねてくるので、許可してください。

v0.2.0 からは、更新でも同じ証明書で署名します。
更新のたびに警告や許可が出直すことはありません。
v0.2.0 の入れ直しのあとは、設定の更新の節が新しい版を知らせるので、手で入れ直す必要はありません。

### zip から入れる（予備）

dmg を使えないときは、同じ場所の `Hangar-vX.Y.Z-macos-arm64.zip` を使います。
checksum は `shasum -a 256 -c Hangar-vX.Y.Z-macos-arm64.zip.sha256` で確かめます。
Finder でダブルクリックして展開し、展開した `Hangar.app` を `/Applications` へ移してから、上の手順の 3 段目から続けます。

展開の仕方で、検疫属性が `.app` に伝わるかどうかが変わります。
Finder でダブルクリックして展開すると伝わり、端末から `unzip` や `tar` で展開すると伝わりません。
伝わらなかった場合は、手順の 3 段目の警告が出ないまま開けるはずです。
展開した場所でダブルクリックせず、先に `/Applications` へ移してください（理由は手順の 2 段目と同じです）。

## 入れる（Windows）

対象は Windows 11（x64）だけです。
タグを打つと、macOS の dmg や zip と同じ Release に Windows のインストーラも添えます。
インストーラを使わずに、ソースから動かして使うこともできます（手順は [docs/development.md](docs/development.md) にあります）。

### Windows の前提

Hangar を動かすには、次の 3 つが先に要ります。

- Node 22.14 以上。
  Hangar のデータベースと端末の部品は Node-API 10 を使うため、それを持つ版が要ります。
  Node 24 など新しい版でも動きます。
  アプリは Node を同梱していません。
  Node がまだ無ければ、PowerShell で `winget install -e --id OpenJS.NodeJS.LTS` を打つのがいちばん手早い入れ方です（公式のインストーラが入ります）。
  すでに 22.14 より古い Node を使っていて、それを置き換えたくないときは、winget は使いません（公式のインストーラは `C:\Program Files\nodejs` の Node を置き換えます）。
  代わりに nodejs.org から Node 22 の Windows 用 zip を取り、別のフォルダ（例 `%LOCALAPPDATA%\Programs\node22`）に展開して、読み込み画面の「node.exe を選ぶ…」か Settings 画面の「Node のパス」でその `node.exe` を指します。
  nvm-windows の `nvm install 22` で入れた版も、fnm、Volta、scoop で入れた Node も見つけます。
- psmux。セッションは tmux の代わりに psmux の中で起こします。入れ方は下の「[psmux を入れる](#psmux-を入れる)」にあります。
- `claude`（Claude Code 本体）。入れ方は Claude Code の案内に従ってください。

git とエディタは、macOS と同じく無くても動きます（使いみちは、macOS の「[前提](#前提)」の節にあります）。
git は Git for Windows（`winget install --id Git.Git -e`）で入ります。

winget で入れたものは、入れたあとに新しく開いた PowerShell から PATH に載ります。

### Node の探し方

Node は同梱していないので、Node-API が同梱の `manifest.json` の `nodeApi`（10）以上で、アーキテクチャが同じ Node を探します。
アプリは、`~\.agent-hangar\settings.json` の `nodePath`、公式のインストーラの入れ先、nvm-windows、fnm、Volta、scoop、PATH にあるすべての `node.exe` の順に探します。
`hangar` コマンドは、その前に環境変数 `HANGAR_NODE` を見ます（アプリは `HANGAR_NODE` を見ません）。
`nodePath` と `HANGAR_NODE` は `node.exe` のフルパスで指します。
fnm などが古い版を PATH の先頭に置いていても、PATH の後ろや版の管理ツールの置き場に合う Node があればそれを使います。
見つからないときは、調べた場所と、それぞれが合わなかった理由を順に出します。

### インストーラで入れる

1. 「[Windows の前提](#windows-の前提)」の 3 つを入れます。
2. Releases から `Hangar-vX.Y.Z-windows-x64-setup.exe` を落とします。
   checksum を確かめるには、同じ場所の `.sha256` も落とし、PowerShell の `Get-FileHash Hangar-vX.Y.Z-windows-x64-setup.exe` が出す値と比べます（大文字と小文字の違いは無視します）。
3. インストーラを開きます。
   署名していないので、SmartScreen が「Windows によって PC が保護されました」と出します。
   そのときは「詳細情報」を押して「実行」を選びます。
   管理者権限は要らず、`%LOCALAPPDATA%\Hangar` に入ります。
4. スタートメニューの Hangar から開きます。
   合う Node が見つからないときは、起動の画面がそう告げます。入れてから「もう一度試す」を押すか、「node.exe を選ぶ…」で入れた Node を選んでください。
   psmux や `claude` が欠けているときは、ホームの「セットアップの確認」に出ます。入れたあとに「再確認」を押すと、開き直さずに見つけます。

インストーラは同梱の `hangar` コマンドの置き場を利用者の PATH に足すので、入れたあとに新しく開いたターミナルで `hangar url` のように打てます。

入れたあとは、新しい版が出ると設定の更新の節と札が知らせます。
「ダウンロードしてインストール」のあと「再起動して更新」を押すと入れ替わります。
動いているセッションは止まらず、開き直したアプリからつなぎ直せます。

### psmux を入れる

hangar は tmux の代わりに [psmux](https://github.com/psmux/psmux) を使います。
先に入れておく必要があります。

```powershell
winget install -e --id marlocarlo.psmux
```

入れたら、新しい PowerShell を開き直して確かめます（winget が張るリンクは、開き直した端末から PATH に載ります）。

```powershell
psmux -V
```

`psmux`、`pmux`、`tmux` の 3 つの名前で入ります。hangar は `psmux` を先に探します。
hangar のセッションは psmux の専用の名前空間で動くので、`psmux -L hangar ls` で見えます。

psmux は 3.4.0 以上を使ってください。
3.4.0 より前（3.3.5〜3.3.8）は、Claude Code が動いているペインでホイールを回すと、`↑` キーに変えてアプリへ送ります（[psmux#548](https://github.com/psmux/psmux/issues/548)）。
端末を上へスクロールできず、Claude Code のプロンプトの履歴が呼ばれます。
古い版のときは、ホームの「セットアップの確認」、設定のツールの節、`hangar setup` の出力が知らせます。

#### psmux を上げる

psmux が 1 つでも動いていると、winget は `psmux.exe` を置き換えられずに失敗します（`remove: Access is denied`、0x8a150003）。
失敗すると、別名の `pmux.exe` だけが消えた状態で止まります。
そのため、先に psmux を止めてから上げます。

1. hangar のセッションを全部閉じます。psmux を止めると、その中で動いているセッションは全部止まります（hangar を再起動しても psmux の中のセッションは止まらないので、ここで止まります）。
2. hangar の端末ではなく、外の PowerShell で次の 1 行を打ちます。hangar のセッションを開き直すと psmux がまた起動するので、止めることと上げることを続けて打ちます。

   ```powershell
   Get-Process psmux -ErrorAction SilentlyContinue | Stop-Process -Force; winget upgrade marlocarlo.psmux; tmux -V
   ```

3. 最後に `tmux 3.4.0` 以上が出れば上がっています。hangar の設定のツールの節で「再確認」を押すと、知らせが消えます。

winget の id は `marlocarlo.psmux` です。
リポジトリは `psmux/psmux` に移りましたが、winget の id は移っていません（2026-10-10 に winget-pkgs の `manifests/m/marlocarlo/psmux` で 3.3.8 を確かめました。`psmux/psmux` という id はありません）。
手元で確かめるときは `winget search psmux` を使います。
id が変わっていたら、そこに出る id を `winget install -e --id <id>` に渡してください。
winget を使えない PC では、[リリースのページ](https://github.com/psmux/psmux/releases)の `psmux-v<版>-windows-x64.zip` を展開し、中の `psmux.exe` の置き場所を PATH に加えます。

### Windows の制限

Windows では、ターミナルで打った `claude` を hangar に載せる包み（macOS の `hangar shell install`）を作りません。
セッションは Hangar の画面から始めます。
通知（WinRT のトースト）、外のターミナルへの受け渡し（Windows Terminal）、`hangar open`（鍵付きの URL を既定のブラウザで開きます。鍵は端末には出しません）は Windows でも使えます。
statusline への追記は Windows の実機で確かめていないので、使えるものとして書きません。

## 初日にすること

アプリを入れたら、次の順で進めます。

1. Hangar を開きます。
   ホームの「セットアップの確認」に、tmux（Windows は psmux）、`claude`、git、エディタの有無が出ます。
   足りないものを入れたら、「再確認」を押すと、開き直さずに見つけます。
2. Claude Code から hangar のツールを使えるようにします。
   設定の「連携」の節の「登録…」を押します（ホームの確認の行にも同じボタンが出ます）。
   ターミナルでは `hangar mcp install` です。
   書く前に差分を見せ、バックアップを取ります（「[アプリのボタンで書くとき](#アプリのボタンで書くとき)」）。
3. 使用量のゲージを出したいときは、同じ「連携」の節で、ステータスラインを登録します（`hangar statusline install`）。
4. ターミナルで打った `claude` も hangar の画面に載せたいときは、同じ「連携」の節でシェル連携を入れます（macOS だけ。`hangar shell install`）。
5. セッションを始めます。
   ⌘N で新規セッションのダイアログが開きます。
   プロジェクトの代わりに「スクラッチ」を選ぶか、⌘⇧N で、すぐに始められます。
6. 後から要約を作るときは、設定の「要約エンジン」で Claude か OpenAI 互換の URL を選んでください（既定は使わない。「[会話の要約](#会話の要約)」）。
7. 仕上げに、設定の「連携」の最後の札「Claude Code に環境を見てもらう」の一言をコピーして Claude Code に貼ると、環境を読むだけで診断し、会話のフォルダの登録や連携を提案します（書き換えは承諾してから）。

クラウド同期は、上級者向けのベータです。
使わなくても、ほかの機能は動きます（「[クラウド同期](#クラウド同期上級者向けのベータ)」）。

## 使い方

配布版の `hangar` コマンドの形で書きます（macOS は「[手順](#手順)」の 4 段目で入れます。Windows はインストーラが PATH に足します）。
Windows の `hangar` は、PowerShell と cmd のほか、Git Bash（Claude Code の `!` もこれを使います）でも同じ名前で打てます。
アプリを使うだけなら、ほとんどの操作は画面のボタンで足ります。

### 画面を開く

`hangar start` は、起動のたびに次のような鍵付きの URL を印字し、既定のブラウザで開きます。

```
この URL から開いてください: http://127.0.0.1:4177/?t=<トークン>
```

開いた時点で鍵はクッキーに変わり、アドレス欄からは消えます。
以後はブックマークから `http://127.0.0.1:4177/` を鍵無しで開けます。
自分で開きたいときは `--no-open` を渡してください。
`hangar open` も同じ鍵付きの URL を印字してから開きます。
ただし開く前にサーバの生死を確かめ、動いていなければ開かずに起動を促します。
鍵付きの URL を出すだけでよいときは `hangar url` を使ってください。

```sh
hangar url     # 鍵付きの URL を印字する（ブラウザは開かない）
```

起動の後に鍵付きの URL を見直す道はこのコマンドだけです。
別のブラウザで開きたいときや、`open` の効かない環境で貼りたいときにも使えます。
サーバが止まっていても印字します。

鍵の無い `http://127.0.0.1:4177/` は 401 になり、トークンを配りません。
`curl` 1 本で誰でもトークンを取れてしまうのを防ぐためです。
401 の画面にも `hangar url` を案内します。
ブラウザでクッキーを消したときは、`hangar open` でもう一度開き直してください。

### Claude Code から使えるようにする

Claude Code から hangar のツールを使うには、一度だけ登録します。
デスクトップアプリでは、設定の「連携」の節の「登録…」を押します（次の「[アプリのボタンで書くとき](#アプリのボタンで書くとき)」）。
ターミナルでは次を実行します。

```sh
hangar mcp install     # user スコープに hangar を登録する
hangar mcp uninstall   # 取り消す
```

登録は hangar が `~/.claude.json` の `mcpServers.hangar` を直接書きます。
`claude mcp add` に任せないのは、`--header` の値がコマンドの引数に載り、トークンが `ps` で同じ機械の誰からでも読めてしまうためです。
ほかの項目とほかの MCP サーバには触れません。
取り消しも hangar が同じやり方で書きます（`claude mcp remove` には任せません）。
どちらも、書く前に `~/.agent-hangar/backups/` へ `~/.claude.json` のバックアップを取ります。

### アプリのボタンで書くとき

デスクトップアプリでは、MCP サーバーの登録、ステータスライン、シェル連携を、設定の「連携」の節のボタンで行えます（ホームの始める前の確認の行にも、同じボタンが出ます）。
ボタンを押すと、アプリが「書き込みの確認」の窓を開き、書く先のファイル、新規か変更か削除か、差分、同じことをするコマンドを見せます。
「書き込み」を押したときだけ書き、書く前にバックアップを取ります。
見せた後に別のプログラムがそのファイルを変えていたら、何も書かずに止まります。「再読み込み」で見直してください。
他の PC から届いた Claude Code の設定の適用と、バックアップに戻す操作も、同じ窓で確認します。
ブラウザで開いた画面からは書きません。ボタンの代わりに、ターミナルで打つコマンドを出します。

```sh
hangar mcp install --dry-run   # 書かずに、書く先と差分だけを見る（shell、statusline も同じ）
```

### セッションを始める、続ける

新規セッションのダイアログでプロジェクトの代わりに「スクラッチ」を選ぶと（⌘⇧N なら最初から選ばれています）、`~/.agent-hangar/scratch/` の下に日時のディレクトリを作って始めます。
スクラッチのセッションは、後から「プロジェクトに昇格」でワークスペースの下に移せます。
セッション画面では ⌘\ で 2 つのタブを横に並べられます。

セッションのトランスクリプトは最新の側から開き、「古い行を読み込む」で過去へ遡ります。
実行中のセッションで追うのをやめている間に届いた分は「新着 N 件」の帯で知らせます。
N は実際に追記された行の数で、遡って読み込んだ古い行は数えません。

PC を再起動したり tmux が止まったりして Claude が途中で終わったセッションは、ホームの帯の「前回実行中」に並びます。
止まる前に作業中だったものから順に並び、「すべて再開」で同時に 2 本ずつ再開します（画面は移りません）。
1 本ずつの「再開」と、再開しない（×）も選べます。Paused、Done、Archived を付けたセッションは並びません。
再開は会話を開き直すだけで、途中だった作業は自動では続けません。続きは自分で指示してください。

### 止まっている理由

Claude がツールの許可を求めて止まると、サイドバーと一覧の点が赤い盾に替わり、ホームの要対応に道具と命令が出ます（「許可待ち」）。
道具と命令は、hangar から起動したセッションにだけ届きます。外部ターミナルのセッションでは「内容はターミナルに出ています」と出ます。
使用制限に当たったセッションは、青みの灰の砂時計とリセットの時刻で出ます（「使用制限」）。実行中に数え、ヘッダーの「停止 N」から一覧を開けます。
Claude Code が自動で続きを始めないままリセットから 90 秒を過ぎたものは、「リセット済み」として要対応に上がります。
区切り（Paused、Done）を付けていても、使用制限でリセットを待っている間は自動の停止で止めません。止めると自動の続きの予約ごと消えるためです。
デスクトップ通知は窓が背面にあるときに出ます。許可待ちはすぐ、使用制限は当たったときにアカウントごとに 1 通です。
通知のきっかけはサーバが決めるので、窓が別のアプリの裏にあって画面が止まっていても届きます。
一覧の欄では `is:permission`（許可待ち）と `is:limited`（使用制限とリセット済み）で絞れます。

### 2 本のセッションの重なり

2 本のセッションが同じファイルを交互に編集しているときは、ホームの実行中の行、セッション画面の現在の札、サイドバーの行に琥珀の印が出ます。
止めはせず、通知も出しません。印を押すと、相手とファイルの一覧と、worktree で新しいセッションを始めるボタンが開きます。
Edit と Write の呼び出しから見ているので、Bash で書き換えた分は拾えません。

### 使用量のゲージ

```sh
hangar statusline install     # statusline スクリプトに追記して、使用量ゲージを動かす
hangar statusline uninstall   # 追記した行を消す（バックアップを取ります）
```

追記先は `~/.claude/settings.json` の `statusLine.command` が指すスクリプトです。
承諾（`y` の入力、または `--yes`）を求め、追記の前に同じディレクトリにバックアップを取ります。
statusline を設定していない場合は追記せず、貼り付ける内容と手順を印字します。
サーバを 4177 以外で動かしているときは `--port <番号>` を渡します。
Windows でスクリプトが PowerShell（`.ps1`）のときは、同じことをする PowerShell の行を入れます。
スクリプトが `param` の塊で始まるときと、`$input` で標準入力を読むときは、自動では入れずに理由を出します。

ヘッダーに 5 時間と 7 日の使用率のゲージが出ます。
値は Claude Code が statusline に渡す JSON が唯一の供給源なので、Claude が動いている間だけ新しくなります。
スニペットはトークンをコマンドの引数に載せません。
`~/.agent-hangar/statusline-header`（権限 0600）に置いた `Authorization: Bearer <トークン>` の 1 行を、`curl -H @<ファイル>` で読みます。
curl 7.55 以降が要ります。
このファイルはサーバの起動のたびに用意するので、`~/.agent-hangar` ごと消しても次の起動で戻ります。
ファイルが読めないときスニペットは何も送らず、statusline の表示だけをそのまま通します。
古い形のスニペットが入っているときは、`statusline install` が承諾を求めたうえで差し替えます。

Settings の使用量の表は、日別とプロジェクト別で同じ期間を見るので、トークン数の合計は一致します。
推定コストだけは、そのセッションの走り全体の累計です。
供給源が statusline の渡す累計の値で、日ごとの内訳を持たないためです。

### 会話の要約

終わった会話の要約を後から作るかどうかは、Settings の「要約エンジン」で 1 つ選びます。
既定は「使わない」です。
会話の中で Claude が書く要約（`set_session_summary`）は、どれを選んでも出ます。

- 使わない：後から要約を作りません。
- Claude：`claude -p` で作ります。あなたの Claude の使用枠を使います。モデルは設定で選べ（既定は haiku）、1 時間あたりの件数（既定 20）と週の使用率 80% で止めます。走らせるのは、その会話のアカウントです。
- OpenAI 互換の URL：LM Studio、Ollama、vLLM などに投げます。API キーが要るサーバでは、キーを設定に入れます（`~/.agent-hangar/settings.json` に権限 0600 で置き、画面には出しません）。補助のスイッチ「接続できないときは Claude を使う」を入れると、繋がらないときだけ Claude に切り替えます（既定は切）。

OpenAI 互換の宛先には会話の本文が送られるので、宛先は既定で手元（`127.0.0.1`、`localhost`、`::1`）だけです。
手元の外にある要約器を使うときは、Settings の「外部の要約エンジンを許可」を入れてください。
入れている間は、会話の本文がその宛先へ送られることを画面に出します。

### 複数のアカウント

Claude Code のアカウントを複数持っているときは、Settings の「連携」にある「アカウント」で足せます。
「アカウントを足す…」を押すと、名前と場所を決めるダイアログが開きます。
場所は、名前を打つと `~/.claude-<名前>` で埋まります（名前が英数字でなければ `~/.claude-2` からの連番）。
打ち直すか、アプリでは「選ぶ…」で既にあるフォルダを選べます。
ダイアログには、`~/.claude` と共有するもの（設定と指示、スキル、メモリ、会話の履歴）と、分けるもの（ログイン、組織から配られる設定、キャッシュ）が出ます。
選んだ場所に同じ名前の実ファイルがあるときは、上書きせずに残し、ダイアログでその名前を知らせます。
「登録してログイン」を押すと、ブラウザが開くので、足したいアカウントで承認してください。終わると、読んだメールアドレスが行に出ます。
ヘッダーの名前を押すと、アカウントの一覧が開き、選んで切り替えられます。ホームや一覧では「いまのアカウント」（新しいセッションの既定）が変わり、セッション画面では確認のうえ、そのセッションを選んだアカウントで再開し直します。
新規セッションのダイアログには、アカウントを選ぶ段が出ます。選んだセッションだけ別のアカウントで始まり、いまのアカウントは変わりません。
アカウントが 1 つだけのときは、これらの表示は出ません。上限に当たっても自動では切り替わりません。切り替えるのは自分の手です。
一覧から外したアカウントの場所は消えないので、同じ場所を登録し直せば戻ります。

### TODO とメモ

プロジェクト詳細の右レールで TODO と Markdown のメモを書けます。
メモは `~/.agent-hangar/projects/<projectId>/memo.md` にも書き出すので、エディタから直接編集できます。
ファイルの方が新しければファイルの内容を採ります。
DB の内容で上書きするときは、消える本文を同じディレクトリに `memo.md.bak-<日時>` として残します。
同じレールに、セッションが claude.ai に公開したアーティファクトのカードが並びます。

### エディタと git

「<名前> で開く」のボタンは、Settings の「一般」の「エディタ」で選んだエディタで開きます。
候補には、この PC で見つけた VS Code、Cursor、Windsurf、Zed、IntelliJ IDEA、WebStorm が、見つかったかどうかと一緒に並びます。
コマンドが PATH に無くアプリだけがあるときも開けます（macOS はアプリの中の CLI、無ければ URL か `open -a`）。
「テスト」は `~/.agent-hangar/hangar-editor-test.md` を書いて 3 行目を開き、行の指定が効くかまで確かめます。
一覧に無いエディタは「任意のコマンド」に書きます。`{path}` が開くファイルかフォルダ、`{line}` が行で、シェルを通さずに起こします。
vim や hx のようなターミナルの中のエディタは、そのセッションのシェルタブか外部ターミナルで開けます。
選んだエディタが見つからないときは、押したボタンの下に、設定を開く、今回だけほかのエディタで開く、再確認の手を出します。
0.4.0 までの「code のパス」は、VS Code とその場所に読み替えます。

一覧の行、ホームの実行中、セッションの現在の札と (i) に、作業ツリーのブランチと未コミットの件数が出ます。
件数は `git status` と同じ数え方で、同じ作業ツリーで動いているセッションがほかにあれば「共有 N」を添えます。
セッションの「変更したファイル」からは、そのセッションが Edit や Write で変えたファイルの差分を、作業ツリーとの差かこのセッションの編集で読めます。
Bash などのコマンドで書き換えたファイルは見分けられないので、「ほかに作業ツリーで変わったファイル」として分けて出します。
他の PC で動いているセッションは、トランスクリプトに残るブランチの名前だけを出します。
hangar は git に書きません（`--no-optional-locks` で読むだけ）。値はこの PC だけのもので、同期しません。

### ショートカット

主なショートカットは、⌘K パレット、⌘N 新規、⌘⇧N スクラッチ、⌘, 設定、⌘1 から ⌘9 でタブ、⌘W でタブを閉じる、⌘\ で分割、⌘J でトランスクリプト、一覧では j と k と Enter と o と e と m です。
`?` を押すと全部の一覧が出ます（⌘/ でも出ます）。
⌘ の付いたものは Ctrl でも打てます。
⌘[ で戻り、⌘] で進みます。
`.app` では、トラックパッドの 2 本指の横スワイプでも戻れます。引いている間は画面端に矢印が出て、引き切ってから指を離した時点で画面が入れ替わります（滑らせる演出は付けていません）。引き切る前に引き戻せば取り消せます。
セッション一覧のように横へはみ出した箱の上では、端に着くまでは箱の横スクロールが優先されます。端で一度止まるので、引き直すと画面が動きます。
ブラウザで開いているときは、この自前のスワイプは働きません。ブラウザ標準の戻る進むの手勢をそのまま使ってください。
閉じられるシェルタブが無いときの ⌘W はアプリが受け取らないので、ブラウザではタブが、デスクトップでは窓が閉じます（窓を閉じるとアプリが終わり、tmux のセッションだけが残ります）。

## クラウド同期（上級者向けのベータ）

**これは上級者向けのベータです。**
始めるのに、このリポジトリの clone（アプリと同じ版のタグ）、ターミナルで打つ CLI（clone した場所で `npm ci` してから `npm run hangar -- setup cloud`。Node 22.14 以上が要ります）、自分の Cloudflare アカウントが要ります。
配布版のアプリだけでは、クラウドを作れません（同梱の `hangar` は、wrangler が 205MB あるので wrangler を持たず、`setup cloud` と `teardown` は、Worker の源が無いことを告げて止まります）。
アプリでできるのは、すでにあるクラウドへの参加（設定の「参加トークンで参加」）と、同期の状態を見ることです。
同期を使わなくても、ほかの機能はそのまま使えます。

同期では、本文だけを暗号化し、題や最初のプロンプトなどのメタデータは平文でクラウドに置きます。
何を置くかは、始める前に、下の「[同期するもの](#同期するもの)」で確かめてください。

自分の Cloudflare アカウントに Worker と D1 と R2 を置き、**自分の端末の間で**セッションを同期します。
無料枠（Workers 10 万要求/日、D1 の書き込み 10 万行/日、D1 5GB、R2 10GB）に収まる規模です。
上限に達すると Cloudflare が断るので、そのときは次の UTC の 0 時まで同期を止め、日が変わると自動で再開します。
他の人と 1 つの箱を共有する使い方は想定していません。
別の人が使うときは、その人の Cloudflare アカウントで `setup cloud` を走らせます。

### 始める前に

- R2 を有効にしておきます。
  Cloudflare のダッシュボードで R2 を有効にするには、支払い方法の登録が要ります。
  無料枠に収まる使い方でも、有効にする操作そのものに登録が要ります。
- Workers の `workers.dev` のサブドメインを、アカウントで 1 度だけ決めておきます（ダッシュボードの Workers & Pages で決められます）。
  Worker の URL（`https://<Worker の名前>.<サブドメイン>.workers.dev`）にそのまま出るので、メールアドレスや本名とつながらない名前にしてください。
  あとで変えると、Worker の URL が変わるので、参加トークンも作り直しになります。
- Cloudflare のアカウントが複数あるときは、作る先を `--account-id <ID>` か環境変数 `CLOUDFLARE_ACCOUNT_ID` で選びます。
  他の人も入っているアカウントに作ると、平文で置くメタデータがその人たちにも読めます（「[暗号化するもの、しないもの](#暗号化するもの、しないもの)」）。
  作る先は、自分だけのアカウントを選んでください。

### 1 台目（同期を始める端末）

次を、このリポジトリを clone する場所で順に打ちます。
`<アプリの版>` は、使っているアプリの版です（設定の更新の節に出ます）。

```sh
git clone https://github.com/gaku1023/agent-hangar.git
cd agent-hangar
git checkout v<アプリの版>      # 例：アプリが 0.6.1 なら v0.6.1
npm ci
npm run hangar -- setup cloud   # wrangler のログイン、資源の作成、デプロイ、参加トークンの表示
```

clone の版は、アプリと同じ版のタグにしてください。
互換の版は、クラウドと話せるかどうかだけを決めるもので、手元の DB は守りません。
clone の CLI は `~/.agent-hangar/hangar.db` をマイグレーションしながら開くので、アプリより新しい版（たとえば main）の clone で打つと、アプリより先に DB が進んでしまうおそれがあります。

資源の名前は既定で Worker と D1 が `hangar`、R2 が `hangar-files` です。
`--name <名前>` で変えられます。

途中で失敗したら、原因を直してから、同じコマンドをもう一度打ってかまいません。
作成済みの D1 と R2 はそのまま使います。

`npm ci` のとき npm 11 が install scripts の警告を出すことがあります。
無視してかまいません（[docs/cloud-sync.md](docs/cloud-sync.md)）。

最後に出る **参加トークン** を控えます。
後から見るときは、UI の Settings のクラウド同期の節で「参加トークンを表示」を押します。

設定が済んだら、アプリを終了して開き直してください。
開き直すと、1 台目でも同期が始まります。
同期の状態は、どこからでも次で見られます。

```sh
hangar cloud status             # Worker とローカルサーバの状態（配布版の hangar でも打てます）
```

### 2 台目（自分の別の PC）

```sh
hangar setup                # ~/.agent-hangar を作る
hangar join                 # 参加トークンを貼り付けて端末を登録し、cloud.json を書く
hangar start                # 再起動すると同期が始まる
```

`join` はトークンを引数ではなく標準入力から受け取ります。
引数に書くと `ps` とシェルの履歴に残るからです。
1Password の項目からそのまま貼れます。
途中で折り返されていても読めます。

デスクトップアプリからも参加できます。
設定 › クラウド同期 › 「参加トークンで参加」で参加トークンを貼り、宛先のホストを確認してから参加します。
参加トークンはサーバの HTTP API を通らず、アプリの殻から同梱の hangar の標準入力へ渡ります。
参加が済むとアプリが再起動して同期が始まります。

### PC の一覧と解除

設定 › クラウド同期 の「PC」に、参加している PC が参加日、最終同期、最後に同期した IP とおおよその場所（Cloudflare の推定。市区はよく外れます）つきで並びます。
手放した PC やなくした PC は、行の「解除…」で同期から解除できます。
解除した PC はこのクラウドと送受信できなくなり、「解除した PC」に移ります。
解除しても、その PC が参加トークンを持っていれば参加し直せます。
締め出すには、解除したうえで、クラウドを作った PC で `npm run hangar -- setup cloud --rotate-secret` を実行して参加用の秘密を再生成します。

```sh
hangar cloud devices        # PC の一覧（ID もここで分かる）
hangar cloud revoke <ID>    # ほかの PC を同期から解除する
hangar cloud leave          # この PC の参加を解除する（既定でクラウドの一覧でも解除する）
```

### 同期するもの

- hangar のメタデータ（プロジェクト、セッション、要約、TODO、メモ）。
  D1 に、暗号化せずに置きます。
- セッションの本文（gzip して AES-256-GCM で暗号化し、R2 に置きます。
  鍵は参加用の秘密から導きます。
  Worker は参加用の秘密そのものを持たず、ハッシュだけを持つので、本文は復号できません。
  暗号化していないと申告された本文は、Worker が R2 に触る前に断ります）
- Claude Code のユーザー設定（既定は off。
  Settings で有効にし、取り込む内容を確認してから `~/.claude` に書きます。
  上書きする前に必ず `~/.agent-hangar/backups/claude-config/<時刻>/` へ控えを取るので、何を書き換えられたかは後から追えます。
  中身は束にして、本文と同じ鍵で暗号化し、R2 に置きます）

対象は `CLAUDE.md`、`settings.json`、`statusLine.command` が指すスクリプト、`skills/**`、`memory/**`、`projects/*/memory/**` です。

#### 暗号化するもの、しないもの

暗号化するのは、セッションの本文（会話のやりとり、ツールの出力、サブエージェントの本文）と、Claude Code の設定の中身だけです。
次のものは、D1 に平文で置きます。

- セッションの題、最初のプロンプト、AI が付けた題、あなたが付けた名前とメモ。
- 要約（題、一行の説明、本文、進捗、次のステップ）。
- プロジェクトの名前、TODO、プロジェクトのメモ。
- 作業ディレクトリとプロジェクトのパス（各 PC のもの）と、本文のファイルのパス。
- 会話を起動したときの指定（最初のプロンプト、モデル、worktree の名前、追加ディレクトリなど）、tmux のセッションの名前、シェルタブの題。
- 成果物（アーティファクト）の URL、題、説明。
- 設定の同期の目録（項目の名前と指紋。
  中身は束の中で暗号化されます）。
- PC の名前と OS、参加日、最終同期の時刻。
- 最後に同期した IP と、Cloudflare が推定した市区、地域、国。
  PC ごとに最後の 1 件だけを持ち、履歴は持ちません。

平文の部分は、あなたの Cloudflare アカウントで D1 を読める人なら、ダッシュボードから読めます。
hangar はこれを暗号化していないので、題や最初のプロンプトに秘密を書いた会話があるときは、そのことを承知のうえで使ってください。
本文だけを暗号化し、題や要約を平文にしているのは、将来 Worker の側で検索や一覧に使えるようにするためです。

本文（セッションの中身）は、クラウドを使い始めた後に動いたものだけを上げます。
参加より前に止まっている本文は上がりません。
新しく始めたセッションと、再開したセッションが対象です。
メタデータ（セッションの一覧、要約、プロジェクト、TODO、メモ）は今までどおり全部同期するので、他端末からも一覧と検索の結果は揃います。

参加より前の本文を上げたくなったら、そのセッションを再開してください。
ファイルが伸びた時点で、いつもの経路で上がります。
まとめて全部上げ直すときは、次を実行します。

```sh
hangar cloud backfill       # 参加より前の本文も上げ直す
```

サーバを立て直さなくても、次の走査から効きます。
いまどこから上げているかは、`hangar cloud status` の「本文:」の行に出ます。
上げる件数は `hangar cloud status` の「未送信」で確かめられます。

他の端末で実行中のセッションは「<端末名> で実行中」と出て、再開とフォークが押せなくなります。
その端末を止めてから「この PC で再開」を押すと、本文を手元に降ろして続きから始められます。
実行中のまま奪い取る「引き継ぎ」はありません。

### やめるとき

```sh
npm run hangar -- cloud teardown   # Worker と D1 と R2 を消す（2 段の確認あり、取り消せません）
```

`teardown` は、クラウドにしか無い本文を先に手元へ降ろしてから消します。
1 件でも降ろせなければ、確認を聞く前に中止します。

### 割り切りと限界

参加トークンは、全セッションの読み書き権を持つ秘密です。
自分の端末以外には渡さないでください。
そのほかの割り切りと、確かめた範囲は [docs/cloud-sync.md](docs/cloud-sync.md) に書きました。

## ファイルと通信

hangar がどのファイルに書き、何を足して claude と tmux を起こし、どこへ通信するかを、ここにまとめます。

### ファイルの扱い

hangar は Claude Code の設定とデータを原則として読むだけで、書き換えません。
`~/.claude/` の中に書く例外は 4 つです。

1. statusline スクリプトへの追記（「[使用量のゲージ](#使用量のゲージ)」の節、承諾を求めてバックアップを取ります。アプリのボタンからは「書き込みの確認」の窓で承諾します）。
2. 他端末のセッションを「この PC で再開」したときの本文の写し。
3. Settings で有効にした Claude Code 設定の取り込み（既定は off、取り込む内容を確認してから書きます）。
4. Settings の保持期間の変更。
   `~/.claude/settings.json` の `cleanupPeriodDays` の 1 か所だけを書き換えます（下の説明を読んでください）。

2、3、4 は、上書きの前に必ず `~/.agent-hangar/backups/` へ控えを取り、控えが取れなければ 1 バイトも書きません。
このほかに、`~/.claude/` の外にある `~/.claude.json` の `mcpServers.hangar` を `hangar mcp install` と `uninstall` が書き換え、`~/.zshrc` の 1 行を `hangar shell install` と `uninstall` が書き換えます。
サーバはどのファイルも書きません。書くのは CLI と、承諾の窓を経たアプリだけです。
索引は `~/.agent-hangar/hangar.db` に置きます。

保持期間は、Claude Code が古い会話の本文を何日で消すかを決める設定です（Claude Code の既定は 30 日）。
Claude Code は期間を過ぎた本文を、セッションを始めたあとの掃除で黙って消すので、hangar は設定の「一般」の節で、いまの日数と、どこで決まっているかを見せます。
期間を変えるときは、書き換える差分と控えの置き場（`~/.agent-hangar/backups/claude-config/<時刻>/`）を見せてから、確認のうえで書きます。
読むのはユーザー設定と組織の設定だけで、プロジェクトの設定と `--settings` は見ません。
組織の設定（macOS は `/Library/Application Support/ClaudeCode/` など）で日数が決まっているとき、ファイルが UTF-8 として読めないとき、書式を読み取れないときは書きません。

複数のアカウントを足すと、2 つ目以降の置き場（例：`~/.claude-2`）を hangar が作り、その中に `~/.claude` の項目（`CLAUDE.md`、`settings.json`、`skills`、`projects`、`history.jsonl` など）へのリンクを張ります。
リンクを張るのは足したほうの置き場の中だけで、`~/.claude` の中は書き換えません。
認証（Keychain の項目と `.claude.json`）は共有せず、hangar はトークンを読みません。
リンクの場所に実ファイルがあるときは、触らずに知らせます。

### hangar が起動する claude に足すもの

hangar は、自分が起動、再開、フォークする `claude` に、次の 3 つを足します。
足すのは起動のときの引数だけで、`~/.claude/` の設定ファイルは書きません。
`claude --bg` で動いている会話へ attach するときと、ターミナルから直接 Claude Code を起動したときは、足しません。
Settings の「連携」の「hangar が起動する Claude Code に足すもの」に、3 つの一覧と、足す指示の全文があります。
MCP の設定と hook は hangar の基本なので切れません。
システムプロンプトの追記のうち、区切りの問いと、ターンの意図と操作の短い説明の 2 つは、そこのスイッチで切れます（次に起動・再開した会話から効きます）。

1. `--mcp-config`。
   hangar の MCP サーバ（`search_sessions`、`get_transcript`、`set_session_summary`、`update_project`、`propose_session_status`、`set_turn_intent` など）を、その会話だけに登録します。
   設定ファイルは `~/.agent-hangar/mcp/<セッション ID>.json`（権限 0600）で、中の Bearer トークンはその会話専用の秘密です。
   本体のトークンは渡しません。
   トークンが `ps` に載らないよう、引数に渡すのはファイルのパスだけです。
   会話が終わると消します。
2. `--settings`。
   hook の設定を `~/.agent-hangar/mcp/<セッション ID>.settings.json` に置いて渡します。
   `AskUserQuestion` の前後（`PreToolUse`、`PostToolUse`、`PostToolUseFailure`）と、許可を求める画面（`PermissionRequest`、全部の道具）で、hangar の台本を裏（`async`）で走らせます。
   入力待ちの問いの文と、許可待ちの道具と命令を、手元の hangar に知らせるためです。
   台本は許可の判断には加わらず、何も出力しません。
3. `--append-system-prompt`。
   短い指示を、Claude Code が自分で組むシステムプロンプトの後ろに足します。
   中身は、プロジェクトの名前と場所、未完の TODO（最大 10 件）、過去のセッションを MCP の `search_sessions` と `get_transcript` で引けること、そして次の依頼です。
   - 依頼を終えたときと、方針が変わったとき、中断するときに、`set_session_summary` で題名、要約、進捗、次のステップを更新する。
   - TODO を片付けたと判断したら、`update_project` で根拠を添えて提案する（完了にするのは利用者です）。
   - 頼まれたことが明確に終わったとき（終わりを告げた、全部済んで次のステップが無い、CI やレビューなど外の出来事を待つ）だけ、ターンの終わりに `AskUserQuestion` で「このセッションをどうしますか」と聞く（Done、Paused、まだ続ける）。
     一手が済んだだけのときや、直しのやりとりの途中では聞かない。
     設定の「区切りで Done／Paused を聞く」で切れます。切っても、状態の提案と自動の Done は続きます。
   - ターンの始めと方針を変えたときに、`set_turn_intent` でそのターンの意図を書く。
   - Bash と Agent の `description` を、短く（20 字程度）書く。
     この 2 つは、設定の「ターンの意図と操作の短い説明を送る」で切れます。切ると、右パネルの現在の札には意図の代わりに依頼の冒頭が出ます。

   全文は `packages/shared/src/i18n/ja/launch.ts` の `launch.injection.body`、`launch.injection.status`、`launch.injection.live` にあり、設定の画面でも読めます（画面を英語にしているときは `en/launch.ts` の同じ鍵の英語版を渡します）。
   プロジェクトのノートは渡しません。
   Claude Code が `CLAUDE.md` と自動メモリを自分で読むためです。

そのほかに、起動した会話には、`--session-id`、`-r`、`--model` などの利用者が選んだ値と、新規セッションの初期プロンプトが付きます。
新しいセッションのモデルの初めの値は、プロジェクトの前回の値、無ければ設定の「既定のモデル」（空なら Claude Code の既定で、`--model` を付けません）です。
会話は tmux の中で、標準エラーと終了コードを `~/.agent-hangar/` のログへ写す小さな包み（`hangar-run.sh`、Windows は `hangar-run.mjs`）を通して起こします。
Claude Code が子に立てる印（`CLAUDECODE`、`CLAUDE_CODE_SESSION_ID` など）と、hangar の受け渡しの変数は、起動する前に環境から外します。

### tmux に足すもの

セッションは、利用者がふだん使う tmux とは別の、hangar 専用の tmux サーバ（`tmux -L hangar`）に置きます。
Windows の psmux も、同じく `-L hangar` の名前空間を使います。

- hangar のセッションは `tmux ls` には出ず、`tmux -L hangar ls`（Windows は `psmux -L hangar ls`）で見えます。
  ターミナルから直につなぐときは `tmux -L hangar attach -t =<名前>` です。
- 利用者の tmux の設定（`~/.tmux.conf`）は、この専用のサーバが起きるときにも読まれます。
- 次のサーバ全体の設定は専用のサーバにだけ入れ、利用者自身の tmux のサーバには入れません。
- 0.6.0 に上げた時点で、前の版が利用者の既定のサーバで動かしていたセッションは、終わるまでそのサーバで扱います。新しく起動するセッションから、専用のサーバに入ります。
- シェル連携（`hangar shell install`）を使っているなら、上げる前から開いていたターミナルは開き直してください。
  古い包みを読み込んだままなので、そこで打った `claude` は起動しても、そのターミナルからはつながりません（セッションは hangar から開けます）。
- 利用者自身の tmux の中で `claude` を打つと、hangar に包まず素の claude を起動します（hangar のシェルタブの中なら、そのまま hangar のセッションへ移ります）。

hangar が入れるものは次のとおりです。

- セッションの名前。
  会話は `hangar-<id>`、会話の中のシェルタブは `hangar-<id>-t<n>` です。
  名前の指定は `=` を付けた完全一致で、自分のセッションを巻き込みません。
- 各セッションの `status off`。
  画面は UI のターミナルに埋めるので、状態の行を出しません。
- `set-clipboard on`（サーバ全体）。
  中のアプリが OSC 52 で写したものを、UI のターミナルへ通します。
  利用者が `on` か `off` を選んでいるときは触りません。
- `focus-events on`（サーバ全体）。
  中の Claude Code に、ターミナルが前に来たか後ろへ回ったかを渡します。
  `off`（既定のまま）のときだけ `on` にします。Windows の psmux には入れません。
- macOS だけ、外のターミナル（iTerm2 など）から attach する人のために、次を足します（Windows の psmux には入れません）。
  - `copy-command`：空か素の `pbcopy` のときだけ、`LC_CTYPE=UTF-8 pbcopy` にします。
    マウスで選んだ範囲を、日本語のままクリップボードへ渡すためです。
  - `extended-keys`：`off` のとき（既定のまま）だけ `on` にします（tmux 3.5 以降は `extended-keys-format` を `csi-u` にします）。
  - `terminal-features`：`xterm*:extkeys` を足します。
  - `S-Enter` のキー割り当て（`bind-key -n`）。
    hangar の会話でだけ Shift+Enter を改行（ESC と Enter）として送り、それ以外のセッションにはそのまま渡します。
    利用者が自分で `S-Enter` に割り当てているときは触りません。

セッションを閉じるときは、名前を指した `kill-session` だけを使い、サーバごと落とす `kill-server` は呼びません。
この設定は、サーバが動いているときに、会話の起動と、UI のターミナルへの attach のたびに確かめます。

### 通信先

hangar が自分で通信するのは、次のところだけです。
手元の hangar サーバへの通信（`127.0.0.1` の 4177）は含みません。

| 通信先 | いつ | 送るもの |
| --- | --- | --- |
| GitHub（このリポジトリの Releases の `latest.json`） | デスクトップアプリが、起動したときと、その後 6 時間ごとに、更新を確かめます。設定の更新の節で「更新を通知する」を切ると、自動の確認は止まります。起動に失敗したときにも 1 度だけ確かめます。 | 更新の目録を取りに行く要求だけです。更新物は署名を確かめてから入れます。 |
| あなたの Cloudflare アカウントの Worker | クラウド同期を設定した PC だけ。 | 「[クラウド同期](#クラウド同期上級者向けのベータ)」の節に書いたもの（本文は暗号化、メタデータは平文）。 |
| Cloudflare の API（`api.cloudflare.com`） | 使用量の API トークンを入れた場合に、Worker が読み取り専用で使用量と費用を問い合わせます。`hangar setup cloud` も、Worker などを作るときに wrangler を通して使い、使用量のトークンの確かめでも呼びます。 | 使用量と費用の問い合わせ。会話の内容は送りません。 |
| 要約の宛先（OpenAI 互換の URL） | 設定の要約エンジンで「OpenAI 互換の URL」を選んだときだけ、事後の要約を作るとき。既定の要約エンジンは「使わない」で、どこへも送りません。 | 会話の本文と、入れていれば API キー。次の 2 項を読んでください。 |
| Claude Code（Anthropic） | 設定の要約エンジンで「Claude」を選んだとき、または「OpenAI 互換の URL」で「接続できないときは Claude を使う」を入れていて繋がらないとき（既定は切）、`claude -p --model <設定のモデル。既定 haiku>` を起こします。 | 会話の本文が、あなたの Claude Code の経路で Anthropic へ渡り、使用枠を消費します。1 時間に 20 件まで（設定で変えられます）で、7 日の使用率が 80% を超えると止めます。 |

要約の宛先は、既定で手元（`127.0.0.1`、`localhost`、`::1`）だけです。
手元の外の URL を使うには、設定の「外部の要約エンジンを許可」を入れます。
入れている間は、会話の本文がその宛先へ送られることを画面に出します。

テレメトリはありません。
hangar は、利用状況やクラッシュを集めて送る仕組みを持たず、広告や解析のサービスにも繋ぎません。
画面の文字の書体も、外のサービスから読みません。
（上の表に無いものは、`claude` や `wrangler`、`git` など、hangar が起こす別のプログラムが自分で行う通信です。
それらの通信は、各プログラムの設定に従います。）

## 困ったとき

- **アプリが起動しない。**
  起動の記録 `~/.agent-hangar/desktop.log` の末尾を見てください。
- **読み込み画面が、Node が見つからない、または版が合わないと告げる。**
  Node 22.14 以上を入れてから開き直すか、画面の「node を選ぶ…」（Windows は「node.exe を選ぶ…」）で入れた Node を選んでください（macOS は「[前提](#前提)」、Windows は「[Windows の前提](#windows-の前提)」と「[Node の探し方](#node-の探し方)」）。
- **初めて開くときに「"Hangar" は開いていません」と出る（macOS）。**
  手順の 3 段目の順で開きます（「[手順](#手順)」）。
- **ローカルネットワークや、ファイルとフォルダの許可をもう一度求められる（macOS）。**
  v0.1.0 から入れ替えた初回だけ起きます（「[v0.1.0 からの移行](#v010-からの移行)」）。
- **Windows の SmartScreen が止める。**
  「詳細情報」を押して「実行」を選びます（「[インストーラで入れる](#インストーラで入れる)」）。
- **ブラウザで開いたら 401 になる。**
  鍵の無い URL は 401 を返します。
  `hangar url` で鍵付きの URL を出してください（「[画面を開く](#画面を開く)」）。
- **クッキーを消したら開けなくなった。**
  `hangar open` でもう一度開き直してください。
- **tmux（Windows は psmux）、`claude`、git の有無を確かめたい。**
  `hangar setup` が報告します。
  ホームの「セットアップの確認」にも出ます。
  入れたあとは「再確認」を押します。
- **Claude Code の新しい版で、知らない形式が出たと知らされた。**
  `~/.agent-hangar/compat.json` に記録され、設定の「連携」の節と、初回の確認リストに出ます（「[できること](#できること)」）。
- **連携の書き込みで、ファイルが変わっていると止まった。**
  「再読み込み」で見直してください（「[アプリのボタンで書くとき](#アプリのボタンで書くとき)」）。
- **アカウントを足したら、リンクの場所に実ファイルがあると断られた。**
  中身を確かめて、要らなければ消してください（「[ファイルの扱い](#ファイルの扱い)」）。
- **同期が止まった。**
  無料枠の上限に達したときは、次の UTC の 0 時まで止まり、自動で戻ります（「[クラウド同期](#クラウド同期上級者向けのベータ)」）。
