# spike 11: 他端末の本文コピーからの再開

判定: 合格
実施日: 2026-09-17

## 確かめたこと
- 別の cwd 用に変換したディレクトリ（`~/.claude/projects/<新 cwd の変換名>/`）へ既存セッションの jsonl をコピーし、新 cwd で `claude -r <id>` を実行すると会話が復元された（前の作業で作った hello.txt の中身「hangar」を正しく答えた）。
- 復元後のターンはコピー先のファイルに追記され（231,621 → 236,928 バイト）、元のファイルは変わらなかった。
- `claude -r <id> --fork-session --session-id <新 id>` で新しい ID のファイルが作られ、文脈を引き継いだ応答が返った。元のファイルは変わらなかった。
- 新しい cwd では最初に信頼確認ダイアログが出た（Task 1 と同じ）。

## 計測値
- 起動 2 回。復元から応答まで通常のセッションと同じ体感。

## 設計への影響
- 「この PC で再開」は、他端末の本文を該当する変換名ディレクトリにコピーして `claude -r` を実行するだけで成立する。行内の `cwd` が元のパスのままでも復元は妨げられない。
- コピー先に既に同じ ID のファイルがある場合の扱い（分岐）は hangar 側で判定する。同一 ID の本文は端末ごとに R2 の別の鍵に置く方針と整合する。
- フォークは新しいセッション行と `kind = 'fork'` の run を作る設計どおりに動く。

## 追記
- コピー先ディレクトリには再開後の元 ID のファイル（238,423 バイト）とフォーク先のファイル（240,601 バイト）の両方が残り、`memory/` ディレクトリも作られた。
- `/rename` で付けた名前（spike-renamed）がフォーク先の画面にも表示された。名前はレジストリだけでなく本文の記録（`agent-name` または `custom-title`）にも残る。hangar は本文からも名前を読める。

## 残った疑問
