# spike 02: 起動フラグとセッション別 MCP

判定: 合格（条件付き）
実施日: 2026-09-17

## 確かめたこと
- tmux 内の対話モードで `--session-id` を事前指定すると、本文ファイルが `~/.claude/projects/<変換名>/<uuid>.jsonl` に生成される。
- `--append-system-prompt` は対話モードで効く（合言葉「格納庫 42」を返した）。
- `--mcp-config` で渡した HTTP の MCP サーバに、`headers.Authorization` の Bearer 付きで接続し、セッション別 URL（`/mcp/s/<uuid>`）からツール呼び出しが届いた。呼び出し元のセッション ID はサーバ側で確定する。
- MCP サーバの承認ダイアログは出なかった。`--mcp-config` の設定は起動元が信頼したものとして扱われる。
- 新しいディレクトリでは信頼確認ダイアログが最初に出て、承認後に初期プロンプトが処理された。

## 計測値
- 起動 3 回のうち、1 回目と 2 回目は引数の順序の誤りで即時終了。3 回目で全項目を確認。
- 信頼ダイアログ承認から MCP の initialize 要求まで約 0.2 秒、`hangar_ping` の呼び出しまで約 6.5 秒（ツール定義の遅延読み込みを含む）。

## 設計への影響
- **`--mcp-config <configs...>` は可変長オプション**で、直後の位置引数（初期プロンプト）を設定ファイル名として飲み込む。起動コマンドの組み立てでは、可変長オプション（`--mcp-config`、`--add-dir`、`--allowedTools`）を他のオプションの前に置き、初期プロンプトは必ず末尾に置く。
- tmux で直接 `claude` を起動すると、異常終了時に出力が失われる。hangar は薄いラッパースクリプト経由で起動し、終了コードとエラー出力をログに残してから tmux セッションを閉じる。
- MCP のツールは遅延読み込み（ツール検索）を経て呼ばれる。ツールの `description` に「agent-hangar」を含め、検索で当たるようにする。
- 利用者の既存の MCP 設定（この環境では `ide`）も同時に読み込まれ、接続失敗のメッセージが出ることがある。hangar が起動するセッションでは `--strict-mcp-config` は使わず、既存設定を尊重する。

## 残った疑問
- `~/.claude.json` にセッション別 URL の MCP サーバが「承認済み」として蓄積されるかどうか。フェーズ 2 で起動を重ねたときに確かめる。
